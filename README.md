# netmoded

Демон управления сетевыми режимами домашнего роутера и веб-панель к нему.
Один статический бинарь на OpenWrt, без зависимостей.

Собирает под одну панель три вещи, которые раньше управлялись из разных
мест: **Nikki (mihomo)** — прозрачный прокси, **b4** — обход DPI,
**happ2clash** — обновление подписки.

Постановка — [`SPEC-backend-router-panel.md`](SPEC-backend-router-panel.md).
Отклонения от неё зафиксированы в [`docs/adr/`](docs/adr/); спека не
переписывалась, чтобы расхождения были видны.

---

## Установка

```sh
./scripts/deploy.sh --install
```

Собирает под `aarch64`, заливает бинарь, `netmode-apply`, `init.d` и сид
конфига, включает автозапуск и печатает ссылку на панель с токеном.
Пароль ssh спросят один раз.

Один шаг остаётся за человеком — демон чужой crontab не правит:

```sh
ssh root@192.168.9.1 'crontab -l | grep -v happ2clash | crontab -'
```

Расписание обновления подписки теперь внутри демона (SPEC §9); две копии
дёргали бы конвертер вдвое чаще, чем нужно.

## Панель

Ссылка печатается при установке. Токен можно посмотреть отдельно:

```sh
ssh root@192.168.9.1 cat /etc/netmoded/token
```

Токен создаётся при первом запуске — 32 случайных байта, права `0600`.
Существующий не перезаписывается никогда: ротация это `rm` плюс
перезапуск, а не побочный эффект старта.

Демон слушает **только LAN-адрес**. `0.0.0.0` отвергается при старте —
это граница безопасности, а не настройка с неудачным значением по
умолчанию ([ADR-0014](docs/adr/0014-lan-bind-and-token.md)).

## Что выяснилось про этот роутер

SPEC §3 требовал разобраться в четырёх вещах по живой системе и
задокументировать результат. Вот он; сырой вывод — в
[`docs/recon/raw/`](docs/recon/raw/), разбор — в
[`docs/recon/`](docs/recon/).

### 1. API b4

| | |
|---|---|
| Адрес | `127.0.0.1:7000`, база `/api` |
| Аутентификация | **выключена** (`auth_check` → `auth_required: false`) |
| Версия | 1.74.1 |

Сеты переключаются через `POST /api/sets/batch-set-enabled`, применяются
**горячо** и **переживают рестарт** b4: `saveAndPushConfig` пишет файл до
подмены указателя конфига (`src/http/handler/config.go:439`).

Поэтому вопрос спеки «дублировать ли выбор в `b4.json`» снят:
**файл не читается и не пишется никогда**
([ADR-0007](docs/adr/0007-b4-api-only.md)), а `scripts/check-b4json.sh`
следит, чтобы это не отросло обратно.

Две ловушки, записанные в [`docs/recon/b4-api.md`](docs/recon/b4-api.md):

- `PUT /api/sets/{id}` — **полная замена, а не слияние**. Отправить туда
  `{"enabled":true}` значит стереть всю стратегию сета.
- В b4 **нет «текущего сета»**: у каждого свой флаг, включённых может быть
  несколько. Выбор одного — семантика нашей панели, а не b4.

### 2. Структура `b4.json`

Вопрос отпал вместе с решением не трогать файл. Замечание на будущее:
`SaveToFile` в b4 пишет через `O_TRUNC` без temp-файла и `rename`
(`src/config/methods.go:36-45`) — на флеше это риск обрезанного конфига
при пропадании питания в момент записи. Не наш файл, но переключение
сета из панели вызывает именно этот путь.

### 3. Управление светодиодами

```
/sys/class/leds/{blue,white}:status/trigger
  → [none] timer heartbeat default-on netdev pattern phy0rx phy0tx …
uci show system | grep -i led  → пусто
```

Триггер `timer` доступен, оба светодиода **ничьи**, секций `config led`
в `/etc/config/system` **нет вовсе** — драться не с кем.

Мигание делается штатным триггером ядра, а не горутиной: горутина мигала
бы только пока жив процесс, и после падения демона светодиод замер бы
в случайной фазе, продолжая врать.

### 4. Имена интерфейсов и роли радио

Снимок разведки — **факт про этот роутер**, а не константы кода:

| | |
|---|---|
| Станция (upstream) | `radio0`, диапазон **2.4 ГГц**, секция `wifinet0` |
| Домашняя точка | `radio1`, 5 ГГц, секция `wifinet1` (`grenderNet`) |
| Интерфейс станции | `phy0.0-sta0` |
| L3 upstream | `wwan`, proto `dhcp` |

**Ни имена интерфейсов, ни имена радио не захардкожены.** Оба выводятся из
одного и того же ответа `ubus call network.wireless status`: связь
«секция ↔ ifname» дана прямо в нём, роль радио — в `interfaces[].config.mode`
(`sta` / `ap`), диапазон — в `config.band`. Если радио выключено и в ubus не
видно, роль берётся из секции `wifi-iface` с `mode=sta` в
`/etc/config/wireless`. Не вывелось ни там, ни там — `503 radio_unknown`,
а не догадка. Порядок разрешения и цена ошибки — [ADR-0019](docs/adr/0019-radio-role-derived.md).

`scripts/check-no-hardcoded-if.sh` валит сборку за литерал вроде
`phy0.0-sta0` **и** за `radio0`/`radio1` в `internal/` и `cmd/` (в тестах
литерал допустим — там он приходит из записанной фикстуры).

Почему это не педантизм: `radio0` и `radio1` — два диапазона **одной** `phy0`,
и их индексы задаются порядком регистрации диапазонов драйвером. После
перепрошивки или на другой ревизии железа они меняются местами, и константа
`stationRadio = "radio0"` тихо направила бы правки на домашнюю сеть.

Следствие, которое видно в панели: **сканирование показывает сети только
того диапазона, в котором работает станция**. Это общее правило — станция
физически работает в одном диапазоне за раз. А вот «в этом списке только
2.4 ГГц» — не правило, а **факт снимка** данного роутера: на станции 5 ГГц
та же панель обязана написать обратное.

Поэтому диапазон нигде не зашит: ответ `/api/wifi/scan` несёт выясненный
`band`, текст `note` следует за ним, а подпись в панели собирается из `band`
на клиенте. Утверждение «сети 5 ГГц не появятся», написанное безусловно, было
бы проверяемо ложным ровно там, где владелец ищет пропавшую сеть.

### Сверх спеки

**`radio0` и `radio1` — диапазоны одной `phy0`**, а не два независимых
модуля (одинаковый `path`, в `/sys/class/ieee80211/` только `phy0`).
Увода канала не будет, но домен перезагрузки общий — это главный блокер
второй фазы.

**Модель сохранённых сетей уже применялась вручную**: `wifinet2` — это
`ATOM` с `disabled='1'`. Мигрировать было нечего.

**Отсутствие опции `disabled` означает «включено»** — подтверждено на
живом примере. Отсюда правило: демон никогда не создаёт секцию без явного
`disabled`.

**Порт 8080 занят mihomo**, поэтому демон слушает 8088.

**Clash API у Nikki** — `9090`, секрет в `nikki.mixin.api_secret`,
аутентификация заголовком `Authorization: Bearer` (параметр `?secret=`
не работает). Ручное закрепление узла возможно и у группы типа `URLTest`:
mihomo проверяет интерфейс `SelectAble`, а возврат к автовыбору —
`DELETE /proxies/{группа}`. Правка профиля не нужна, вопреки
предположению SPEC §7 — подробности в [`docs/recon/nikki.md`](docs/recon/nikki.md).

## Что делает первая фаза, а чего не делает

**Инвариант, из-за которого она безопасна:**

> Демон никогда не делает станционную секцию включённой и изменяет только
> выключенные. Опция `disabled` записывается ровно в одном месте — при
> создании секции, и только значением `'1'`.

Первая фаза структурно не способна изменить то, что делает станционное
радио. Поэтому у записей в `wireless` нет ни джоба, ни светодиода, ни шага
применения — хватает `uci commit`
([ADR-0009](docs/adr/0009-phase1-write-invariant.md)).

| Работает | Не работает |
|---|---|
| Просмотр состояния; скан эфира в диапазоне станции | Переключение внешней сети → `501` |
| Добавить, изменить, удалить **выключенную** сеть | Правка **активной** сети → `409` |
| Переключение режима nikki / b4 / off | Автоматический откат конфигурации — **отменён** |
| Выбор узла Nikki и возврат к автовыбору | Замер задержек: `POST /api/nikki/test` **документирован, но не реализован** — маршрут не зарегистрирован, кнопка в панели отвечает `405` (RQ-06) |
| Выбор сета b4 | Пометка «эта сеть уже сохранена» в результатах скана: поле `saved_id` описано контрактом, но демон его не отдаёт |
| Обновление подписки по расписанию и вручную | Ссылки на веб-морды Nikki и b4 в шапке панели: `status.links` заполняется всегда `null`, обе ссылки мертвы |

Три нижние строки правой колонки — не «ещё не дошли руки», а расхождение кода
с контрактом: `openapi.yaml` эти три вещи описывает, а демон их не делает.
Записаны здесь, потому что иначе читатель контракта решит, что функция есть.

Отката нет намеренно ([ADR-0006](docs/adr/0006-no-rollback.md)):
`SnapshotConfigs`/`RestoreConfigs` **удалены из интерфейса**, а не
помечены устаревшими — пока методы существуют, функция отрастает обратно.
Следит `scripts/check-no-rollback.sh`.

## Разработка

```sh
make verify                  # весь гейт: тесты, сборка, одиннадцать охранников
go run ./cmd/netmoded-dev    # настоящие обработчики против фикстур роутера
docker compose up            # панель против node-мока
```

Подробности по панели — [`web/README.md`](web/README.md).

### Механические охранники

Каждый стоит на конкретном решении и валит сборку, если решение начали
отменять в коде. Все проверены на срабатывание — охранник, который
никогда не падал, это не защита, а её имитация.

| Скрипт | Что стережёт |
|---|---|
| `check-stdlib` | ноль зависимостей; падает раньше и точнее, чем предел размера |
| `check-size` | бинарь ≤10 МБ |
| `check-no-rollback` | отменённый автооткат не вернулся |
| `check-b4json` | `b4.json` не читается и не пишется |
| `check-disabled-write` | `disabled` пишется в одном месте и только `"1"` |
| `check-no-hardcoded-if` | имена интерфейсов И роли радио выводятся, а не зашиты |
| `check-evidence` | каждый внешний литерал подтверждён выводом роутера |
| `check-routes` | OpenAPI ≡ маршруты Go ≡ вызовы панели |
| `check-web-size` | панель ≤60 КБ gzip |
| `check-netmode-seed` | секция `netmode.main` в сиде **именованная**: с анонимной `uci get` падает, и переключение режима отказывает мгновенно |
| `check-netmode-apply` | синтаксис `netmode-apply` и его поведение на подставных `/etc/init.d/*`: коды возврата и то, что при неудавшемся `firewall restart` туннель НЕ поднимается ([ADR-0020](docs/adr/0020-netmode-apply-exit-codes.md)) |

`check-evidence` — главный из них. Каждый URL, порт и путь в sysfs обязан
ссылаться на строку в `docs/recon/raw/`; выдуманный эндпоинт механически
валит сборку, а не проходит ревью на веру.

### Структура

```
cmd/netmoded          демон
cmd/netmoded-dev      те же обработчики против фикстур
internal/executor     единственная дверь к системе (10 методов)
internal/uci          парсер `uci show`
internal/wireless     вывод состояния выбора из конфигурации
internal/nikki        клиент Clash API
internal/b4           клиент API b4
internal/job          сериализация медленных операций
internal/led          индикация
internal/sched        расписание подписки
internal/logs         журнал обновлений
internal/httpapi      HTTP-слой и панель через go:embed
internal/safe         перехват паники на границе фоновых горутин
web/                  панель: Preact + htm, без сборки
docs/recon/           что ответил живой роутер
docs/adr/             принятые решения и их цена
docs/api/openapi.yaml контракт, от которого растут обе стороны
```

Вся работа с системой — за интерфейсом `Executor`. Логика режимов, джобов
и планировщика гоняется на ноуте с фикстурами, без роутера (SPEC §10).
