# Панель netmoded

Preact + Vite + TypeScript ([ADR-0035](../docs/adr/0035-panel-build-step.md)).
Исходники в `panel/`, собранный артефакт коммитится в
`internal/httpapi/panel/` и уезжает в бинарь через `go:embed`
([ADR-0036](../docs/adr/0036-panel-artifact-committed.md)).

```sh
make panel      # собрать в go:embed и переписать манифест происхождения
make dev        # авторская петля: Vite отдаёт панель, API из мока
make preview    # то, что ОТГРУЖАЕТСЯ: собранный бандл из мока
make geometry   # замер геометрии (нужен Chrome, вне verify)
```

**`make verify` панель не собирает и от node не зависит.** Это инвариант, а
не сегодняшнее свойство: правку на Go обязано быть можно загейтить на машине
без фронтенд-инструментов. Правили панель — сделайте `make panel` и
закоммитьте `internal/httpapi/panel/` вместе с
`internal/httpapi/panel.lock.json`; забыли — `check-panel-build` скажет об
этом красным и назовёт команду.

**Cookie-рукопожатие в `make dev` НЕ задействовано.** Прокси Vite
подставляет токен заголовком явно. Это осознанный отказ от подражания:
cookie ключуется хостом, а не портом, поэтому между `:5173` и `:8099` она
доехала бы — по совпадению, невидимо и до первой замены `localhost` на
`127.0.0.1`. Половина работающего механизма хуже неработающего: она не даёт
заметить, что механизм не проверен. Отгружаемый путь авторизации живёт
в `make preview` и `go run ./cmd/netmoded-dev`, и его обязательно прогонять
перед коммитом, трогающим `panel/index.html`, имена ассетов или `withToken`.

## Потыкать без роутера

```sh
docker compose up            # → http://localhost:8088
```

или без Docker, если есть Node 22+:

```sh
node web/mock-server.mjs     # → http://localhost:8088
node web/mock-server.mjs 9000    # другой порт
```

Мок отдаёт **те же golden-фикстуры** из `docs/api/examples/`, против которых
потом сверяются Go-обработчики. Панель и демон растут от одного контракта
(`docs/api/openapi.yaml`), поэтому расхождение видно здесь, а не при первом
клике на живом роутере.

Правки подхватываются без перезапуска: файлы примонтированы на чтение,
достаточно обновить вкладку.

## Против настоящих обработчиков

```sh
go run ./cmd/netmoded-dev        # → http://127.0.0.1:8099/?token=dev-token-not-for-production-use
```

Это честнее node-мока: работает тот же Go-код, который поедет на роутер,
только клиенты Nikki и b4 подменены фикстурами (на ноуте на 9090 и 7000
никого нет). Записи отражаются в чтениях, поэтому цикл «создал сеть —
увидел её в списке — удалил» проверяется целиком.

> **Панель здесь отдаётся из бинаря** (`go:embed`), а не с диска. После
> правки файлов в `web/` нужно `make panel` и **перезапуск**
> дев-сервера — иначе увидите прежнюю версию и будете чинить то, что уже
> починено. Node-мок такого не требует: он читает с диска.

## Сценарии

Мок умеет переключать состояние — иначе половину интерфейса невозможно
увидеть, потому что она появляется только когда что-то сломалось.

```sh
curl -s 'http://localhost:8088/__scenario?name=ambiguous'
```

| Сценарий | Что показывает |
|---|---|
| `single` | рабочее состояние: одна сеть включена (по умолчанию) |
| `ambiguous` | включено ≥2 станционных сетей. Создание, правка и удаление отбиваются `409 ambiguous_selection`, а кнопка **«Подключить» активна** — переключение и есть выход из неоднозначности ([ADR-0026](../docs/adr/0026-switch-from-ambiguous.md)). Нажатие обязано вывести панель в `single` без единой команды в ssh |
| `all-disabled` | сети сохранены, ни одна не выбрана |
| `empty` | сохранённых сетей нет — так выглядит свежая установка |
| `b4-down` | b4 не отвечает, джоба нет. Карточка обязана сказать «не отвечает» **сразу**: запуска никто не просил, и обещать его нечем |
| `job` | идёт медленная операция |
| `b4-after-nikki` | **Главный.** Рабочий `nikki`; b4 молчит столько, сколько вы просидите в этом режиме. Нажмите «b4» через полминуты — весь штатный старт обязан читаться как «b4 запускается», а не как отказ. Единственный сценарий, ловящий выгорание отсчёта грации: см. ниже, почему остальные его пропускали |
| `b4-slow-start` | режим уже `b4`, а порт 7000 молчит **8 секунд**: скелетон с подписью «b4 запускается», побочные запросы `503 b4_unavailable`. Потом b4 поднимается сам, и сеты приезжают без перезагрузки страницы |
| `nikki-slow-start` | то же для Nikki: Clash API молчит 8 секунд, `/api/nikki/{proxies,proxy,test}` → `503 nikki_unavailable`, затем узлы появляются |
| `b4-never-up` | b4 не поднимется **никогда**. Проверка потолка `START_GRACE` (20 с): после нажатия скелетон обязан смениться на «Панель b4 не отвечает», а не остаться навсегда. При открытии страницы без нажатия отказ виден сразу — джоба нет |
| `host-unknown` | движок отвечает, а `links` оба `null`: кнопок в шапке нет при живой службе. Так выглядит панель, открытая через ssh-туннель по `localhost` |
| `job-fail-short` | джоб `failed`, текст ошибки в одну строку (`uci commit netmode: exit status 1`) |
| `job-fail-long` | тот же джоб, но текст — дословное сообщение демона (`modehandler.go` поверх `executor.ErrApplyFirewall`), 2–3 строки на телефоне. Худший реальный случай; на нём и меряется геометрия |
| `job-fail-vanish` | тот же провал, но джоб исчезает через 5 секунд — ровно `keepFinished` из `internal/job/job.go`. Заголовок и текст ошибки уходят с экрана **вместе**: столько времени у владельца и есть на прочитать |
| `upstream-fail-seen` | **фаза 2.** Переключение не состоялось, `last_fail` лежит в статусе с первого кадра — джоба ждать не надо. Блок провала стоит **ниже** карточки Wi-Fi: причина обязана быть рядом с тем местом, где нажимали |
| `upstream-fail-long` | то же, но ssid ровно 32 байта — предел стандарта (`validateNetwork`) и худший случай для вёрстки. Список сетей тоже длинный |
| `single-long` | база сравнения для длинных состояний, заведена ради замера (`C3`/`C4`). Побайтовая копия фикстуры `upstream-fail-long` с `last_fail: null` — отличается от неё **ровно** блоком провала |
| `no-executors` | **половинчатая установка.** На роутере нет ни одного скрипта слоя 2, и `missing_executors` перечисляет оба. Баннер обязан стоять **выше** всех карточек и **до** нажатия: пока файлов нет, любая кнопка применения запишет намерение и не применит его. Крестика у него нет намеренно — это состояние, а не событие |
| `upstream-no-executor` | тот же отказ, увиденный **после** нажатия: причина `executor_missing`, а под её текстом — `detail` с путём к отсутствующему файлу. Пара к `no-executors`: два разных доклада об одном факте, и владелец на роутере может увидеть только один из двух |
| `upstream-job-long` | идёт переключение (`kind: "upstream"`, `eta_sec: 20`) при длинном ssid |
| `upstream-long-list` | три кнопки в ряду у сети с длинным именем: статус обычный, длина живёт в списке |
| `nikki-test-dead` | «Замерить все» отвечает `200`, но не ответил ни один узел. Кодом ошибки это не является: движок отработал, узлы опрошены — тост обязан сказать об этом словами, иначе нажатие неотличимо от бездействия (числа mihomo обновляет и сам, раз в пять минут) |
| `nikki-test-slow` | замер не успел обойти всех: часть узлов уходит в `skipped`. Тост обязан отличить «не ответил» (про узел) от «не замерен» (про нас) — во втором случае неизвестно вообще ничего |
| `nikki-no-manifest` | список узлов **без манифеста подписки**: демон отдаёт живой список mihomo, все строки — `node`, строки «Авто» в нём нет. Так выглядит свежая установка. Единственное состояние, где кнопка возврата к автовыбору обязана стоять **в шапке карточки**: во всех остальных её место занимает строка «Авто» в списке, и две одинаковые кнопки рядом не показываются |
| `sub-unset` | `subscription.configured: false` — адрес подписки не задан в `/etc/config/netmode`. Кнопка «Обновить сейчас» заблокирована, над ней команда для ssh. Состояние первой установки: на роутере его видят один раз, а панель обязана его переживать всегда |
| `rulesets-profile` | наборов geosite ещё не выбирали — `sets: []`, правила целиком из профиля Nikki. Так выглядит свежая установка (`mixin.yaml` на диске нет), и это же умолчание, если сценарий про наборы не выбран отдельно |
| `rulesets-only` | выбрано три набора: `youtube` и `telegram` загружены, `openai` — нет (`loaded: false`, `rules: 0`, `updated_at: null`). Панель обязана показать тег «не загрузился» ровно у него, а не у всех трёх |
| `rulesets-foreign` | `mixin.yaml` на диске написан не нами. Кнопка «Применить» обязана быть недоступна — запись затёрла бы чужую правку молча |
| `rulesets-down` | тот же выбор, что у `rulesets-only`, но движок не отвечает: `live: false`, а `loaded`/`rules`/`updated_at` у каждого набора — `null`, а не `false`/`0`. «Не загружен» и «неизвестно, загружен ли» — разные утверждения, и подменять один null-набором нельзя |
| `rulesets-nocatalog` | тот же выбор, что у `rulesets-only`, но `GET …/catalog` отвечает `503 catalog_unavailable`: список имён с GitHub недоступен, а уже применённые наборы панель всё равно показывает — они читаются из файла, а не из каталога |

Джоб можно вызвать и вживую — нажать кнопку режима: мок держит операцию
8 секунд, как роутер.

### Почему `b4-after-nikki` понадобился отдельно

Первая версия правки «карточка не врёт при запуске» вела отсчёт от момента,
когда панель **заметила** молчание. На ноуте это выглядело исправным, потому
что фикстуры отдавали `mode: "nikki"` при живом b4 — состояние, которого на
роутере не бывает: `netmode-apply` гасит вторую службу безусловно
(`files/usr/local/bin/netmode-apply:128-129`). На железе b4 в режиме nikki
молчит постоянно, отсчёт стартовал на первом же тике опроса и протухал
задолго до нажатия — и весь штатный старт панель называла отказом.

Отсюда два правила для этого файла. Фикстура обязана держать инвариант
«одновременно отвечает не больше одного движка, и это тот, что в `mode`».
А сценарий, проверяющий поведение при запуске, обязан включать **ожидание
в другом режиме** — иначе он проверяет только тот путь, где панель монтируется
уже в целевом режиме, и пропускает самый частый: пришёл, посмотрел, нажал.

Окно молчания в `*-slow-start` заводится при переключении сценария и заново
при `POST /api/mode`; в `b4-after-nikki` — только по нажатию. Первое нужно,
чтобы сценарий воспроизводился без нажатия; второе — чтобы нажатие давало
ровно то расхождение, что на роутере: `mode` записан, служба ещё не слушает.

В `job-fail-*` движок в фикстуре тоже лежит (`b4.available: false` при
`mode: "b4"`) — это законное состояние «намерение записано, служба не
поднялась». На замер геометрии это не влияет: она меряется по `.wrap .card`,
а карточка на месте в обоих состояниях.

### Часы роутера

Сценарием это не является: сдвиг часов ортогонален состоянию роутера и
проверяется вместе с любым из них.

```sh
curl -s 'http://localhost:8088/__clock?skew=-3600'   # роутер отстаёт на час
curl -s 'http://localhost:8088/__clock?skew=3600'    # опережает на час
curl -s 'http://localhost:8088/__clock?skew=0'       # как у машины (умолчание)
```

Задаётся и при запуске: `MOCK_SKEW_SEC=-3600 node web/mock-server.mjs 8090`.

Зачем. Все метки времени в контракте (`generated_at`, `started_at`,
`last_fail.at`) идут с часов роутера, а тикает время в браузере. На ноутбуке
мок и браузер живут на одних часах, поэтому любая ошибка вида «местное время
минус метка роутера» здесь даёт верный ответ и не воспроизводится ни одним
прогоном. На коробке без RTC, у которой не поднялся upstream — ровно та, ради
которой панель и делается, — расхождение составляет часы, и знак важен обеих:
отстающий роутер и опережающий ломают разное.

Что смотреть при ненулевом сдвиге: полоска джоба обязана начинаться с нуля
и расти, а «осталось ~N с» — считать вниз от `eta_sec`. Замершая на 99% полоска
с «осталось 0 с» и панель, которая не отпирается после операции, — это оно.

## Измерение геометрии

```sh
make geometry
```

Скрипт сам поднимает мок и Chrome, снимает 18 состояний на трёх ширинах
(320 / 390 / 1440) и валится ненулевым кодом на нарушении. Ручного протокола
нет: прыжок в четырнадцать пикселей за один кадр глазами не ловится, а
именно он и происходит в момент, когда владелец смотрит, сработало ли
нажатие.

**Ни одного клика.** Состояния переключаются сценариями мока и адресом
(`#uplink` разворачивает раздел, `#all` — все), а не нажатиями: клик по
кнопке режима запускает джоб на 8–20 секунд и превращает замер в гонку
с таймером — ровно то, на чём умерла предыдущая попытка.

**Меряется СОБРАННЫЙ бандл** (`make geometry` зависит от `make panel`):
у дев-сервера нет ни минификации, ни вынесенного CSS, и мерить на нём значит
мерить то, что никто не загрузит.

**Адресация — только `data-part`, `data-anchor` и ARIA.** Классы под
бандлером принадлежат сборке; регексп по заголовку — это структурное
утверждение, привязанное к локали, и оно ломается в день, когда кто-то
улучшит русский текст.

### Критерии C1′–C8

Разбор каждого и доводы за снятие C1/C5 — в
[ADR-0037](../docs/adr/0037-geometry-criteria-rewritten.md).

| | Что проверяет |
|---|---|
| **C1′** | якоря, до которых изменение состояния физически достаёт, не двигаются между покоем и «занята» |
| **C2** | горизонтальной прокрутки нет ни в одном состоянии; виновник называется поимённо |
| **C3′** | блок провала физически растит низ сетки — доказательство, что замер его видит |
| **C4′** | якоря ниже блока сдвинулись все на одно и то же, и ровно на прирост низа сетки |
| **C5′** | высота баннера совпадает между покоем и «занята» |
| **C6** | состояния аккордеона измеряются, `aria-expanded` согласуется с видимостью |
| **C7** | пустых областей не бывает |
| **C8** | обе раскладки существуют |

`GEOM_DUMP=<файл>` кладёт все замеры как есть: когда критерий падает на
числе, вопрос всегда один — из чего это число сложилось.

**Скрипта мало.** Совпадающие числа доказывают постоянную высоту, но не
поймают «не то содержимое»: C7 ловит пустоту, а не подмену. Скриншот
в покое по-прежнему обязателен — под переключателем режима обязана быть
видна подсказка, а не пустое место.


## Что проверить глазами

- **Обе раскладки.** Брейкпоинт 900px: до него аккордеон (свёрнутый раздел
  отдаёт своё состояние заголовком), после — сетка с раскрытыми разделами
  и без кнопок сворачивания вовсе. Кнопки там нет намеренно: `aria-expanded`,
  которое нельзя изменить, — это ложь скринридеру, а не украшение. Числами
  это проверяет C8, глазами надо смотреть на другое: в свёрнутом виде
  заголовок обязан отвечать на «что там», иначе разворачивать придётся всё
  подряд и аккордеон не экономит ничего.
- **Полоса аномалии.** На `bridge-on` шлюз молчит, и над карточками встаёт
  жёлтая полоса с кнопкой «Проверить связь». Смотреть надо, что она стоит
  ПОД статусом и НАД разделами: аномалия важнее статуса, но не важнее
  ответа на «что вообще происходит».
- **Встроенные подтверждения.** Смена аплинка и выключение проброса больше
  не зовут браузерный `confirm()`: подтверждение раскрывается на месте и
  называет ПОСЛЕДСТВИЯ — связь прервётся, отката нет. Смотреть надо именно
  текст последствий: без него подтверждение только добавляет клик.
- **Маска ссылки подписки.** В разделе подписки обязан быть виден хост и
  путь, и НИ ОДНОГО символа токена ([ADR-0034](../docs/adr/0034-subscription-url-write-only.md)).
  Нажмите «Изменить» — поле открывается ПУСТЫМ: маска не адрес, и отправить
  её обратно значило бы записать многоточия вместо токена.
- **Кнопки движков в шапке.** Кнопка движка рисуется, только когда известен
  адрес И движок отвечает ([ADR-0024](../docs/adr/0024-panel-links-only-when-service-answers.md)),
  поэтому одновременно видна **не больше одной**, а в режиме `off` — ни одной.
  Серой заглушки на месте невидимой кнопки нет и быть не должно. На
  `b4-slow-start` кнопка b4 отсутствует все 8 секунд и появляется вместе с
  движком — при том что карточка в это же время говорит «b4 запускается».
  Расхождение осознанное: карточка обещает данные, кнопка — открывающуюся
  страницу.
- **Кнопка LuCI видна ВСЕГДА, когда выводится хост.** Это не то же правило, что
  у движков, и проверять её надо именно там, где остальные кнопки погасли:
  в режиме `off`, на `b4-down`, на `b4-never-up` после истечения грации, при
  обоих лежащих движках. Она остаётся, потому что uhttpd мы не гасим и живость
  его не проверяем. **Единственный сценарий, где её нет, — `host-unknown`:**
  там `null` во всех трёх полях, и прятать нечего — адреса не существует.
  Если LuCI пропала где-то ещё, это дефект, а не состояние.
- **Перенос шапки.** Числа прежнего замера сюда не переносятся: шапка
  изменилась целиком (чип режима уехал, набор кнопок другой), и старые
  значения были бы враньём с видом точности. Смотреть надо на само явление:
  на узком экране `.top-links` переносится на свою строку, и включается
  этот перенос от ПОЯВЛЕНИЯ кнопки движка — то есть страница уезжает вниз
  ровно тогда, когда движок поднялся. Принятая цена, записана в ADR-0024;
  лечится слотом фиксированной ширины, а не возвратом серой заглушки.
- **`ambiguous`** — самое важное состояние: демон сообщает о конфликте и
  **не чинит его сам**. Но неактивны только кнопки **правки**: создать,
  изменить и удалить сеть нельзя (`409 ambiguous_selection`), а **«Подключить»
  работает** — это единственный выход из неоднозначности, и он в панели, а не
  в ssh ([ADR-0026](../docs/adr/0026-switch-from-ambiguous.md)). Смотреть надо
  именно это: нажали на нужную сеть — баннер конфликта ушёл, состояние стало
  `single`. Противоречия с «не чинит сам» здесь нет: секцию называет человек,
  демон не выбирает, какая из включённых лишняя.
- **Мёртвый узел** — пустая полоска, а не полная: полная читалась
  бы как «очень медленно», то есть узел жив.
- **Четыре вида строк в списке узлов** (умолчание мока — 30 строк в порядке
  подписки). Смотреть надо, что оформление идёт от `kind`, а не от `alive`:
  у всех строк-не-узлов `alive: false` и `delay_ms: null`, и общее правило
  сказало бы про них «узел мёртв» дважды — приглушением и пустым метром.
  `⬇️ Обходы белых списков ⬇️` — **не кнопка**: ни фона карточки, ни рамки,
  ни высоты узловой строки, иначе читается как узел, который почему-то не
  нажимается. `🎁 Бонус | Пригласи друга` — кнопка заблокированная, и причина
  от демона стоит **строкой**, а не только в `title`: на телефоне `title`
  не существует, а панель открывают именно с телефона. Строка «Авто»
  подсвечена ровно тогда, когда ничего не закреплено (`pinned: false`);
  нажмите узел — подсветка обязана уйти на него, нажмите «Авто» — вернуться.
- **«Замерить все»** — нажатие обязано дать три вещи: спиннер на кнопке сразу,
  новые числа в списке и тост с итогом. Тост здесь не украшение: mihomo
  обновляет задержки сам примерно раз в пять минут ([RQ-06](../docs/recon/evidence.json)),
  так что «числа поменялись» само по себе ничего не доказывает, а на
  `nikki-test-dead` они не меняются вовсе — и без тоста нажатие выглядит
  как бездействие. Смотреть надо и на формулировку: **«не ответил» и «не
  замерен» — разные вещи**, второе означает, что про узел неизвестно ничего.
- **Три состояния сетов b4** — включён один, ни одного, несколько. Все три
  показаны как НОРМА, а не как ошибка ([ADR-0033](../docs/adr/0033-b4-sets-not-exclusive.md)):
  у каждого сета свой флаг, порядок задаёт приоритет. Нажатие на включённый
  сет обязано его выключать, а соседний — оставаться нетронутым.
- **Результат операции.** После смены режима обязана появиться строка
  «готово за N с», а не тишина: джоб доводит демон, замок панели снимается
  сразу после 202, и без этой строки нажатие заканчивается ничем видимым.
- **Переключение ru/en** в шапке, выбор запоминается.
- **Потеря связи с демоном** — остановите мок при открытой вкладке: панель
  покажет последнее известное состояние и пометит его устаревшим, а не
  станет пустой. Пустой экран бесполезен ровно тогда, когда нужен больше
  всего.

## Размер

**Гейта размера панели нет** ([ADR-0032](../docs/adr/0032-panel-budget-dropped.md)
отменил [ADR-0029](../docs/adr/0029-panel-budget-revised.md)), и появление
сборки этого не изменило ([ADR-0035](../docs/adr/0035-panel-build-step.md)).
Предел бинаря (10 МБ, `scripts/check-size.sh`) — другое решение и другая
физика, он остаётся.

Рукописной таблицы здесь тоже больше нет: она отставала бы, как отставала и
раньше. Каждая сборка пишет размеры в `internal/httpapi/panel.lock.json`,
файл коммитится, и любая правка панели показывает число в диффе.

```sh
sed -n '/"sizes_gzip"/,/}/p' internal/httpapi/panel.lock.json
```

Число в диффе, а не число в гейте: храповик («падать, если вырос больше чем
на X%») — это порог, который двигают вслед за ростом, а такое ADR-0032 верно
назвал не решением, а ритуалом. Причину роста при сборке охраняет другое —
аллоу-лист рантайм-зависимостей (`scripts/check-panel-deps.sh`): панель
удваивается библиотекой, а не текстом.

Считается gzip, потому что демон отдаёт статику сжатой
([ADR-0038](../docs/adr/0038-static-cache-and-gzip.md)). `mock-server.mjs`
не считается вовсе: он не попадает в бинарь.

## Чего в панели нет намеренно

| Нет | Почему |
|---|---|
| WebSocket / SSE | статус опрашивается раз в секунду **по SPEC §7**; push стоит памяти роутера и ничего не покупает при одном пользователе в LAN |
| светлая тема | панель открывают ночью, чтобы понять, почему нет интернета |
| правка пароля активной сети | `409 enabled_network_readonly` ([ADR-0026](../docs/adr/0026-switch-from-ambiguous.md), раздел «Что сохраняется из ADR-0009 дословно»). Чтобы сменить пароль активной сети, надо сначала переключиться на другую — теперь это делается в панели |
| откат неудачного переключения | отката нет ([ADR-0006](../docs/adr/0006-no-rollback.md)). Неудачная попытка оставляет роутер без upstream и **говорит об этом**: `status.last_fail` с машинной причиной, панель показывает блок провала |
| правка активной сети в состоянии `ambiguous` | пока включено больше одной сети, правку невозможно доказать безвредной ([ADR-0026](../docs/adr/0026-switch-from-ambiguous.md)). «Подключить» при этом работает: выбрать одну — и есть способ выйти |
