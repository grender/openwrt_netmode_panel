## Сеты

### Модель b4 не совпадает с моделью панели

В b4 **нет «текущего сета»**. Каждый сет имеет собственный флаг `enabled`
(`src/config/types.go:395`), включённых может быть несколько одновременно,
а порядок задаёт приоритет обработки.

Панель по решению владельца **навязывает эксклюзивность**: один выбранный,
остальные погашены. Это наша семантика, а не b4 — реализуется двумя вызовами.

Следствие, которое стоит помнить: если пользователь включил сеты через
веб-морду b4, наше переключение их погасит. Это ожидаемое поведение выбранной
модели, а не баг.

### Список

```
GET /api/sets  →  [ {"id":"<uuid>", "name":"general", "enabled":true, ...}, ... ]
```
`src/http/handler/sets.go:16,233-242,270-277`

Массив плоский, никогда не `null` (нормализуется в `[]`, строки 273-275).

**`name` не уникален и не является ключом** (`src/http/handler/sets.go:315` —
`id` генерируется сервером как UUID). Имя резолвится в `id` сканированием
массива. Хранить `id` между запросами нельзя — он может измениться, если сет
пересоздали.

### Переключение

```
POST /api/sets/batch-set-enabled
{"ids": ["<uuid>", ...], "enabled": true|false}
→ {"success": true, "updated": <n>}
```
`src/http/handler/sets.go:23,634-698`

Коды: `400 bad_request` при пустом `ids` (649-652), `400 invalid_json` (644-647),
`404 not_found` если ни один id не найден (674-677), `405` на не-POST (635-638).

**`updated: 0` — не ошибка.** Если запрошенное значение уже стоит у всех
указанных сетов, обработчик возвращает успех, пропуская запись
(`src/http/handler/sets.go:679-683`).

### Применяется горячо

`saveAndPushConfig` проталкивает конфиг в живой пакетный движок —
`globalPool.UpdateConfig` (`src/http/handler/config.go:402-407`), который
пересобирает матчер и атомарно раскладывает новый конфиг по воркерам
(`src/nfq/pool.go:212-227`). **Рестарт b4 не нужен.**

`PerformSoftRestart` следом трогает только правила firewall и только если
менялись порты/марки/masquerade/MSS (`src/http/handler/config.go:476-516`).
Переключение `enabled` их не меняет — то есть это no-op.

### Переживает рестарт — да

```go
// src/http/handler/config.go:439-442
err := newCfg.SaveToFile(newCfg.ConfigPath)
```

Запись в файл происходит **до** подмены указателя конфига (`:453`). Значит
`200` от `batch-set-enabled` можно считать долговечным.

**Это окончательно закрывает вопрос SPEC §3** — «продублировать ли выбор
в `b4.json`, если API меняет только память». Не надо: API пишет сам, и файл
нам трогать незачем.

## Здоровье

```
GET /api/version  →  {"version":"1.74.1","commit":"99808ed","build_date":"..."}
```
`src/http/handler/system.go:21,234-248`

Один из двух маршрутов под `/api/`, освобождённых от аутентификации
(`src/http/auth.go:267-271` — в комментарии прямо сказано «used as health
check»); второй — `GET /api/auth/check`, которым и снят сам факт
`auth_required: false` (`raw/50-b4-api.txt`). Пробой живости выбран
`/api/version`: он же отдаёт версию, а `auth/check` пришлось бы звать
отдельно ради одного булева поля. Не ответил — значит b4 лежит, и
`/api/b4/*` отдаёт `503`.

## Запрещено использовать

**`PUT /api/sets/{id}` — полная замена, а не слияние.** Обработчик декодирует
тело в обнулённый `config.SetConfig` и кладёт его в слот
(`src/http/handler/sets.go:351-368`), сохраняя только `id` (`:365`). Дефолты
не применяются.

Отправить `{"enabled": true}` этим методом — **стереть всю стратегию сета**.
Механически запрет держат `scripts/check-b4json.sh` и `scripts/check-routes.sh`:
клиент b4 знает только `GET /api/version`, `GET /api/sets` и
`POST /api/sets/batch-set-enabled`.

Раньше этот метод был нужен как запасной путь для сборок старее 1.64.0, где
`batch-set-enabled` ещё не существовал. На роутере 1.74.1, поэтому запасной
путь не пишем вовсе.

## Замечание не про нас

`SaveToFile` пишет через `O_TRUNC` без temp-файла и `rename`
(`src/config/methods.go:36-45`), в отличие от `downloadFile` в том же дереве
(`src/http/handler/common.go:255-285`), который делает это правильно. На флеше
это означает риск обрезанного `b4.json` при пропадании питания в момент
записи.

Не наш файл и не наша ошибка — но упомянуть в README стоит, потому что
переключение сета из нашей панели этот путь как раз вызывает.
