# Разведка: что выяснено о живой системе

Разведка по SPEC §3 закрыта до начала работ. Здесь лежит то, что реально
ответил роутер, а не то, что мы предполагали.

## Как этим пользоваться

- `raw/` — **дословный вывод роутера, append-only.** Не редактируется никогда,
  кроме одной операции — редактирования секретов (ниже). На него ссылаются
  диапазонами строк из `evidence.json` и из документов рядом.
- `evidence.json` — машинно-проверяемый индекс. `scripts/check-evidence.sh`
  валит сборку, если код обращается наружу по литералу, которого здесь нет
  со `status: "verified"`.
- `raw/` — это ещё и **тестовые фикстуры**. Парсеры проверяются на настоящем
  выводе, а не на рукописных структурах: рукописный мок проверяет нашу
  догадку саму против себя, записанный вывод ловит ошибки формы.

## Редактирование секретов

В `raw/` заменены только значения, раскрывающие секреты или идентифицирующие
устройство. Плейсхолдер **сохраняет форму** значения, потому что форма влияет
на парсер, а содержимое — нет:

| Было | Стало | Зачем сохранена форма |
|---|---|---|
| пароли WiFi, только цифры | `REDACTED_PSK_NUMERIC8` | обычный случай |
| пароль со спецсимволами | `REDACTED_PSK!!SPECIAL@@` | **проверяет экранирование в парсере `uci show`** — самый ценный из трёх |
| `dhcp_default_duid` | `REDACTED_DUID_36HEX` | производный от MAC |
| `ula_prefix` | `fdxx:xxxx:xxxx::/48` | идентифицирует сеть |

Больше не изменено ничего: ни порядок строк, ни отступы, ни пустые массивы
в JSON.

## Что выяснилось сверх спеки

**Модель сохранённых сетей уже применяется вручную.** `wifinet2` — это `ATOM`
с `disabled='1'`, то есть ровно «сохранённая upstream-сеть как выключенная
секция». Мигрировать нечего.

**Отсутствие `disabled` означает «включено»** — подтверждено на живом примере:
у `wifinet0` этой опции нет, и именно она в ассоциации. Отсюда правило: демон
никогда не пишет секцию без явного `disabled`.

**`radio0` и `radio1` — диапазоны одной `phy0`**, а не два независимых модуля
(одинаковый `path`, в `/sys/class/ieee80211/` только `phy0`). Увода канала не
будет — станция в 2.4 ГГц, точка доступа в 5 ГГц. Это выглядело как главный
блокер второй фазы — общая `phy0`, общий домен перезагрузки. **Замер RQ-03
показал, что домен всё-таки делим:** глаголы с аргументом `device` действуют
на радио, а не на phy. Грубые глаголы (`wifi` целиком) phy действительно
передёргивают — и это измерено, см. [`apply-verbs.md`](apply-verbs.md).

**Станция живёт на 2.4 ГГц** (`radio0.band='2g'`), значит скан покажет только
сети 2.4 ГГц. Панель обязана это писать — иначе отсутствие знакомой
5-гигагерцовой сети выглядит как баг.

**`/etc/config/wireless` имеет права 644**, в отличие от `network` и `system`
с 600. Поэтому токен API живёт в сайдкаре `/etc/netmoded/token` с правами
0600, а не в UCI.

## Что осталось открытым

Открытые вопросы ведутся в `evidence.json` → `open_questions`. Кратко:

- **RQ-01 — ЗАКРЫТ.** Clash API: порт 9090, адрес из `nikki.mixin.api_listen`,
  секрет из `nikki.mixin.api_secret`, аутентификация `Bearer`; раскладка групп
  снята (`raw/60`, `raw/61`, разбор — [`nikki.md`](nikki.md)). Клиент
  реализован, `/api/nikki/*` работают.
- **RQ-02** — сохраняет ли LuCI Save&Apply именованные секции. Низкий
  приоритет: влияет только на стратегию идентификаторов.
- **RQ-03 — ЗАКРЫТ, блокера второй фазы больше нет.** Домен перезагрузки
  делим: `ubus call network reload` + `ubus call network.wireless reconf
  '{"device":"<радио станции>"}'` применяет конфигурацию, не трогая домашнюю
  точку — её клиент не переассоциировался ни разу за шесть применений.
  `rc=0` при этом **не означает** «применилось». Замер и все оговорки —
  [`apply-verbs.md`](apply-verbs.md), сырьё `raw/27`, `raw/28`, `raw/29`.
- **RQ-04 — ЗАКРЫТ прямо.** Скан не рвёт ассоциацию: три скана по 2.36–2.42 с
  при непрерывном наблюдении, `uptime` wwan рос без сброса (`raw/27` раздел
  `rq04 scan`, `raw/28` фазы `scan:*`). Прежняя формулировка «косвенно» снята.
- **RQ-05 — ЗАКРЫТ.** Брать `assoclist` по интерфейсу точки; `connected_time`
  в нём есть и даёт признак свежей переассоциации. **Функция при этом не
  реализована:** `ap.clients` по-прежнему `null` — теперь это невыполненная
  работа, а не открытый вопрос.
- **RQ-06** — форма ответа `GET /proxies/{name}/delay`. Блокирует
  `POST /api/nikki/test`: маршрут не зарегистрирован, панель упирается в `405`.
