# ubus: формы ответов

Разбор фикстур в `raw/`. Файлы там — **чистый JSON без единого добавленного
байта**, чтобы `encoding/json` скармливался ими напрямую; все комментарии
живут здесь.

## Что откуда берётся

| Нужно | Объект и метод | Фикстура |
|---|---|---|
| имена интерфейсов, связь секция↔ifname, `pending` | `network.wireless status` | `raw/21-…json` |
| ассоциированный SSID, сигнал, шум | `iwinfo info {device}` | `raw/24-…json` |
| список сетей вокруг | `iwinfo scan {device}` | `raw/23-…json` |
| «интернет есть» | `network.interface.wwan status` | `raw/26-…json` |
| клиенты домашней точки | `iwinfo assoclist {device}` | **нет, RQ-05** |

## `iwinfo scan` — три вещи, которые меняют код

Корень — `{"results": [...]}`, не голый массив.

### 1. Поле `ssid` может отсутствовать

**Три результата из четырнадцати пришли без `ssid` вообще** — это скрытые
сети. Значит:

- в Go поле обязано быть `*string` либо проверяться на пустоту; структура
  с `ssid string` молча превратит скрытую сеть в сеть с пустым именем;
- панель обязана их показывать (они занимают эфир и объясняют помехи), но
  подключиться к скрытой сети по одному тапу нельзя — SSID неизвестен;
- сортировка и дедупликация по SSID сломается на трёх записях подряд.

Наивный парсер, написанный по рукописному моку, этого бы не встретил:
такую форму не придумывают, её только наблюдают.

### 2. Уровень сигнала — `signal`, в dBm

`signal: -48` — отрицательное число, децибелы. Именно его рисует макет
(«−48 dBm»). Рядом есть альтернативная шкала `quality` / `quality_max`
(здесь 62 из 70) — она удобнее для полоски, но макет просит dBm.

### 3. Опциональные блоки

`ht_operation`, `vht_operation`, `eht_operation` встречаются
непредсказуемо и **вразнобой**: в снимке из 14 сетей у `John24` есть `ht` и
`vht`, у одной соседской — `vht` и `eht`, у остальных ни одного. Всех трёх
блоков нет ни у кого. Нам они не нужны, но при жёстком разборе в структуру их
отсутствие не должно быть ошибкой.

Варианты `encryption.wpa`: `[2]`, `[2,3]` (WPA2+WPA3, `authentication`
включает `sae`), `[1,2]`. Это только отображение — и в фазе 2 тоже:
переключение внешней сети меняет одну опцию `disabled` и не трогает ни
`ssid`, ни `key`, ни `encryption` ([ADR-0026](../adr/0026-switch-from-ambiguous.md)).

## `iwinfo info` — ответ на главный вопрос и одна ловушка

**Поле с ассоциированным SSID называется `ssid`.** Подтверждено сходимостью:
`ssid: "John24"` совпадает с включённой секцией `wifinet0` из
`raw/10-uci-show-wireless.txt`. Это и есть `associated_ssid` в `/api/status`.

> **Ловушка: поле `bssid` в режиме station содержит MAC самого роутера.**
>
> В фикстуре `bssid: "94:83:C4:E4:69:D8"`. Тот же адрес виден в
> `raw/25-netstat.txt` как `fe80::9683:c4ff:fee4:69d8` — link-local нашего же
> интерфейса. А сеть `John24` в скане (`raw/23`) вещает с BSSID
> `1C:3B:F3:DF:74:88`.
>
> То есть это **не адрес точки доступа, к которой мы подключены**. Поле
> выглядит осмысленным и врёт — худший вид данных. Не использовать, пока
> не разобрано отдельно.

Полезное рядом: `signal` (−45), `noise` (−79), `quality`/`quality_max`,
`bitrate`, `channel`, `frequency`, `mode: "Client"`.

## `network.interface.wwan status` — как считать «интернет есть»

Одного поля недостаточно. `online.ok` истинно, когда выполнено **всё**:

```
up == true
  И  len(ipv4-address) > 0
  И  есть маршрут { target: "0.0.0.0", mask: 0 } с непустым nexthop
```

Почему не только `up`: интерфейс поднимается и без аренды DHCP — тогда
`up: true`, адреса нет, интернета нет. Проверка одного флага дала бы
уверенное «всё хорошо» ровно в той ситуации, ради диагностики которой
панель и открывают.

Наблюдённые значения: адрес `192.168.0.234/24`, шлюз `192.168.0.1`,
`uptime: 215`, `data.dhcpserver: 192.168.0.1`.

Попутно: **upstream в `192.168.0.0/24`, LAN роутера в `192.168.9.0/24`** —
подсети не пересекаются, NAT отработает штатно. Совпади они, был бы
не наш баг, но наша головная боль.

## `network.wireless status`

Даёт связь **секция ↔ ifname прямо в ответе**: `radio0.interfaces[]` содержит
и `section: "wifinet0"`, и `ifname: "phy0.0-sta0"` в одном объекте.
Сопоставлять по порядку не нужно, и хардкодить имя не нужно тем более —
за этим следит `scripts/check-no-hardcoded-if.sh`.

Поле `<radio>.pending` — источник `pending_apply` в `/api/status`:
конфигурация изменена, но к радио не применена. В фазе 1 наши записи
применения не вызывают, поэтому `pending_apply: true` после нашей записи —
штатное состояние, а не тревога.

## Порты: 8080 занят

`raw/25-netstat.txt`. Заняты: 22, 53, 80, 443, 1053, 1080, 7890, 7891,
7892, **8080**, 9090, 40253. Почти всё за mihomo.

Демон получает **8088**. Проверить `netstat` перед первым запуском всё
равно стоит: снимок мог устареть.

Заодно подтверждён **Clash API на 9090** (`:::9090 LISTEN mihomo`). Вместе с
секретом и раскладкой групп (`raw/60`, `raw/61`, разбор — [`nikki.md`](nikki.md))
это закрывает RQ-01 целиком.

## b4 в снимке лежал

Порта **7000 в `netstat` нет**, хотя в `raw/50-b4-api.txt` он был. И три
первых `curl` к `/api/sets` вернули пустоту, а четвёртый — данные.

Значит b4 в этот момент перезапускался. Это не курьёз, а подтверждение
проектного решения: клиент b4 обязан переживать недоступность как `503`
и не считать её ошибкой демона. Панель в этот момент гасит чипы сетов
и продолжает работать.
