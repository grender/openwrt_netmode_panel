# ADR-0018: SPEC §4, §6, §10 и §11 заменены этим набором решений

## Статус
Принято — 2026-08-02

## Контекст

`SPEC-backend-router-panel.md` остаётся базовым документом: целевая среда
(§1), инвентарь роутера (§2), разделение быстрых и медленных операций (§5),
список эндпоинтов (§7), светодиоды (§8), планировщик и формат лога (§9),
границы (§12) — всё это в силе.

Но четыре раздела написаны до разведки и до решений владельца, и содержат
требования, которые теперь **неверны**. Опасность не в том, что они устарели,
а в том, что они написаны утвердительно и с обоснованием: «откат обязателен»,
вот интерфейс, вот структура конфига. Читатель — человек или агент — примет
их за задание и «починит недостающее».

Этот ADR — единственное место, где перечислено, что именно из спеки больше
не является заданием.

## Решение

| Раздел спеки | Что там сказано | Что вместо | Где |
|---|---|---|---|
| **§4, Слой 1** | `/etc/config/netmode` с `config network 'home'` — каталог сохранённых сетей | Сохранённые сети — обычные `wifi-iface` в `/etc/config/wireless`. `config network` не существует | [ADR-0003](0003-saved-networks-in-wireless.md) |
| **§4, Слой 1** | `option upstream 'home'` — id активной сети | Выбор выводится из `disabled`, нигде не хранится | [ADR-0004](0004-selection-derived.md) |
| **§4, Слой 2** | `netmode-apply` — единственное место старта/останова сервисов | **В силе.** Усилено удалением `Service` из `Executor` | [ADR-0015](0015-executor-shape.md) |
| **§4, Слой 3** | демон слушает на LAN, токен в конфиге | В силе, но токен — в сайдкаре 0600, в UCI только путь | [ADR-0014](0014-lan-bind-and-token.md) |
| **§6** | снапшот `/etc/config` в tar, таймер 90 с, `POST /api/confirm`, «откат обязателен» | Отката нет ни в какой форме. `SnapshotConfigs`/`RestoreConfigs` и `POST /api/confirm` удалены | [ADR-0006](0006-no-rollback.md) |
| **§6** | `Manager` с полем `rollback *time.Timer` | Поля нет. Сериализация джобов — в силе, `409 job_busy` — в силе | [ADR-0006](0006-no-rollback.md), [ADR-0013](0013-fast-vs-slow.md) |
| **§10** | интерфейс `Executor` из 8 методов | Другой интерфейс: нет `Run`, `Service`, `WifiScan`, снапшотов; есть перечисление, удаление, создание секции, чтение стейджинга, `UbusCall` | [ADR-0015](0015-executor-shape.md), [`executor.md`](../contracts/executor.md) |
| **§10** | `WifiScan(device)` возвращает `[]Network` | Чистая функция `wireless.ParseScan([]byte)` над результатом `UbusCall` | [ADR-0015](0015-executor-shape.md) |
| **§11, п.1** | начать с `Executor` + снапшот/восстановление, проверить с `reboot` | Снапшота нет. Фаза 1 — `Executor` + чтение + запись выключенных секций | [ADR-0006](0006-no-rollback.md), [ADR-0009](0009-phase1-write-invariant.md) |
| **§11, п.7** | `/api/upstream` последним, после проверки отката | Отложено в фазу 2, отдаёт `501` | [ADR-0016](0016-upstream-deferred.md) |
| **§3, п.1–2** | выяснить API b4; при необходимости дублировать выбор в `b4.json` | Выяснено: выбор переживает рестарт. `b4.json` не трогаем никогда | [ADR-0007](0007-b4-api-only.md) |
| **§7** | `POST /api/confirm` | Эндпоинта нет: подтверждать нечего | [ADR-0006](0006-no-rollback.md) |
| **§9** | «`flock` в `happ2clash` сохранить — скрипт остаётся запускаемым вручную из ssh» | Скрипта нет: конвертер подписки внутри демона, `/usr/local/bin/happ2clash` и `/etc/nikki/happ2clash.jq` удаляются с роутера при установке. У файла провайдера один писатель, второму замку не с кем расходиться. Строку про `happ2clash` в `/etc/crontabs/root` по-прежнему убирают руками. Инвентарная запись §2 про конвертер описывает прошлое, а не задание | [ADR-0031](0031-subscription-in-daemon.md) |

Что из спеки осталось нетронутым и обязательно к исполнению: §1 (сборка,
бюджет 10 МБ, только stdlib), §2, §5 (быстрые/медленные — кроме двух строк
про исполнителя обновления подписки: «Обновить подписку — happ2clash» в
таблице и «запустить happ2clash» у `POST /api/subscription/update` описывают
удалённый скрипт, см. ряд §9 выше и [ADR-0031](0031-subscription-in-daemon.md)), §7 (кроме
`confirm`), §8 (светодиоды, `trigger=timer`, быстрые операции LED не трогают),
§9 (планировщик внутри демона, лог в `/etc/nikki/updates.log`, обрезка до 200
строк — **но не `flock` в `happ2clash`**, см. строку §9 в таблице выше),
§12 (границы).

## Последствия

**Приобретаем**

- Одно место, куда смотрит человек, обнаруживший расхождение между кодом и
  спекой. Дальше — по ссылке в конкретный ADR за причиной.
- Спека не переписывается. Она остаётся историческим документом и продолжает
  быть полезной там, где верна.

**Платим**

- Два документа вместо одного, и чтение спеки без этой таблицы вводит в
  заблуждение. Смягчается ссылкой из README и грепающими скриптами на
  ключевые решения.
- Таблица будет устаревать по мере фазы 2 — её придётся вести.

## Рассмотренные альтернативы

| Вариант | За | Против | Почему не он |
|---|---|---|---|
| Переписать спеку под принятые решения | Один непротиворечивый документ | Теряется история: непонятно, что было решено изначально и почему изменилось. Именно это знание защищает от повторного «улучшения» | ADR существуют ровно для того, чтобы хранить «почему» |
| Пометки прямо в тексте спеки | Видно на месте | Спека — входной документ владельца; править её от лица исполнителя неверно | Чужой документ |
| Ничего не писать, полагаться на скрипты | Меньше текста | Скрипты ловят только код, и только там, где формулируется грепом. `/api/confirm` и структура конфига грепом не ловятся | Механики недостаточно |
