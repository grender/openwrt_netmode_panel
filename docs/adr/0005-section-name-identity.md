# ADR-0005: Идентификатор сохранённой сети — имя секции, индексы наружу не выходят

## Статус
Принято — 2026-08-02

## Контекст

UCI адресует секции двумя способами:

```
wireless.wifinet2.ssid='ATOM'      # именованная секция
wireless.@wifi-iface[2].ssid       # позиционный индекс
```

На этом роутере все `wifi-iface` **именованные** (`raw/10-uci-show-wireless.txt`):
`wifinet0`, `wifinet1`, `wifinet2`. Именно имя секции отдаёт `ubus call
network.wireless status` в поле `interfaces[].section`
(`raw/21-ubus-network-wireless-status.json`) — вместе с `ifname` в том же
объекте.

Индекс — это позиция в файле. Удаление любой секции выше по файлу сдвигает
все нижние. Если панель выдала клиенту `@wifi-iface[2]`, а пользователь в
соседней вкладке LuCI удалил `wifinet0`, то `DELETE` по этому идентификатору
удалит **чужую сеть**.

## Решение

1. Идентификатор сети в API (`id` в `/api/wifi/networks`, `{id}` в пути
   `DELETE`) — **имя секции UCI**: `wifinet0`, `wifinet2`.
2. Синтаксис `@wifi-iface[N]` не появляется ни в одном ответе, ни в одном
   запросе, ни в одном UCI-вызове демона.
3. Если в `wireless` встретилась **безымянная** `wifi-iface` с
   `device=radio0`, `mode=sta`, она показывается в списке с `"id": null` и
   `"editable": false`. Мы её видим, считаем при классификации выбора, но не
   трогаем. Дать ей имя — значит переписать чужую секцию.
4. Имена, которые создаём мы, — `netmode_<8 hex>` (например
   `netmode_a1b2c3d4`). Префикс отличает наши секции в `uci show` и не
   конфликтует с нумерацией LuCI (`wifinetN`), которая может занять любой
   свободный номер.
5. Имя интерфейса (`phy0.0-sta0`) не хардкодится никогда — выводится из
   `network.wireless status`. Проверяется `scripts/check-no-hardcoded-if.sh`.

> **RQ-02 (открыт, низкий приоритет)** — сохраняет ли LuCI Save&Apply
> именованные секции и неизвестные ей опции. Если окажется, что LuCI
> переименовывает секции, идентификаторы придётся строить на `ssid`, а это
> ломается на двух сетях с одинаковым именем. Проверяется на выключенной
> секции-черновике.

## Последствия

**Приобретаем**

- Идентификатор стабилен при любых правках в LuCI и ssh, кроме переименования
  самой секции.
- `id` совпадает с тем, что человек видит в `uci show wireless` и в логах
  netifd. Отладка не требует перевода из одного пространства имён в другое.
- `section` из `ubus` напрямую соединяется с `id` — таблица соответствия не
  нужна.

**Платим**

- Безымянные секции придётся поддерживать как read-only частный случай.
  Это лишняя ветка в коде и лишний столбец в UI ради конфигурации, которой
  на этом роутере нет.
- Переименование секции руками выглядит как «сеть удалили и создали новую» —
  панель потеряет её из выделения. Приемлемо: это ручная операция.

## Рассмотренные альтернативы

| Вариант | За | Против | Почему не он |
|---|---|---|---|
| Индекс `@wifi-iface[N]` | Работает всегда, даже для безымянных | Сдвигается при удалении → удаление чужой сети от чужой правки. Это порча данных, а не неудобство | Отвергнуто безоговорочно |
| `ssid` как идентификатор | Читаемо, стабильно при переименовании секции | SSID не уникален; два сохранённых профиля одной сети (разные пароли/BSSID) — обычная вещь | Ключ, который может совпасть, — не ключ |
| Свой `option netmode_id` в секции | Полностью наш, стабилен | Пишет в чужие секции; риск потери при LuCI Save&Apply (RQ-02); нарушает [ADR-0009](0009-phase1-write-invariant.md) для включённой сети | Стоимость выше выигрыша |
