# ADR-0047: Приложение desktop/ — тестовая VM из строки меню Mac

## Статус

Принято 2026-09-25. Ничего не отменяет: дополняет стенд
[ADR-0045](0045-vm-test-rig.md) графической обёрткой. Инструкция —
[desktop/README.md](../../desktop/README.md), раздел «Приложение desktop/» в
[docs/vm-utm.md](../vm-utm.md).

## Контекст

Работа с VM — это пять разных действий в терминале: `make vm-up` /
`make vm-down`, токен панели через `ssh.sh cat /etc/netmoded/token`, пароль
прокси через `uci get nikki.@authentication[0].password`, и руками —
прокси в «Системных настройках» или в Firefox (там хост и порт — разные
поля). Забытый системный прокси на погашенную VM оставляет Mac без
интернета, и причину не видно.

## Решение

**Electron-приложение в строке меню, `desktop/`.** Окно управления на
Preact (как панель), иконка-точка: серая — VM стоит, жёлтая — грузится или
режим панели не `nikki`, зелёная — работает; кольцо вокруг — системный
прокси смотрит в VM. Действия: старт, стоп, панель внутри окна (см. ниже), копирование настроек прокси по частям
(хост, порт, логин, пароль, `host:port`, `http://`, `socks5://`, строка
`export`), системный прокси вкл/выкл с показом, что сейчас действует.

**Один облик с панелью; панель — секция страницы.** Стили приложения —
`web/panel/src/styles.css` через `@import` (не копия): те же токены,
карточки и заголовки-аккордеоны. Окно узкое (440 px — панель в
одноколоночной раскладке). Секция «Panel» есть, только пока панель
отвечает (токен прочитан, `/api/status` отвечает; три пропуска опроса
подряд — нет). Открытая, она убирает свой заголовок: `iframe` на
`http://127.0.0.1:<VM_HTTP_PORT>/` стоит в левом верхнем углу окна во всю
ширину (полосы прокрутки у окна нет — она отъедала бы ширину), под ним —
строка «Hide panel» и свёрнутые секции приложения. Главный процесс
вытягивает окно на всю высоту экрана и возвращает прежний размер при
закрытии или когда панель перестала отвечать.

**Одна прокрутка и родной вид.** В кадр панели главный процесс добавляет
стили и скрипт (`desktop/src/main/panelEmbed.ts`; сама панель не менялась):
у панели снимаются её рамки (`.page`, `.shell`), и её карточки встают на
те же поля 12 px и зазоры 9 px, что и секции приложения. Кадр сам не
прокручивается: скрипт сообщает высоту содержимого (`postMessage`), и
приложение делает кадр ровно такой высоты — прокручивается только окно.
Плавающий тост панели (`.slot-float`, `position: fixed`) привязан к
низу кадра, который выше экрана; приложение сообщает панели, где кончается
видимая часть кадра, и тост ставится над этой линией. Страница
`file://` для панели — чужой сайт, и её кука `SameSite=Strict` туда не
ходит; поэтому главный процесс дописывает `Authorization: Bearer <токен>`
к запросам на origin панели (`session.webRequest`) — демон принимает его
на всех маршрутах, а токен в окно не попадает.

**С VM приложение говорит только через `scripts/vm/*.sh`.** Новые
`env.sh`, `status.sh`, `start.sh`, `proxy-info.sh` подключают `common.sh`
и печатают `KEY=value`; остановка — прежний `down.sh`. Порты и имя VM
по-прежнему живут в одном месте — `check-vm-scripts.sh` охраняет именно
это, и приложение не стало вторым местом. `start.sh` — быстрый запуск
созданной VM (UTM или QEMU — `vm_backend` в `common.sh`), без provision и
deploy; код 3 — VM нет, и приложение запускает `make vm-up` с живым логом.
Цикл запуска UTM вынесен из `utm-create.sh` в `utm_start` (`common.sh`).

**Секреты не покидают главный процесс.** Пароль и токен читаются одним
ssh (`proxy-info.sh`), в окно уходит только маска; в буфер обмена значение
кладёт главный процесс по id.

**Системный прокси — только хост и порт, без логина.** `networksetup`,
запущенный от пользователя, кладёт логин в связку ключей, но флаг
«Authenticated Proxy» не ставит — CFNetwork (URLSession, Safari) логин не
подставляет и получает 407 (проверено 2026-09-25). Аутентификацию nikki в
VM решено не снимать: приложения, умеющие спрашивать логин прокси,
спросят; логин и пароль — в списке копирования. Записи связки ключей для
`127.0.0.1:<порт>` приложение удаляет при включении и выключении.

**Системный прокси не переживает VM.** Выключается перед `down.sh`, при
выходе из приложения, когда опрос (2 с) видит VM не запущенной, и при
старте приложения, если в `userData/state.json` записано, что оно включало
прокси (падение, `kill -9`).

## Последствия

- `make desktop` (нужен Node 22) — вне `make verify`, который по-прежнему
  требует только Go и шелл. Тесты приложения — `npm test` в `desktop/`
  (vitest: строки копирования, разбор `scutil --proxy` и
  `networksetup -listnetworkserviceorder`).
- Приложение не упаковывается в `.app`: это инструмент разработчика,
  запускается из клона (`NETMODED_REPO` — если не из `desktop/`).
- Системный прокси ставится на одну сетевую службу (по умолчанию — ту, что
  держит маршрут по умолчанию); смена Wi-Fi на кабель при включённом прокси
  оставит новую службу без прокси.
- Прокси пропускает трафик, только когда панель в режиме `nikki`;
  приложение показывает режим и предупреждает.

## Рассмотренные альтернативы

- **Tauri / SwiftUI.** Меньше вес, но второй язык в репозитории (Rust или
  Swift) ради инструмента на пять кнопок; Electron + Preact повторяет стек
  панели.
- **Порты и команды прямо в приложении.** Второе место правды рядом с
  `common.sh` — ровно то расхождение, от которого стережёт
  `check-vm-scripts.sh`.
- **Системный прокси с логином через диалог администратора.** Не
  проверено, что root-`networksetup` ставит флаг аутентификации; пароль
  администратора на каждое включение. Отложено.
- **Снять аутентификацию nikki в VM.** Порт проброшен только на
  `127.0.0.1` Mac, так что логин там мало что защищает, — но VM перестала
  бы совпадать с роутером. Отклонено владельцем.
