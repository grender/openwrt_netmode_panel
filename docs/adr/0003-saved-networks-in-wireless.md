# ADR-0003: Сохранённые сети живут в `/etc/config/wireless`

## Статус
Принято — 2026-08-02. **Отменяет SPEC §4, Слой 1** в части `config network`.

## Контекст

SPEC §4 предлагал собственный конфиг с секциями сохранённых сетей:

```
config network 'home'
    option ssid 'HomeNet'
    option encryption 'psk2'
    option key '...'
```

То есть каталог сетей, из которого демон материализует `wifi-iface` в момент
переключения.

Разведка показала, что модель **уже существует на роутере в другом виде** и
применяется вручную (`raw/10-uci-show-wireless.txt`):

- `wifinet0` — `John24`, `mode=sta`, `device=radio0`, опции `disabled` нет →
  включена, именно она в ассоциации;
- `wifinet2` — `ATOM`, `mode=sta`, `device=radio0`, `disabled='1'` →
  сохранённая, но не выбранная.

Мигрировать нечего: то, что спека предлагала спроектировать, владелец уже
завёл руками штатными средствами.

## Решение

**Сохранённая upstream-сеть — это обычная секция `wifi-iface` в
`/etc/config/wireless`** со следующим набором признаков:

| Опция | Значение | Смысл |
|---|---|---|
| `device` | `radio0` | станционное радио, 2.4 ГГц |
| `mode` | `sta` | клиент |
| `network` | `wwan` | upstream L3 (`raw/11-uci-show-network.txt`) |
| `ssid`, `encryption`, `key` | — | как обычно |
| `disabled` | `'1'` у всех, кроме выбранной | см. [ADR-0004](0004-selection-derived.md) |

Секция «наша», если совпали `device=radio0` **и** `mode=sta`. Всё прочее в
`wireless` — не наше: `wifinet1` (`grenderNet`, `mode=ap`, `radio1`) не
показывается в списке сетей и не редактируется никогда.

В `/etc/config/netmode` секций `config network` **нет** — см.
[`docs/contracts/uci-netmode.md`](../contracts/uci-netmode.md).

## Последствия

**Приобретаем**

- Сети остаются видимыми и редактируемыми в LuCI. Панель не становится
  обязательной прослойкой между владельцем и его роутером.
- Нет синхронизации между каталогом и реальным конфигом — а значит, нет
  состояния «в каталоге есть, в `wireless` нет» и обратного.
- Нет миграции: то, что уже настроено руками, работает с первого запуска.
- Формат один — тот, что понимает netifd. Опции, которых мы не знаем
  (`bssid`, `ieee80211r`, `wds`), сохраняются просто потому, что мы их не
  трогаем.

**Платим**

- Мы пишем в файл, который редактируют LuCI и ssh. Отсюда нужен отпечаток
  ([ADR-0011](0011-optimistic-concurrency.md)) и проверка чужих
  незакоммиченных правок.
- `/etc/config/wireless` имеет права 644 (`raw/40-etc-config-perms.txt`) —
  пароли сетей мировидимы. Это не мы сделали и не нам чинить, но токен API
  в этот файл класть нельзя ([ADR-0014](0014-lan-bind-and-token.md)).
- Нельзя хранить наши собственные поля (заметку, порядок, «последний раз
  работала»): чужие опции в `wifi-iface` может выбросить LuCI при Save&Apply
  (RQ-02). Поэтому таких полей нет вовсе.

## Рассмотренные альтернативы

| Вариант | За | Против | Почему не он |
|---|---|---|---|
| Каталог `config network` в `/etc/config/netmode` (SPEC §4) | Свобода формата, свои поля, невидим для LuCI | Два источника правды об одном и том же; сеть, заведённая в LuCI, для панели не существует; при переключении надо материализовать секцию — то есть всё равно писать в `wireless` | Даёт всю сложность синхронизации и ни одного выигрыша |
| Гибрид: `wireless` — правда, `netmode` — метаданные (заметки, порядок) | Можно UX-поля | Метаданные осиротеют при удалении сети из LuCI; нужен сборщик мусора | Отложено. Ни одно поле мокапа этого не требует |
| Хранить только активную сеть, остальные — в файле панели | Меньше секций в `wireless` | Ровно то же расщепление правды, только наоборот | То же возражение |
