# ADR-0052: Несколько подписок — один общий список узлов

## Статус

Принято 2026-11-17. Дополняет [ADR-0031](0031-subscription-in-daemon.md)
(конвертер и манифест), [ADR-0034](0034-subscription-url-editable.md) и
[ADR-0012](0012-write-only-credentials.md) (адрес — секрет на запись),
[ADR-0044](0044-autopool.md) и [ADR-0050](0050-exit-chains-via-subscription.md)
(пулы берут узлы из того же списка). Ничего не отменяет: с одной подпиской
демон ведёт себя как прежде.

## Контекст

У владельца появилась вторая подписка, у другого провайдера, и нужен общий
пул узлов из обеих. Демон знал ровно один адрес
(`netmode.main.subscription_url`) и ходил за ним с одним заголовком
`User-Agent: Happ`.

Второй провайдер (панель типа Remnawave с лимитом устройств) на такой запрос
отдаёт заглушку — два «узла» с именами «Приложение не поддерживается» — и
заголовок `x-hwid-not-supported`. С заголовком `x-hwid` (так представляется
клиент Happ) он отдаёт тот же формат, что и первый: массив Xray-конфигов.
Разведка — [`docs/recon/happ.md`](../recon/happ.md), раздел про второго
провайдера.

## Решение

### Слияние в один файл, а не второй провайдер mihomo

Все подписки сливаются в существующие `providers/sub.yaml`, манифест и
`outbounds.json` (`happ.Merge`, `subs.Updater`). Имена провайдеров `sub` и
`sub-auto` — контракт с профилем, который демон не пишет (ADR-0002,
ADR-0046): второй провайдер mihomo потребовал бы править профиль на каждом
роутере — `PROXY`, `AUTO`, группы хопов. Слияние не требует ничего: авто-пул,
пул хопов, свои выходы и подписка телефонов видят один список, как видели.

### Кэш на подписку

Каждая подписка качается и разбирается отдельно; удачный разбор кладётся в
`/etc/netmoded/subs/<id>.json` (0600: там узлы с ключами) вместе с итогом
попытки. Общий список собирается из кэшей. Подписка, не скачавшаяся в этот
раз, остаётся в пуле прошлыми узлами — иначе отказ одного провайдера
закрывал бы туннель всем, кто закреплён на его сервере.

Обновление — отказ, только когда не скачалась ни одна: тогда файлы не
трогаются, как и раньше. Иначе это успех с пометкой `partial`: запись
журнала `ok` с непустым `err` (формат `logs.Entry` не изменён). Ноль узлов в
ответе — отказ этой подписки, а не повод вытеснить её прошлые узлы.

### Имена: хвост только при совпадении

Имя уникально на весь список: по нему узел выбирают, по нему он попадает в
пулы, от него считается группа-однохопник (`nm-hop-<hash>`). Имя, уже
занятое более ранней подпиской, получает хвост ` · <имя подписки>`; имена
ранней подписки не меняются никогда — добавление второй не сдвигает ничего
закреплённого в первой. Пул балансировщика переезжает вместе с именами
своей подписки.

### ID устройства

Один на роутер — `netmode.main.hwid`, заводится демоном (64 hex) при первой
подписке, которой он нужен. Шлётся только подпискам с `hwid '1'`
заголовками `x-hwid`, `x-device-os`, `x-ver-os`, `x-device-model`: каждый
новый ID занимает у провайдера слот устройства, и слать его всем подряд —
тратить слоты там, где их не просили. Наружу не отдаётся, как и адрес.

Отказы по устройству приходят кодом 200 и телом, которое разбирается как
подписка без узлов; их называет заголовок: `x-hwid-not-supported` →
«провайдер требует ID устройства», `x-hwid-max-devices-reached` → «кончились
слоты устройств».

### Хранение и API

Основная подписка остаётся в `main.subscription_url`; остальные, до трёх, —
секции `config subscription '<id>'` с `label`, `url`, `hwid`
([`uci-netmode.md`](../contracts/uci-netmode.md)). Маршруты
`GET/POST /api/subscriptions`, `PUT/DELETE /api/subscriptions/{id}`; прежние
`/api/subscription` работают с основной. Удаление — джоб: секция, кэш и
пересборка списка из кэшей остальных, без сети.

У адреса без параметров запроса секрет лежит в пути — маска таких подписок
закрывает последний сегмент пути. Маска основной не менялась.

### Заодно

- **trojan** (tcp и grpc, только с TLS) переводится конвертером: у второго
  провайдера один такой сервер. На движке не проверен — снята форма записи.
- **Перечитка `sub-auto`**: обновление перечитывало только `sub`, и новые
  узлы не попадали в `AUTO` до перезапуска nikki.

## Последствия

- Хвост имени держится, пока оригинал есть в ранней подписке. Исчезнет он —
  имя второй вернётся без хвоста, и закреплённый по нему выбор укажет на
  другой сервер. При переименовании демон пишет строку в журнал.
- Авто-пул в режиме «все, кроме» и пул «как в подписке» вырастают сами:
  балансировщики обеих подписок — отдельные строки «Авто», пул «как в
  подписке» — их объединение.
- Удалили последнюю подписку с узлами — пересобирать не из чего, и прежний
  файл провайдера остаётся до следующего обновления.
- Узлы из кэша не несут сведений о незнакомых ключах xhttp: предупреждение о
  них выходит только в прогон, когда подписка скачана.
- Провайдер может сменить требования к клиенту — подписка уйдёт в отказ, её
  узлы останутся из кэша до следующей удачи.

## Рассмотренные альтернативы

- **Провайдер mihomo на каждую подписку.** Правка профиля владельца на
  каждом роутере и фильтр авто-пула на нескольких провайдерах; совпадения
  имён всё равно всплывают в Clash API, где узел адресуется именем.
- **Хвост с именем подписки всем узлам второй.** Устойчиво, но все имена
  длиннее, а совпадений сейчас нет ни одного.
- **Список адресов в одной опции UCI.** Нет устойчивого id для кэша, маски
  и правки; нет места для имени и признака `hwid`.
- **Свой ID устройства на подписку.** Лишние слоты у провайдеров без пользы:
  роутер — одно устройство.
