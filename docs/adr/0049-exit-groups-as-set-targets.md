# ADR-0049: Свои выходы — группы профиля `EXIT-*` как цель набора и правила

## Статус

Принято 2026-11-13. Дополняет [ADR-0040](0040-custom-rules-in-mixin.md) и
[ADR-0041](0041-per-set-direction.md): у набора и своего правила появляется
третья цель. Ничего не отменяет: файлы без новых целей читаются и
отпечатываются байт-в-байт как прежде. Номера 0047–0048 заняты в неслитых
ветках (`claude/desktop-vm-app`, b4 SOCKS5).

## Контекст

До этого решения у набора было два направления: `tunnel` (группа `BYPASS`,
то есть один узел подписки на весь туннель) и `direct`. README прямо
называл «выбор узла-цели для отдельного набора» неподдерживаемым.

Появилась своя выходная нода в Астане с двумя выходами, выбираемыми по UUID:

- **resi** — ISP-прокси с домашним IP (Tele2 KZ): для того, что отличает
  дата-центр от дома, — LLM (OpenAI, Anthropic), Google, PayPal, стриминги;
- **dc** — IP самого VPS: для того, что режется по IP, — Telegram, Instagram.

Нужно направлять конкретные наборы в конкретный выход: `category-ai-!cn`,
`openai`, `anthropic`, `google` → resi; `telegram`, `instagram` → dc.

## Решение

### Цель `exit` с именем группы

`RuleAction` получает третье значение `exit`, у `Set` и `Rule` — поле
`Group`. Правило в файле — `RULE-SET,nm-geosite-openai,EXIT-RESI`; в строке
состояния на месте действия стоит `@ИМЯ`: `openai>@EXIT-RESI`. Прежние
токены не меняются, поэтому отпечатки выборов без групп остаются верными, а
демон прежней версии на `>@…` отвечает `500 mixin_corrupt` — громко, как
договорено для `rules=` и `auto=`.

### Группы живут только в профиле

Миксин групп не пишет: `proxy-groups` при склейке `nikki.init`
**конкатенируются**, и наша одноимённая группа уронила бы движок; а своя
группа под другим именем пропала бы вместе с файлом при «Вернуть профилю»,
оставив профиль ссылаться на пустоту (тот же довод, что в ADR-0044). Ноды с
секретами (UUID, ключи Reality) тем более не место в файле, который демон
переписывает целиком и отдаёт панели. Поэтому ноды и группы заводит
владелец в профиле, а демон только ссылается на них.

### Список целей — из живого движка, по приставке `EXIT-`

Рассматривались два источника: явный список в UCI и живой ответ
`GET /proxies`. Список в UCI — вторая правда о том же: он и профиль
расходятся молча, и расхождение обнаруживается как не поднявшийся nikki.
Живой движок — та самая правда, на которой правило и будет работать.

Приставка, а не «все группы профиля»: в `main.yml` владельца групп много, и
панель предлагала бы в цели служебные (`GLOBAL`, `AUTO`, `BYPASS`). Имя —
`EXIT-` и 1–32 знака `A-Za-z0-9._-`: оно уезжает в одинарные кавычки
правила и в строку состояния, где `,` `;` `>` `|` и пробел — разделители.

### Проверка до записи

Правило на несуществующую группу не даёт mihomo подняться, а отката нет
(ADR-0006). Поэтому `PUT` до первой записи:

- движок ответил — каждая группа из выбора есть у него и это **группа**, не
  узел, иначе `400 unknown_group`;
- движок молчит — уже применённые группы проходят (проверены прошлой
  записью; иначе смена одного лишь «откуда качать» без движка была бы
  невозможна — тот же довод, что у имён наборов без каталога), новая —
  `503 groups_unverified`.

Это отличается от проверки `BYPASS`, где молчание — пропуск: `BYPASS`
обязан быть в любом профиле под нашим контрактом, а `EXIT-*` владелец
пишет сам и может опечататься.

### Ярусов нет — порядок задаёт владелец

Наборы пересекаются: `geosite:google` включает `youtube`. Ярус «группы
раньше всех» отправил бы YouTube в домашний выход вопреки желанию держать
его в туннеле; ярус «группы после всех» дал бы обратную ошибку для
`category-ai-!cn`. Поэтому цель-группа не сдвигает строку: набор стоит там,
куда его поставил владелец, и панель получила режим «Изменить порядок»
(перестановка наборов и своих правил стрелками; перестановка — изменение
выбора, она меняет отпечаток). Пояснение «верхний побеждает» с примером
google/youtube — в самой панели.

### Выходы — fail closed

Рекомендуемая раскладка — `select` с нодой и `REJECT`:

```yaml
- name: EXIT-RESI
  type: select
  proxies: [kz-nqz-exit-01-resi, REJECT]
```

`select` сам не переключается: упала нода — соединения рвутся, а не уходят
через чужой IP. Для resi это и есть требование (LLM-сервис, увидевший
другой IP, хуже, чем недоступный); для dc выбрано то же ради
предсказуемости. `REJECT` вторым участником — способ закрыть выход руками.
Ноды можно добавить в `PROXY.proxies` для ручного выбора; в `AUTO` — нет:
url-test смешал бы их с подпиской (ADR-0031, ADR-0044).

## Цена

- **Удаление группы из профиля роняет старт nikki**, если на неё ещё
  ссылается набор (замерено на VM: `netmode-apply` — код 6, `proxy
  [EXIT-DC] not found` в `core.log`). Проверка при записи этого не ловит —
  профиль правится мимо демона. Порядок для владельца: сначала снять цель в панели, потом
  группу. Восстановление — `mixin_file_content=0` (контракт, раздел про
  цели-группы).
- Без ответа движка новую цель не выбрать. Это осознанно: записать
  непроверенную ссылку — рискнуть стартом.
- Нода с `udp: false` не пропускает UDP: QUIC браузер переведёт на TCP, а
  звонки Telegram через `EXIT-DC`, скорее всего, не заработают.

## Что дальше (оценено, не сделано)

Запасной путь при заблокированном входе на ноду — копия прокси с
`dialer-proxy: AUTO` (цепочка через платный узел) и `fallback` «прямо,
потом через цепочку, потом REJECT» внутри `EXIT-*`. Ложится на эту же
модель без кода в демоне: миксин ссылается только на `EXIT-*`, что внутри —
решает профиль. Хоп — `AUTO`, не `PROXY`: закреплённый на KZ-ноде `PROXY`
дал бы петлю. `xtls-rprx-vision` через `dialer-proxy` теряет splice и
деградирует до TLS-в-TLS — проверять на VM.
