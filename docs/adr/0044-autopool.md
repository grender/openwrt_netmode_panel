# ADR-0044: Авто-пул — отдельный провайдер под фильтром, а не отдельная группа

## Статус

Принято 2026-09-19. Уточняет [ADR-0039](0039-geosite-rulesets-mixin-file.md):
у `mixin.yaml` появляется вторая независимая секция, и пакет, который им
владеет, переименован из `internal/rulesets` в `internal/mixin` — по файлу,
а не по одной из двух своих секций. Ничего не отменяет: профиль со старой
раскладкой групп продолжает работать.

## Контекст

`PROXY` в профиле владельца была `url-test` поверх `use: [sub]`, а «Авто» в
панели — снятие ручного закрепления (`DELETE /proxies/PROXY`). Отсюда два
следствия, и оба вскрылись на живом роутере 19.09.2026.

**Пул авто-выбора и список ручного выбора были одним списком.** Сузить
первый, не отняв узлы у второго, было нельзя в принципе.

**Движок выбирал «быстрейшего» из всех 38 узлов подписки** — и выбрал
`🇦🇬💳Альфа`. То есть трафик, который правила гонят в туннель ради обхода,
выходил через домашний узел. Ровно та опасность, о которой предупреждает
[ADR-0031](0031-subscription-in-daemon.md), только случившаяся.

Провайдер устроен иначе. Его «Авто | Быстрый узел» — это конфиг Xray с
балансировщиком `leastLoad` (`maxRTT: 1500ms`, `expected: 7`, `baselines:
[200ms, 500ms]`, штраф ×3 на обходные) над **двенадцатью отобранными им
европейскими серверами**, с собственным замерщиком раз в две минуты по
среднему из трёх проб (`docs/recon/raw/94-proxies-vs-providers.txt`).

## Решение

Развести пулы, оставив в панели одну строку «Авто».

**`PROXY` становится селектором, `AUTO` — его участником.** Это возврат к
исходному замыслу SPEC §7, от которого отказались в разведке как от
ненужного: тогда `DELETE` решал задачу дешевле. Теперь не решает — пул
авто-выбора обязан отличаться от списка ручного.

**Сужение выражается фильтром на ОТДЕЛЬНОМ провайдере, а не своей группой.**
Довод механический. `nikki.init` склеивает так:

```
. * $item | .proxy-groups = .nikki-proxy-groups + .proxy-groups | …
```

`proxy-groups` конкатенируются: дописать поле в группу профиля нельзя, а
своя группа с тем же именем дала бы две одноимённых, и движок не
поднимется. `proxy-providers` — карта, и `yq` сливает её по ключу. Поэтому
профиль объявляет `sub-auto` **без фильтра** (весь список), а демон
дописывает ему `filter` или `exclude-filter`.

Отсюда свойство, ради которого всё и выбрано: **выключенная склейка не
ломает сеть.** Флаг `mixin_file_content` в 0 — остаётся профильный
`sub-auto` без фильтра, `AUTO` работает по всему списку, движок жив.
Сломать сеть настройкой пула нельзя.

**Три режима:** `deny` (все, кроме отмеченных), `allow` (только отмеченные),
`provider` (состав из балансировщика подписки, пересобирается при каждом её
обновлении). Умолчание — `deny` с пустым списком, то есть прежнее
поведение, и в файл оно не пишется вовсе.

**`empty-fallback: REJECT`** в профиле. Не `DIRECT`: тот оказался fail-open —
при пустом пуле туннельный трафик пошёл бы напрямую и молча. `REJECT`
совпадает с уже принятым выбором для `BYPASS`.

**Демон понимает обе раскладки профиля.** Профиль ему не принадлежит
([ADR-0002](0002-source-of-truth.md)), и требовать одной формы он не вправе:
селектор с участником `AUTO` → `Select`, иначе прежний `Unfix`.

## Рассмотренные альтернативы

**Подкрутить `url-test`: `lazy: false`, короче `interval`, `exclude-filter`
прямо на группе.** Ноль строк кода в демоне. Отвергнуто: пул остаётся
один. Исключив «РЦ» из группы, владелец теряет возможность запинить их
вручную — а они рабочие, просто для другого.

**Воспроизвести `leastLoad`.** У mihomo нет ни ранжирования по стабильности
RTT, ни пула из `expected`: есть `url-test` (минимум задержки, один
победитель), `fallback` (первый живой) и `load-balance` (размазывание вообще
без учёта задержки). Взято `url-test` над суженным пулом — эмуляция духа, а
не копия. `load-balance` со `sticky-sessions` отвергнут: один медленный
сервер в пуле ловил бы свою долю трафика постоянно.

**`filter: "⚡"` по маркеру в имени.** Даёт 15 узлов — те же 12 провайдера
плюс три одноклассника, и одним символом отсекает Альфу, «РЦ», GAMING,
торренты и SS-узлы. Отвергнуто как режим: это догадка о чужом соглашении об
именовании, которое провайдер вправе сменить молча. Режим `provider` даёт то
же самое, опираясь на данные, а не на привычку.

**Своя группа в `nikki-proxy-groups`.** Отвергнуто: см. выше — «Вернуть
профилю» убрала бы `AUTO`, на которую ссылается `PROXY`, и движок перестал
бы стартовать вовсе. Аварийный выход из README сломался бы ради удобства
записи.

**Отдельный файл состояния.** Отвергнуто: nikki склеивает ровно один
`MIXIN_FILE_PATH`, второй файл до движка не доехал бы.

## Следствия

**У `Selector` нет поля `fixed`** (проверено на живом движке,
`raw/95-autopool-spike.txt`). Признак «закреплено руками» выводится из того,
на что группа указывает: `now != "AUTO"`. Заодно `selected` перестаёт быть
словом «AUTO» — владельцу нужен узел, через который работает авто.

**Файл пишется двумя перьями.** Оба `PUT` переносят чужую секцию из
прочитанного: без переноса «Применить» на вкладке наборов стёрло бы выбор
узлов молча. Отпечатки при этом раздельные — решения независимы, и правка
одного не должна отбивать чужую запись другого.

**Флаг склейки решается по всему файлу**, а не по политике наборов:
«правила из профиля» — это про правила, а не про узлы.

**Конвертер запоминает состав балансировщика.** Раньше `routing.balancers`
читался только на «непусто ли». Теперь у записи `KindAuto` есть `Pool` —
имена узлов, сопоставленные по отпечатку outbound (протокол, сеть, адрес,
порт, секрет), а не по разбору тега `proxy-31-56-150-7-direct`: тег это
чужое соглашение об именовании.

**Режим `provider` перезапускает движок после обновления подписки** — но
только когда состав действительно изменился. Перестановка имён изменением
не считается: порядок участников группы решает mihomo.

**Профиль правится руками один раз.** Демон его не пишет, и до этой правки
новая раскладка не появится. Старая при этом работает как работала.
