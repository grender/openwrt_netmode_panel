# ADR-0011: Оптимистичная блокировка `wireless` по отпечатку

## Статус
Принято — 2026-08-02

> **Сверка с кодом — 2026-08-03.** Решение в силе; ADR задним числом не
> переписывается. Но текст ниже местами описывает как существующее то, чего
> в коде нет. Расхождения правятся кодом, а не этим файлом:
>
> - **Мьютекса на пути записи нет.** Утверждение «запись в `wireless` сериализуется тем же мьютексом, что и джобы» неверно: `internal/httpapi/wifiwrite.go` не берёт ни одной блокировки. TOCTOU между проверкой отпечатка в `openWrite` и `uci commit` в `commitAndRespond` не закрыт ничем, кроме самого отпечатка.
> - Отсутствие `If-Match` даёт **`409 fingerprint_required`**, а не `400 bad_request`.
> - Поле `details` в ответах не существует: демон отдаёт `{code, error}`. Список чужих правок наружу не уходит.
> - Между `uci changes` и первым `uci set` код делает ещё `uci show wireless` и `ubus call network.wireless status` (разрешение радио, ADR-0019). «Одна последовательность без пауз» верна только для отрезка `set` → `commit`.

## Контекст

`/etc/config/wireless` — общий файл ([ADR-0003](0003-saved-networks-in-wireless.md)).
Его редактируют панель, LuCI и ssh. Два сценария порчи:

1. **Потеря чужой правки.** Панель показала список сетей, пользователь пошёл
   пить чай, за это время сеть удалили в LuCI, потом он нажал «сохранить» —
   запись идёт по устаревшему представлению.
2. **Публикация чужого черновика.** LuCI держит незакоммиченные изменения в
   стейджинге UCI. Наш `uci commit wireless` закоммитит **их вместе с
   нашими** — то есть применит чужую недоделанную правку от нашего имени.

Блокировка файла (`flock`) не помогает: LuCI её не берёт, а держать её между
HTTP-запросами нельзя.

## Решение

Две независимые проверки перед каждой записью в `wireless`.

### 1. Отпечаток (защита от устаревшего представления)

```
fingerprint = "sha256:" + первые 16 hex-символов sha256(вывод `uci show wireless`)
```

Считается по сырым байтам вывода. Порядок вывода `uci show` стабилен для
данного файла, поэтому одинаковая конфигурация даёт одинаковый отпечаток.

- `GET /api/wifi/networks` отдаёт его в теле (`fingerprint`) и в заголовке
  `ETag`.
- `POST` и `DELETE /api/wifi/networks` **обязаны** прислать
  `If-Match: "sha256:…"`. Нет заголовка → `400 bad_request`. Не совпал →
  `409 fingerprint_mismatch`, запись не выполняется.
- `/api/status` отдаёт то же значение в `wireless_fingerprint`, чтобы панель
  при опросе 1 Гц замечала чужую правку без второго запроса.

### 2. Чужой стейджинг (защита от публикации черновика)

Перед записью — `uci changes wireless`. Непусто → `409 foreign_staged_changes`
со списком строк в `details`. Мы **не коммитим** и **не откатываем** чужое:
`uci revert` уничтожил бы чужую работу так же необратимо, как коммит её
опубликовал бы. Поэтому глагола `revert` нет и в `Executor`
([ADR-0015](0015-executor-shape.md)).

Собственная запись выполняется одной последовательностью без пауз:
`uci changes` (пусто) → `uci set …` → `uci commit wireless` → перечитать и
вернуть новый отпечаток. Между `set` и `commit` не делается ни одного
внешнего вызова.

Внутри демона запись в `wireless` сериализуется тем же мьютексом, что и джобы
([ADR-0013](0013-fast-vs-slow.md)), — параллельных писателей у нас нет.

## Последствия

**Приобретаем**

- Обе гонки закрыты без блокировок и без демона-владельца файла.
- Отпечаток считается на данных, которые мы и так читаем для `/api/status` —
  дополнительной цены нет.
- `409 fingerprint_mismatch` воспроизводится в тесте за две строки: подсунуть
  другую фикстуру `uci show`.

**Платим**

- Отпечаток меняется от **любой** правки `wireless`, включая чужую и
  безразличную нам (например, смену канала `radio1`). Пользователь получит
  `409` и вынужден будет обновить список, хотя его сеть никто не трогал. Это
  цена дешёвой проверки: посекционных отпечатков не будет.
- Клиент обязан уметь обрабатывать `409` и перечитывать — без этого панель
  выглядит сломанной.
- `uci changes` — ещё один процесс на каждую запись. На записи это неважно
  (записи редки); в `/api/status` он не вызывается.
- Отпечаток вычисляется по выводу, включающему `key` сохранённых сетей.
  Значение необратимо (sha256, 16 hex наружу), но оно косвенно подтверждает
  факт изменения пароля. Приемлемо: доступ к API уже равен доступу к роутеру.

## Рассмотренные альтернативы

| Вариант | За | Против | Почему не он |
|---|---|---|---|
| Без проверок, «последний победил» | Проще всего | Молчаливая потеря правок и публикация чужого черновика | Порча данных |
| `mtime`/размер файла вместо хеша | Дёшево, без чтения содержимого | Секундная гранулярность `mtime`; `uci commit` может не менять размер | Ненадёжно ровно в интересном случае |
| Отпечаток на секцию, а не на файл | Меньше ложных `409` | Не ловит удаление и добавление секций; сложнее и не закрывает основной сценарий | Точность не окупает сложности |
| `flock` на `/etc/config/wireless` | Знакомый механизм | LuCI её не берёт; блокировка между HTTP-запросами требует состояния сессии | Не работает против главного участника |
| `uci revert` чужого стейджинга перед записью | Всегда чистое поле | Необратимо уничтожает чужую незавершённую работу | Хуже, чем отказать |
| Отпечаток в теле запроса вместо `If-Match` | Не нужен заголовок | `DELETE` с телом поддержан не всеми клиентами; два разных места для одного понятия | `If-Match` единообразен и стандартен |
