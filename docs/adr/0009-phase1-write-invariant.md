# ADR-0009: Инвариант записи фазы 1

## Статус
Принято — 2026-08-02. Несущее решение всей поставки.

> **Сверка с кодом — 2026-08-03.** Решение в силе; ADR задним числом не
> переписывается. Но текст ниже местами описывает как существующее то, чего
> в коде нет. Расхождения правятся кодом, а не этим файлом:
>
> - `scripts/check-disabled-write.sh` **написан** и стоит в `make checks`. Пометка «ещё не написан» ниже устарела.
> - Скрипт сканирует `internal/wireless internal/manager internal/httpapi`, а единственная запись `disabled` живёт в `internal/httpapi/wifiwrite.go` — то есть в каталоге, которого текст ниже не называет.

## Контекст

Единственный способ потерять доступ к роутеру через эту панель — изменить то,
что делает `radio0` (станция, upstream). Автоматического отката нет
([ADR-0006](0006-no-rollback.md)), поэтому фаза 1 должна быть устроена так,
чтобы **потерять связь было физически нечем**.

Заодно это снимает вопрос, поднятый разведкой: `radio0` и `radio1` — диапазоны
одной `phy0` (одинаковый `path` в `raw/10-uci-show-wireless.txt`, в
`/sys/class/ieee80211/` только `phy0`). Домен перезагрузки общий: применение
конфигурации передёргивает phy целиком и может уронить домашнюю точку доступа
`grenderNet`. Насколько узким может быть применение — открытый вопрос RQ-03.

## Решение

> **Демон может создавать, изменять и удалять только те секции `wifi-iface`,
> у которых `disabled` истинен, и никогда не пишет значение `disabled`.**

Единственное уточнение, без которого «создавать» неисполнимо: **при создании
новой секции демон пишет `disabled='1'` — и только это значение, и только в
той же партии UCI-команд, что создаёт секцию.** Причина не в удобстве:
отсутствие `disabled` означает «включено» ([ADR-0004](0004-selection-derived.md)),
поэтому создать секцию, не написав `disabled`, — значит создать **включённую**
станционную секцию, то есть ровно то, что инвариант запрещает. Ни при каком
другом действии `disabled` не пишется, не удаляется и не меняется.

Что из этого следует по действиям:

| Действие | Фаза 1 | Почему |
|---|---|---|
| Создать сохранённую сеть | **можно**, всегда с `disabled='1'` | выключенная от рождения секция не влияет на radio0 |
| Изменить выключенную сеть (ssid, key, encryption) | **можно** | netifd её не поднимает |
| Удалить выключенную сеть | **можно** | то же |
| Изменить **включённую** сеть | **нельзя**, `409 enabled_network_readonly` | смена пароля активной сети рвёт ассоциацию при ближайшем применении |
| Удалить **включённую** сеть | **нельзя**, `409 enabled_network_readonly` | то же |
| Тронуть `disabled` существующей секции | **нельзя** | это и есть смена upstream — фаза 2 |
| Тронуть `radio1` / `wifinet1` (`grenderNet`) | **нельзя** | не наше ([ADR-0003](0003-saved-networks-in-wireless.md)) |
| Тронуть `wifi-device` (канал, страна, htmode) | **нельзя** | не наше |

**Из инварианта следует, что применения нет.** Раз ни одна запись не может
изменить поведение radio0, то для записей в `wireless` в фазе 1:

- нет джоба,
- нет LED,
- нет подтверждения,
- нет `wifi reload`, `wifi up`, `ubus network.reload` — **ничего**;
- достаточно `uci commit wireless`.

Запись — быстрая операция ([ADR-0013](0013-fast-vs-slow.md)): `uci set` +
`uci commit`, десятки миллисекунд, синхронный ответ `200`.

Побочный эффект, который надо принять честно: закоммиченная, но не
применённая правка **уедет в живую систему при следующем применении, кем бы
оно ни было вызвано** — нашей сменой режима, LuCI Save&Apply или
перезагрузкой. Для выключенной секции это безвредно по построению.

Механический гейт `scripts/check-disabled-write.sh` (ещё не написан): в
`internal/wireless` и `internal/manager` строка `"disabled"` может
встречаться в аргументе записи ровно в одном месте — на пути создания
секции, со значением `"1"`.

## Последствия

**Приобретаем**

- Фаза 1 не может разорвать связь. Это доказуемо, а не «маловероятно».
- RQ-03 (насколько узко можно применять) и RQ-04 (рвёт ли скан ассоциацию)
  перестают быть блокерами первой поставки.
- Домашняя точка `grenderNet` не моргает: мы не вызываем применения вообще.
- Тесты на запись не нуждаются в роутере — проверяется только содержимое
  `/etc/config/wireless`.

**Платим**

- **Пароль активной сети через панель не поменять.** Владелец увидит `409`
  на самом естественном действии. UI обязан объяснить это заранее, а не
  ошибкой после нажатия.
- Панель фазы 1 умеет только *готовить* сети. Переключение — через LuCI или
  ssh, пока не приедет фаза 2.
- Есть окно рассинхрона: `uci commit` без применения означает, что
  `/etc/config/wireless` и живая конфигурация расходятся. Показываем это
  полем `pending_apply` (из `network.wireless status`, `pending`) и
  расхождением `configured_ssid` / `associated_ssid`.

## Рассмотренные альтернативы

| Вариант | За | Против | Почему не он |
|---|---|---|---|
| Разрешить правку включённой сети + `wifi reload` | Естественный UX: смена пароля работает | Требует джоба, LED, подтверждения и отката; передёргивает всю phy0, роняя `grenderNet` (RQ-03 не отвечён) | Ровно тот риск, ради устранения которого сделана фаза 1 |
| Разрешить правку включённой сети без применения | Нет джоба, нет риска сейчас | Мина замедленного действия: правка уедет в систему при чужом применении через час, и связь пропадёт без видимой причины | Отложенный разрыв хуже немедленного |
| Не создавать секции вовсе, только читать | Инвариант формулируется совсем без исключений | `POST` и `DELETE /api/wifi/networks` теряют смысл; панель фазы 1 не делает ничего полезного с сетями | Создание выключенной секции доказуемо безопасно, отказ от него не покупает ничего |
| Копировать `wireless` в песочницу и применять диффом | Точный контроль | Второй экземпляр правды, сложный merge с правками LuCI | Нарушает [ADR-0002](0002-source-of-truth.md) |
