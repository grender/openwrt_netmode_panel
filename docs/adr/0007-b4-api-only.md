# ADR-0007: b4 управляется исключительно через HTTP API

## Статус
Принято — 2026-08-02. **Снимает вопрос SPEC §3.2.**

> **Сверка с кодом — 2026-08-03.** Решение в силе; ADR задним числом не
> переписывается. Но текст ниже местами описывает как существующее то, чего
> в коде нет. Расхождения правятся кодом, а не этим файлом:
>
> - `503 b4_auth_required` **не отдаётся**: клиент не зовёт `GET /api/auth/check` вовсе, а включённая аутентификация деградирует в `ErrUnavailable` → `503 b4_unavailable`. Код зарезервирован, см. `docs/contracts/errors.md`.
> - Ссылка на «пункт 13 чек-листа ревью» висячая: такого документа в репозитории нет. Механического гейта на `PUT /api/sets/{id}` тоже нет: `check-b4json.sh` грепает только литерал `b4.json`, а `check-routes.sh` в `internal/b4` не заглядывает. Запрет держат ревью и тест `TestNeverUsesPutSets`.

## Контекст

SPEC §3 ставил условие: «проверь, переживает ли выбранный сет рестарт b4 —
если API меняет только состояние в памяти, демон обязан продублировать выбор
в `b4.json`». А SPEC §12 добавляла: «`b4.json` — только точечные правки».

Разведка по исходникам ответила (`docs/recon/b4-api.md`):

- `POST /api/sets/batch-set-enabled` вызывает `saveAndPushConfig`, который
  **сначала пишет файл** (`src/http/handler/config.go:439`,
  `newCfg.SaveToFile`) и **только потом** подменяет указатель конфига
  (`:453`);
- изменение применяется горячо через `globalPool.UpdateConfig`
  (`src/http/handler/config.go:402-407`) — рестарт b4 не нужен;
- на роутере 1.74.1, порт 7000, аутентификация выключена
  (`raw/50-b4-api.txt`).

То есть условие «если API меняет только память» не выполнилось. Дублировать
нечего.

## Решение

`/etc/b4/b4.json` **не читается и не пишется никогда**. Проверяется
`scripts/check-b4json.sh` — упоминание имени файла в Go-коде валит сборку.

Используем ровно три поверхности:

| Вызов | Зачем | Источник |
|---|---|---|
| `GET /api/version` | проба живости (единственный маршрут вне аутентификации, в исходниках прямо назван health check, `src/http/auth.go:267-271`) | `raw/50-b4-api.txt` |
| `GET /api/sets` | список сетов, плоский массив, никогда не `null` (`sets.go:270-277`) | `b4-api.md` |
| `POST /api/sets/batch-set-enabled` | включить/выключить N сетов | `b4-api.md` |

**Запрещён `PUT /api/sets/{id}`.** Обработчик декодирует тело в обнулённый
`config.SetConfig` и кладёт его в слот, сохраняя только `id`
(`sets.go:351-368`). Отправить туда `{"enabled": true}` — стереть стратегию
сета целиком. Запасной путь для сборок старее 1.64.0 не пишем: на роутере
1.74.1.

Клиент b4 не делает логина, не хранит токен и не переигрывает запрос на 401.
Если аутентификацию когда-нибудь включат, `GET /api/auth/check` вернёт
`auth_required: true`, и клиент деградирует в `503 b4_auth_required` —
не пытаясь угадать пароль.

## Последствия

**Приобретаем**

- Не участвуем в миграции формата `b4.json` между версиями b4. Он сам
  переносит свой конфиг (`b4.json.v0.bak`); наша запись рано или поздно
  затёрла бы поле, которого мы не знаем.
- Переключение сета не требует рестарта b4 и не разрывает соединения.
- Клиент — три HTTP-вызова на stdlib. Ни парсера JSON-схемы b4, ни блокировок
  файла, ни атомарной записи.

**Платим**

- Мы полностью зависим от того, что b4 жив. Лежит — `/api/b4/*` отдаёт `503`,
  и сделать что-либо в обход нельзя. Это осознанно: обход означал бы правку
  файла, то есть возврат к отменённому варианту.
- Запись в `b4.json` делает сам b4 через `O_TRUNC` без temp+rename
  (`src/config/methods.go:36-45`) — при пропадании питания в момент нашего
  переключения файл может обрезаться. **Не наш файл и не наша ошибка**, но
  наш вызов приводит этот путь в действие. Упомянуто в README проекта.
- Привязаны к версии ≥1.64.0 из-за `batch-set-enabled`. Проверять версию в
  рантайме не будем: на роутере 1.74.1, а деградация «в никуда» хуже
  честного `404` от b4.

## Рассмотренные альтернативы

| Вариант | За | Против | Почему не он |
|---|---|---|---|
| API + дублирование в `b4.json` (SPEC §3.2) | Страховка, если API однажды перестанет писать файл | Страховка от события, которого нет; риск затереть поля неизвестной нам версии; нужен атомарный писатель и знание схемы | Условие спеки не выполнилось — проверено по исходникам |
| Только `b4.json` + `/etc/init.d/b4 reload` | Не нужен HTTP-клиент | Рестарт рвёт соединения там, где API применяет горячо; полная зависимость от схемы файла | Строго хуже по всем осям |
| `PUT /api/sets/{id}` вместо batch | Один вызов вместо двух | Полная замена: стирает стратегию | Прямо запрещено; клиент этот маршрут не знает |
