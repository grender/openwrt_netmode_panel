# ADR-0012: Пароли сетей — только на запись

## Статус
Принято — 2026-08-02

## Контекст

Сохранённая сеть содержит `key` — пароль WiFi
(`raw/10-uci-show-wireless.txt`). Панель должна уметь его задать и заменить.
Соблазн — отдавать его в `GET /api/wifi/networks`, чтобы форма редактирования
открывалась заполненной, «как в LuCI».

Аргумент «файл всё равно 644, пароль и так виден» (`raw/40-etc-config-perms.txt`)
не работает: чтобы прочитать файл, нужен доступ к роутеру, а чтобы прочитать
ответ API — достаточно доступа к панели. Это разные уровни, и смешивать их
не нужно.

## Решение

Пароль **никогда не покидает роутер через наш API**.

| Направление | Поле | Тип | Смысл |
|---|---|---|---|
| Ответ (`GET`) | `has_key` | `bool` | у секции есть непустой `key` |
| Ответ | `key` | — | **поля нет вовсе.** Не `null`, не `"***"` — нет ключа в JSON |
| Запрос (`POST`) | `key` | `string`, необязательное | если поле отсутствует — пароль не меняется; если пришло — записывается как есть |

Правила:

1. Отсутствие `key` в запросе и пустая строка — **разные вещи**. Отсутствие
   означает «не трогать», пустая строка — «записать пустой пароль» (осмысленно
   при `encryption: none`). Поэтому в Go поле — `*string`, а не `string`.
2. `key` не попадает в логи, ни в каком виде, включая тексты ошибок и
   `details`.
3. `key` не отражается в ответе на `POST` — ответ такой же, как у `GET`.
4. Отпечаток (`sha256` от вывода `uci show wireless`,
   [ADR-0011](0011-optimistic-concurrency.md)) считается по данным, включающим
   `key`, но наружу уходят 16 hex-символов — восстановить пароль из них
   невозможно.
5. То же правило для токена API: `/api/status` никогда его не отражает.

## Последствия

**Приобретаем**

- Компрометация панели (XSS в статике, чужая вкладка, забытый на экране
  ноутбук) не даёт паролей от соседских и домашних сетей.
- В логах, дампах и скриншотах панели паролей нет структурно, а не по
  договорённости.
- Фикстуры `docs/api/examples/*.json` можно хранить в репозитории без
  редактирования — там нечего редактировать.

**Платим**

- Форма редактирования сети открывается с пустым полем пароля. Пользователь,
  привыкший к LuCI (где пароль виден), решит, что панель его потеряла. Лечится
  подписью «оставьте пустым, чтобы не менять».
- Проверить «тот ли пароль сохранён» через панель нельзя — только через ssh
  или LuCI.
- `*string` в модели вместо `string`: чуть больше кода и обязательный тест на
  «поле отсутствует» против «поле пустое».

## Рассмотренные альтернативы

| Вариант | За | Против | Почему не он |
|---|---|---|---|
| Отдавать `key` как есть | Форма заполнена, UX как в LuCI | Пароли всех сохранённых сетей утекают в любой ответ API и в кэш браузера | Несоразмерная цена за удобство формы |
| Отдавать маску `"••••"` | Форма выглядит заполненной | Маску можно случайно отправить обратно и записать её как пароль; требует «магического значения», означающего «не менять» | Магические значения ломаются молча; `has_key` честнее |
| Отдавать `key` только по отдельному запросу с подтверждением | Компромисс | Второй эндпоинт, второй путь утечки, реальной потребности нет | Не окупается |
| Хранить пароли в отдельном файле 0600, а в `wireless` — ссылку | Пароли не в 644-файле | netifd не умеет ссылок; сеть просто не поднимется | Технически невозможно |
