# ADR-0001: Слои и направление зависимостей

## Статус
Принято — 2026-08-02

## Контекст

Демон: один статический бинарь ≤10 МБ, только stdlib, один пользователь в LAN,
роутер с 512 МБ. Никакой БД, никакой очереди, никакого второго процесса.

Единственное требование, ради которого вообще нужны границы, — **проверяемость
на ноутбуке без роутера** (SPEC §10). Всё остальное — цена, которую надо
платить осознанно.

Дерево пакетов уже создано: `internal/{model,uci,wireless,executor,b4,nikki,led,job,manager,sched,logs,httpapi}`.
Нужно правило, которое проверяется механически, а не «архитектурным вкусом».

## Решение

Четыре круга. Зависимости идут только внутрь.

| Круг | Пакеты | Что можно | Что запрещено |
|---|---|---|---|
| 1. Чистое ядро | `model`, `uci`, `wireless` | функции «байты → структура», классификация, форматирование | `os/exec`, `net/http`, `os`, любой импорт из кругов 2–4 |
| 2. Порты | `executor`, `b4`, `nikki`, `led` | интерфейс + одна реальная реализация + фейк | импорт `manager`, `httpapi` |
| 3. Политика | `manager`, `job`, `sched`, `logs` | сериализация, один джоб, кэш 500 мс, расписание | прямой `os/exec`, прямой `net/http` |
| 4. Транспорт | `httpapi`, `cmd/netmoded` | роутинг, токен, JSON, сборка графа | бизнес-решения, прямой вызов `Executor` |

Дополнительные правила:

- `httpapi` **не вызывает `Executor` напрямую** — только `manager`. Обход
  считается архитектурным запахом; если он где-то нужен, это документируется
  в самом файле, а не делается молча.
- Всё, что парсит вывод роутера, живёт в круге 1 и тестируется на записанных
  фикстурах `docs/recon/raw/` (см. [ADR-0015](0015-executor-shape.md)).
- `cmd/netmoded` только строит граф и запускает `http.Server`. Логики нет.

Проверяется `scripts/check-layering.sh` (ещё не написан): `go list -deps` на
каждый пакет круга 1 не должен содержать `os/exec`, `net/http` и пакетов
`netmoded/internal/{executor,b4,nikki,led,manager,httpapi}`.

## Последствия

**Приобретаем**

- Парсер `uci show`, классификатор выбора и парсер скана тестируются без
  роутера, без моков и без сети — обычный `[]byte` на входе.
- Полный список того, что демон вообще умеет делать с системой, — это
  интерфейс `Executor` на одном экране.

**Платим**

- От хендлера до системного вызова два прыжка вместо одного. Для девяти
  эндпоинтов это заметная доля скучного кода.
- Каждое новое системное действие требует правки интерфейса **и** фейка —
  добавить `exec.Command` по месту нельзя.
- Круг 1 не может логировать через общий логгер (он в круге 3) — возвращает
  ошибки, а не пишет их.

## Рассмотренные альтернативы

| Вариант | За | Против | Почему не он |
|---|---|---|---|
| Один пакет `main` | Минимум кода, минимум церемонии | Парсеры не тестируются иначе как через живой роутер; невозможно проверить `Ambiguous` без второй сети под рукой | Убивает единственную реальную цель — тесты на ноуте |
| Три слоя как в спеке (конфиг / скрипт / демон) | Совпадает со SPEC §4 | Это слои *развёртывания*, а не пакетов; ничего не говорит о том, кто кого импортирует внутри демона | Оставлен как описание системы, но не как правило для кода |
| Transport → Service → Repository | Знакомо | Слой репозиториев осмыслен при БД. У нас источник правды — UCI и живые API, «репозиторий» выродится в переименованный `Executor` | Лишний слой без выигрыша |
