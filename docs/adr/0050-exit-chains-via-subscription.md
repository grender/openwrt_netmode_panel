# ADR-0050: Цепочки до своих нод через узлы подписки — пул хопов и провайдер `exits`

## Статус

Принято 2026-11-14. Дополняет [ADR-0049](0049-exit-groups-as-set-targets.md):
выполняет его «Что дальше» (цепочка через платный узел), но не так, как там
было набросано — `dialer-proxy: AUTO` отвергнут, см. ниже. Дополняет
[ADR-0044](0044-autopool.md): у `mixin.yaml` третья секция. Уточняет
[ADR-0002](0002-source-of-truth.md): узлы своих нод теперь пишет демон — в
файл провайдера, как узлы подписки, а не в профиль. Разведка —
[`docs/recon/exit-chains.md`](../recon/exit-chains.md).

## Контекст

Своя выходная нода (`kz-nqz-exit-01`, VLESS + Reality, выходы `resi` и
`dc`) работает, пока на неё пускают напрямую. Прямой вход могут закрыть —
тогда до неё нужно ходить через платный узел подписки: роутер → узел
подписки → своя нода → выход. Ноды до этого решения владелец вписывал в
профиль руками (yq по `docs/exit-nodes.md`), и вписать туда ещё N
цепочек на каждую ноду значило бы держать руками то, что меняется с каждым
обновлением подписки.

Разведка на VM (mihomo 1.19.27) дала четыре факта, на которых всё стоит:

1. **Vision + Reality через `dialer-proxy` работает** на vision- и
   hysteria2-хопах — второй inbound без flow на ноде не нужен.
2. **Хопы ss и ws провайдера подменяют адрес назначения по SNI** — Reality
   через них падает (`REALITY authentication failed`), а сами хопы при этом
   живы. Значит, здоровье надо мерить **по всей цепочке до ноды**: `url-test`
   над хопом выбрал бы живой хоп, через который цепочка мертва.
3. **`dialer-proxy` разрешается только в узел или группу верхнего уровня.**
   Узел провайдера по имени он не находит: из узла верхнего уровня — nikki
   не стартует, из узла провайдера — отказ на каждом соединении. `mihomo -t`
   не ловит ни то, ни другое.
4. **Sniffer живого роутера** (`overwrite_destination=1`,
   [nikki-sniffer.md](../recon/nikki-sniffer.md)) переписывает адрес
   Reality-соединений клиентов LAN на сайт маскировки — прямой вход на свою
   ноду с телефона дома не работает. Соединений самого mihomo роутера это не
   касается.

## Решение

### Раскладка

- **Демон пишет файл провайдера `exits`** (`/etc/nikki/run/providers/exits.yaml`,
  0600, `internal/exits`): на каждую ноду и выход — прямой узел
  `<нода>-<выход>` и цепочка `<нода>-<выход> ⇢ <хоп>` на каждый хоп пула,
  с `dialer-proxy: nm-hop-<hash>`. Источник — экспорты нод в
  `/etc/netmoded/exits/<нода>.json` (контракт `schema: 1` с репо выходных
  нод; кладёт `scripts/exits-push.sh`).
- **Демон пишет в миксин группы-однохопники** `nm-hop-<hash>` в
  `nikki-proxy-groups` (`select`, `use: [sub]`, `filter: ^<имя>$`) — по одной
  на хоп. Они и дают цепочкам ссылку верхнего уровня (факт 3).
- **Профиль владельца ссылается только на провайдер:** `EXIT-DC-HOP` =
  `url-test`, `use: [exits]`, фильтр по цепочкам выхода — он и меряет
  здоровье по всей цепочке (факт 2); `EXIT-DC` = `select` [прямо,
  `EXIT-DC-HOP`, `REJECT`]. Выбор «прямо / через хоп / закрыть» — ручной,
  по решению владельца.

Pool — один список на оба файла: и группы, и цепочки строятся из него, иначе
цепочка сослалась бы на группу, которой нет.

### Пул хопов — как авто-пул, но умолчание — ноль

Режимы те же (`deny`/`allow`/`provider`), состав считает демон по манифесту
подписки в её порядке и пересчитывает после каждого обновления подписки.
Умолчание — **ноль хопов** (`off`), а не весь список: каждая цепочка — своя
проверка здоровья через выход, у `resi` — через ISP-прокси, который на
частых новых соединениях отказывает (разведка). Потолок — 8 хопов.

### Имя группы — от имени хопа

`nm-hop-` + 8 hex от sha256 имени, а не номер в пуле. Миксин применяется
перезапуском движка, провайдер — перечиткой; между ними файлы могут жить в
разных версиях, и позиционное имя увело бы цепочку через чужой хоп. С
именем от хопа ссылка либо попадает в свой хоп, либо не находит группу — и
mihomo отказывает, а не выпускает другим путём.

### Sniffer — `skip-domain` с SNI своих нод

В миксин пишется `sniffer.skip-domain` с SNI своих нод (факт 4). По SNI, а
не по IP (`skip-dst-address`): адрес ноды не нужно резолвить на роутере, и
пересборка ноды на новом IP ничего не ломает. ucode nikki пишет
`skip-domain` только при `sniffer_ignore_domain_name=1` — на роутере он `0`;
если владелец его включит, его список затрёт наш, и это надо видеть в
панели.

## Рассмотренные альтернативы

**`dialer-proxy: AUTO` (ADR-0049, «что дальше»).** Хоп — лучший узел
авто-пула. Отвергнуто фактом 2: `AUTO` меряет хоп, а не цепочку, и выбрал бы
ss-узел. Плюс пул обхода и пул хопов — разные решения (хопы ближе к стране
ноды, без ss/ws).

**Одна группа `HOP` + один узел `-via-hop`.** Проверено на VM — работает, но
здоровье опять по хопу. Отвергнуто тем же фактом 2.

**Узлы цепочек и хопов — в `nikki-proxies` миксина.** Тогда `dialer-proxy`
ссылался бы на узел верхнего уровня без групп. Отвергнуто: секреты своих
нод оказались бы в файле, который демон отдаёт панели (довод ADR-0049), а
выключенная склейка унесла бы узлы, на которые ссылается профиль, — nikki не
поднялся бы.

**Цепочки руками в профиле.** Отвергнуто: N×M узлов, меняющихся с каждым
обновлением подписки, и вторая копия для подписки телефонов.

## Цена

- **Профиль правится руками один раз** под новую раскладку
  (`docs/exit-nodes.md`); прежняя ручная (узлы в `proxies:`) продолжает
  работать, но цепочек в ней нет.
- **Окно после перезапуска.** До первого замера `url-test` стоит на первом
  участнике, и тот может быть мёртв — несколько секунд отказов. Цена
  перезапуска движка, как у любой записи миксина.
- **Пустой пул** даёт `EXIT-*-HOP` без участников — mihomo подставляет
  `COMPATIBLE`, движок жив (проверено на VM).
- **resi медленный** (2–5 с на новое соединение) — в него только
  AI-сервисы; это свойство прокси, а не цепочки.
- `mihomo -t` сломанную раскладку не ловит, поэтому демон после перезапуска
  сверяет у движка, что группы `nm-hop-*` есть, и иначе проваливает джоб.

## Подписка для телефонов

`GET /sub/happ/<токен>` (`internal/happsub`) — JSON-массив конфигов Xray, как у
провайдера: «Умный · прямо», «Умный ⇢ хоп» и по ноде и выходу — прямо и через
каждый хоп пула. Свой токен в пути (`/etc/netmoded/sub-token`, `POST
/api/sub/rotate`), мимо токена панели ровно один шаблон, неверный — пустой
`404`; демон слушает только LAN. Хопы и туннель — исходные outbounds
провайдера (`/etc/netmoded/outbounds.json`, пишет обновление подписки), а не
обратный перевод из mihomo.

Что выяснено на телефоне и Xray 26.10.21 и вошло в сборку:

- `dialerProxy` на балансировщик молча не работает — запись «через хоп» по
  одной на хоп, а «Умный» держит балансировщики над целыми цепочками;
- `domainStrategy: AsIs`, DoH отдельным первым правилом через туннель или
  напрямую — не через выход (иначе каждый DNS-запрос шёл через resi);
- observatory с `enableConcurrency: true`: без этого Xray пробует по одному
  outbound с паузой `probeInterval` между каждым, и балансировщики минутами
  пусты (`fallback to [block]`);
- **туннель «Умного» — узлы авто-пула**, а не хопы: хоп `🇷🇺💳Россия`
  годится до своей ноды, но YouTube через него не открывается;
- `EXIT-<X>` из наборов → выход «x» всех нод; такого выхода нет — `block`.

На VM, сквозь подписку демона: «Умный ⇢ хоп» — ya.ru напрямую, YouTube через
авто-пул, Telegram и Instagram через цепочку dc, ipinfo.io через resi; все
записи проходят `xray run -test`. На телефоне ещё не проверено: VM телефону
недоступна, нужен живой роутер.
