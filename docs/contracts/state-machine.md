# Контракт: состояние выбора upstream (`Selection`)

Какая сеть выбрана — **вычисляемая величина**, она нигде не хранится
([ADR-0004](../adr/0004-selection-derived.md)). Этот документ фиксирует, как
она вычисляется, что демон отдаёт в каждом состоянии и где запись запрещена.

## Что считается нашей секцией

Секция `wifi-iface` из `/etc/config/wireless` — наша, если выполнены **оба**
условия:

```
device = <станционное радио>   и   mode = sta
```

**`<станционное радио>` — не литерал.** Какое радио работает станцией,
выводится из системы за каждую единицу работы (`wireless.ResolveRadios`,
[ADR-0019](../adr/0019-radio-role-derived.md)); `wireless.Classify` принимает
его вторым аргументом. Не вывелось — пути записи отказывают
`503 radio_unknown`, а `/api/status` гасит поля и остаётся `200`.

На снимке разведки станция — `radio0`, домашняя точка — `radio1`
(`raw/10-uci-show-wireless.txt`). Это **факт снимка**: `radio0` и `radio1` —
два диапазона одной `phy0`, и их индексы задаёт порядок регистрации
драйвером. Литерал `radio0` в `internal/` и `cmd/` валит сборку
(`scripts/check-no-hardcoded-if.sh`).

Всё прочее вне модели: `wifinet1` (`grenderNet`, `mode=ap`) — домашняя точка
доступа, мы её не показываем и не трогаем.

## Признак включённости

| Значение `disabled` | Секция |
|---|---|
| опции нет | **включена** — подтверждено живым примером: у `wifinet0` опции нет, и именно она в ассоциации |
| `'0'` | включена |
| `'1'` | выключена |
| любое другое | **не распознано** → весь набор становится `Ambiguous` |

Нераспознанное значение не «трактуется по-своему» и не исправляется: мы не
знаем, как его прочтёт netifd, поэтому не имеем права угадывать
([ADR-0010](../adr/0010-never-auto-repair.md)).

## Сумма состояний

```go
// internal/wireless
type State string

const (
	Empty       State = "empty"        // наших секций нет вовсе
	AllDisabled State = "all_disabled" // есть, все выключены
	Single      State = "single"       // ровно одна включена
	Ambiguous   State = "ambiguous"    // ≥2 включены ИЛИ нераспознанный disabled
)

type Selection struct {
	State    State
	Active   string   // id секции при Single, иначе ""
	Sections []string // id всех наших секций, в порядке файла
	Conflict []string // при Ambiguous — id, вызвавшие конфликт
	Reason   string   // почему Ambiguous; наружу не отдаётся
}
```

Наружу из этой структуры уходят `State` (как `selection_state`), `Active`
(как `configured_ssid` после разыменования секции) и `Conflict` (как
`conflict` в `/api/status`, только при `Ambiguous`). `Reason` остаётся
внутренним.

### `Empty` — станционных секций нет

| | |
|---|---|
| Когда | ни одной `wifi-iface` с `device=<станционное радио>`, `mode=sta` |
| HTTP `/api/status` | **200** |
| `selection_state` | `"empty"` |
| `configured_ssid` | `null` |
| `associated_ssid` | `null` (ассоциации быть не может) |
| Запись | **разрешена** — создание сети |
| Панель | «Сохранённых сетей нет». Кнопка «Добавить сеть» — главное действие |

**Это нормальное состояние.** Свежая установка выглядит ровно так. Отдавать
на неё `500` или создавать что-то самостоятельно — объявить нормальную жизнь
роутера сбоем.

### `AllDisabled` — есть сети, ни одна не выбрана

| | |
|---|---|
| Когда | ≥1 наша секция, у всех `disabled` истинен |
| HTTP `/api/status` | **200** |
| `selection_state` | `"all_disabled"` |
| `configured_ssid` | `null` |
| `associated_ssid` | `null` |
| Запись | **разрешена** — все секции выключены, значит все редактируемы |
| Панель | «Ни одна сеть не выбрана». Список сетей активен; переключение — в фазе 2 (`501`) |

Тоже нормальное состояние: пользователь отключил сеть в LuCI и не выбрал
новую. Upstream при этом отсутствует, `online.ok` будет `false`.

### `Single` — рабочее состояние

| | |
|---|---|
| Когда | ровно одна наша секция включена |
| HTTP `/api/status` | 200 |
| `selection_state` | `"single"` |
| `configured_ssid` | `ssid` включённой секции |
| `associated_ssid` | из живой системы, может отличаться — см. ниже |
| Запись | **разрешена, кроме включённой секции**: её правка и удаление → `409 enabled_network_readonly` |
| Панель | обычный вид; у активной сети замок вместо кнопки «изменить» |

Состояние снимка разведки: `wifinet0` (`John24`) включена, `wifinet2`
(`ATOM`) сохранена с `disabled='1'`.

### `Ambiguous` — включено больше одной, либо непонятный `disabled`

| | |
|---|---|
| Когда | ≥2 наших секций включены **или** хотя бы у одной `disabled` не распознан |
| HTTP `/api/status` | **200** — состояние докладывается, а не прячется |
| `selection_state` | `"ambiguous"` |
| `configured_ssid` | `null` — «какая настроена» не определено, а угадывать запрещено |
| `associated_ssid` | заполняется, если ассоциация есть: физическая правда доступна и в этом состоянии |
| Запись | **запрещена вся**, включая правку выключенных секций → `409 ambiguous_selection` |
| Панель | предупреждающий баннер, список конфликтующих секций, ссылка на LuCI. Все кнопки изменения неактивны |

Запись запрещена **целиком**, а не только для включённых секций. Причина:
в непонятном состоянии мы не можем доказать, что правка безвредна — например,
неизвестно, какие из секций netifd поднимет.

**`Ambiguous` не чинится никогда**, даже если очевидно, какая секция лишняя.
Выход — только через LuCI или ssh. Кнопки «исправить» нет: она и есть
автопочинка ([ADR-0010](../adr/0010-never-auto-repair.md)).

## Сводная таблица

| Состояние | HTTP | `configured_ssid` | Запись в `wireless` | Код отказа |
|---|---|---|---|---|
| `empty` | 200 | `null` | да | — |
| `all_disabled` | 200 | `null` | да | — |
| `single` | 200 | ssid | да, кроме включённой секции | `409 enabled_network_readonly` |
| `ambiguous` | 200 | `null` | **нет** | `409 ambiguous_selection` |

## `configured_ssid` и `associated_ssid` не сливаются

Два поля с разными источниками. Совпадение — не повод объединить их в одно,
а **расхождение — самый полезный сигнал в панели**.

| Поле | Источник | Означает |
|---|---|---|
| `configured_ssid` | `uci show wireless`, включённая секция | что **настроено**: наше намерение |
| `associated_ssid` | `ubus call iwinfo info` по `ifname` станции | к чему радио **реально подключено** |

| Комбинация | Что произошло | Реакция |
|---|---|---|
| оба равны | нормальная работа | ничего |
| `configured` есть, `associated` = `null` | сеть не поднялась: нет в эфире, неверный пароль, слабый сигнал | панель показывает «не подключено», причина — в `logread` |
| `configured` ≠ `associated` | конфиг изменили, но не применили; либо применяется прямо сейчас | панель показывает обе; вместе с `pending_apply` даёт полную картину |
| `configured` = `null` (`empty`/`all_disabled`), `associated` есть | ассоциация осталась от прежней конфигурации, применения не было | то же |
| `configured` = `null` (`ambiguous`), `associated` есть | конфликт в конфиге, радио работает по прежнему применённому состоянию | баннер + фактический ssid |

Ни при какой комбинации демон не пытается «привести в соответствие».

`pending_apply` берётся из `network.wireless status` → `<radio>.pending`
(`raw/21-ubus-network-wireless-status.json`) и означает: конфигурация
изменена, но ещё не применена к радио. В фазе 1 наши записи применения не
вызывают ([ADR-0009](../adr/0009-phase1-write-invariant.md)), поэтому
`pending_apply: true` после нашей записи — ожидаемое, штатное состояние.

`associated_ssid` берётся из `iwinfo info` → `ssid` и заполняется только при
`associated`. Форма подтверждена фикстурой `raw/24-ubus-iwinfo-info.json`
(`ssid: "John24"` совпадает с включённой секцией `wifinet0`), разбирается
`wireless.ParseInfo`. `null` означает «ассоциации нет» либо «имя станционного
интерфейса не выведено», а не «не реализовано».

## Переходы

Демон не вызывает переходов сам. Все они — следствие чужих действий:

```
Empty ──создать сеть (наш POST)──────────────► AllDisabled
AllDisabled ──включить секцию (LuCI/ssh)─────► Single
Single ──выключить секцию (LuCI/ssh)─────────► AllDisabled
Single ──включить вторую (LuCI/ssh)──────────► Ambiguous
Ambiguous ──выключить лишнюю (LuCI/ssh)──────► Single
любое ──удалить все секции (LuCI/ssh)────────► Empty
любое ──непонятное значение disabled─────────► Ambiguous
```

Переходов, инициированных демоном, в фазе 1 ровно один: `Empty → AllDisabled`
при создании первой сети. Все переходы, меняющие `disabled`, — фаза 2
([ADR-0016](../adr/0016-upstream-deferred.md)).

## Проверяется тестами

Четыре фикстуры `uci show wireless` (по одной на состояние) плюс:

- секция с `disabled='maybe'` → `ambiguous`, а не «выключена»;
- секция без `disabled` → включена (регрессия на главный факт разведки);
- `mode=ap` на станционном радио — не наша, в классификации не участвует;
- радио переставлены местами в фикстуре — код идёт за `mode=sta`, а не за индексом;
- безымянная секция → участвует в классификации, `id: null`, `editable: false`;
- `Ambiguous` + `POST /api/wifi/networks` → `409`, файл не изменён.
