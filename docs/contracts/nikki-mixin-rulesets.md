# Контракт: `/etc/nikki/mixin.yaml` — наборы geosite

Файл, в котором живёт выбор наборов доменов. **Пишет его демон, целиком;
читают — nikki при старте службы и демон при ответе панели.** Второго
хранилища выбора нет: ни секций UCI, ни своего JSON
([ADR-0039](../adr/0039-geosite-rulesets-mixin-file.md)).

Путь зашит константой `mixinPath` (`internal/httpapi/server.go`) и
переопределяется только полем `Config.MixinPath` — им пользуются тесты и
дев-стенд. Каталог `/etc/nikki` демон **не создаёт**: если его нет, nikki на
роутере не разворачивался, и создавать конфигурацию за чужой пакет мы не
станем.

Формат порождается пакетом `internal/rulesets` (`Render`), читается им же
(`Parse`); golden-фикстуры — `internal/rulesets/testdata/*.yaml`.

## Файл целиком

```yaml
# netmoded: файл пишет панель (раздел «Узлы Nikki» → «Что в туннель · наборы»).
# Не правьте руками — при следующем применении он переписывается целиком.
# netmoded-rulesets: policy=only download=direct sets=youtube,telegram+ip rules=suffix:worldsimseries.com>tunnel|%D0%9B%D0%B8%D0%B3%D0%B0+WSS;cidr:100.64.0.0/10>direct
rule-providers:
  nm-geosite-youtube:
    type: http
    behavior: domain
    format: mrs
    url: https://raw.githubusercontent.com/MetaCubeX/meta-rules-dat/meta/geo/geosite/youtube.mrs
    path: ./rules/nm-geosite-youtube.mrs
    interval: 86400
  nm-geosite-telegram:
    type: http
    behavior: domain
    format: mrs
    url: https://raw.githubusercontent.com/MetaCubeX/meta-rules-dat/meta/geo/geosite/telegram.mrs
    path: ./rules/nm-geosite-telegram.mrs
    interval: 86400
  nm-geoip-telegram:
    type: http
    behavior: ipcidr
    format: mrs
    url: https://raw.githubusercontent.com/MetaCubeX/meta-rules-dat/meta/geo/geoip/telegram.mrs
    path: ./rules/nm-geoip-telegram.mrs
    interval: 86400
nikki-rules:
  # Лига WSS
  - 'DOMAIN-SUFFIX,worldsimseries.com,BYPASS'
  - 'IP-CIDR,100.64.0.0/10,DIRECT,no-resolve'
  - 'RULE-SET,nm-geosite-youtube,BYPASS'
  - 'RULE-SET,nm-geosite-telegram,BYPASS'
  - 'RULE-SET,nm-geoip-telegram,BYPASS,no-resolve'
  - 'GEOIP,PRIVATE,DIRECT,no-resolve'
  - 'MATCH,DIRECT'
```

Запись атомарная: временный файл, `fsync`, `rename`
(`internal/atomicfile`). Права `0644` — секретов в файле нет, а читать его
владельцу по ssh полезно.

### Ноль наборов — рубрики `rule-providers:` нет вовсе

Если выбрана политика `only`/`except`, но не выбрано ни одного набора, файл
состоит из шапки и одних только двух хвостовых правил. **Ключ
`rule-providers:` при этом не пишется совсем** — не пустым, а никак.

Причина в склейке: `rule-providers:` без содержимого — это
`rule-providers: null`, а слияние `yq` (`. * $item`, последний побеждает)
затёрло бы этим `null` провайдеров профиля владельца. Пустая рубрика стоила
бы семи рабочих `rule-providers` в `main.yml`. Стережёт
`TestRenderEmptySetsHasNoProviders`.

## Шапка и машинное состояние

| Строка | Смысл |
|---|---|
| 1-я, начинается с `# netmoded:` | **признак нашего файла.** Только первая строка: комментарий в середине чужого файла ничего не доказывает |
| 2-я | предупреждение человеку, что файл переписывается целиком |
| 3-я, `# netmoded-rulesets: …` | **машинное состояние**, из которого порождается тело |

Состояние — поля `ключ=значение` через пробел:

- `policy=profile\|only\|except`;
- `download=direct\|tunnel` (у `profile` не пишется: качать нечего, а
  `download=direct` рядом с «правила из профиля» читался бы как обещание
  что-то скачать);
- `sets=` — имена через запятую, у пары с подсетями суффикс `+ip`. **Поле
  пишется даже пустым**: его отсутствие значило бы «строка оборвалась», а
  пустое значение — «выбрано ноль наборов»;
- `rules=` — свои правила владельца, токены `вид:значение>действие` через
  точку с запятой: `suffix:worldsimseries.com>tunnel;cidr:fd00::/8>direct`.
  Вид отрезается по первому двоеточию (в IPv6 есть свои), действие — по
  последнему `>`. **Пишется только при непустом списке** — и это не
  экономия. Демон прежней версии незнакомое поле считает порчей (ниже), и
  для файла С правилами это желаемое: громкий `500 mixin_corrupt` вместо
  молчаливой потери правил при следующей записи (так вышло бы с отдельной
  строкой-комментарием, которую старый разбор не считает). А файл БЕЗ
  правил старый демон обязан читать как раньше — иначе обновление ломало
  бы выбор всем, у кого своих правил и не было;
- **комментарий** правила — необязательный хвост токена
  `…>действие|<комментарий в url.QueryEscape>`:
  `suffix:worldsimseries.com>tunnel|%D0%9B%D0%B8%D0%B3%D0%B0+WSS`. QueryEscape
  экранирует пробел, `;`, `>`, `|`, `#`, `%` и всё не-ASCII, поэтому
  комментарий не может порвать ни поля состояния, ни список правил, ни сам
  токен. Разбор: вид по первому `:`, комментарий по первому `|`, действие по
  последнему `>` в части до `|`. Пустой комментарий — хвоста нет, и токен
  байт-в-байт прежний. Демон до появления поля на токене с `|…` прочитает
  действие как `tunnel|%D0…` и отбросит файл как испорченный — громко, `PUT`
  чинит.

Комментарий — одна строка до 80 рун, валидный UTF-8, без управляющих
символов и переводов строки, без пробелов по краям (`commentProblem`,
та же проверка на входе `PUT` и при чтении файла). В теле он пишется как
есть строкой `  # …` **над своим правилом** — для человека с ssh; обратно
из тела не читается, как и всё тело, и на подсчёт строк не влияет (`Parse`
считает только четыре префикса правил). YAML-комментарий внутри
последовательности `yq` переживает. В сверке на дубль комментарий не
участвует, в отпечатке участвует.

Значение своего правила после проверки состоит только из `[a-z0-9.:/-]`
(`rulesets.ValidateRules`): ни апострофа, ни запятой, ни точки с запятой, ни
`>`, ни пробела — то есть безопасно и в одинарных кавычках YAML, и в строке
состояния. Что не принимается телом `PUT`, не принимается и с диска
(`parseRules` зовёт ту же проверку): файл, правленный руками, не вернёт в
`mixin.yaml` то, что панель бы отбила.

Знаки в имени набора — только `A-Za-z0-9._@!-` (`geosite.ValidName`). Имя
уезжает в строку правила в **одинарных кавычках** и в `sets=` через запятую:
апостроф порвал бы YAML при следующем старте nikki, запятая или пробел —
строку состояния. Имена с посторонними знаками отбрасываются на входе (при
чтении дерева GitHub), отбиваются при `PUT` (`400 bad_request`) и делают файл
испорченным при чтении (`ErrCorrupt`).

Порядок имён в `sets=` = порядок правил в файле = порядок выбора в панели.
Незнакомое поле в состоянии — не «наш файл нашей же версии»: разбор
отказывает, а не пропускает его молча.

Признак `+ip` хранится **в файле**, а не выводится из каталога при чтении:
иначе панель без интернета не смогла бы показать применённое, а повторное
применение молча потеряло бы половину набора (домены остались бы, подсети
исчезли).

## Три состояния файла: наш, чужой, испорченный

| Что на диске | Как читается | Что отвечает API |
|---|---|---|
| файла нет; файл пуст; одни комментарии (в том числе `mixin.yaml` из поставки nikki) | `policy: profile`, наш | `200`, `foreign: false` |
| есть непустая строка, которая не комментарий, а первой строки `# netmoded:` нет | **чужой** | `GET` → `200` с `foreign: true` (`policy: profile`, `sets: []`); `PUT` → `409 foreign_mixin`, файл не трогается |
| шапка есть, а состояние не разбирается **или** число строк `RULE-SET,nm-geosite-` не равно числу наборов в `sets=` **или** число строк `DOMAIN-SUFFIX,` / `DOMAIN,` / `IP-CIDR,` / `IP-CIDR6,` не равно числу правил в `rules=` | **испорченный** | `GET` → `500 mixin_corrupt` с путём; `PUT` **переписывает файл** — это наш файл, и повторное применение его чинит |
| файл не прочитался вовсе (права, ФС только для чтения) | неизвестно | `500 read_failed` — не `mixin_corrupt`: о содержимом не известно ничего, и «примените заново» тут не поможет |

Тело файла обратно **не разбирается** — оно порождается из состояния.
Сверяется только число строк: доменных правил наборов и своих правил, в обе
стороны. Расхождение означает, что файл правили руками или запись
оборвалась, и показывать владельцу выбор, которого в правилах нет, хуже, чем
попросить применить заново. Строка своего правила, дописанная в тело руками
без `rules=` в состоянии, тоже делает файл испорченным — намеренно: при
следующей записи она пропала бы молча.

Коды и их тексты — [`errors.md`](errors.md) (`foreign_mixin`,
`mixin_corrupt`, `read_failed`).

## Флаг `nikki.mixin.mixin_file_content`

Файл без этого флага лежит на диске мёртвым грузом: `nikki.init` его просто не
читает. Поэтому запись файла и переключение флага — **одна операция**:

- `only`/`except` → флаг `1`;
- `profile` → флаг `0` (файл при этом остаётся, из одной шапки).

Флаг читается `uci get` и переписывается **только если отличается**: запись
тем же значением стоила бы коммита пакета `nikki` на флеше и заодно
опубликовала бы всё, что накопил в стейджинге кто-то ещё
([ADR-0011](../adr/0011-optimistic-concurrency.md)). Опции нет вовсе — nikki
считает её выключенной, и мы считаем так же.

При отказе `uci set`/`uci commit` демон снимает **свою** правку
(`uci revert nikki.mixin`, [ADR-0028](../adr/0028-uci-revert-not-rollback.md))
и докладывает, действует ли записанный файл прямо сейчас: если флаг и так стоял
в `1` — действует.

## Порядок правил и почему он такой

`nikki.init` склеивает конфиг на старте службы и **приписывает `nikki-rules`
перед `rules` профиля**. Порядок внутри нашего блока:

1. **свои правила владельца**, в порядке ввода: `DOMAIN-SUFFIX,<домен>,<группа>`,
   `DOMAIN,<хост>,<группа>`, `IP-CIDR,<подсеть>,<группа>,no-resolve` (для
   IPv6 — `IP-CIDR6`). Они стоят **раньше наборов**, потому что у mihomo
   побеждает первое совпадение, а правило владельца обязано перебивать
   набор, в котором тот же домен есть: «youtube в туннель, но
   music.youtube.com напрямую» иначе не выразить;
2. по одному-двум правилам на набор, в порядке выбора: сначала домены
   (`RULE-SET,nm-geosite-<имя>,<группа>`), затем подсети
   (`RULE-SET,nm-geoip-<имя>,<группа>,no-resolve`). `no-resolve` обязателен:
   без него mihomo резолвил бы каждый домен, чтобы сверить адрес, и платил бы
   за это задержкой DNS;
3. `GEOIP,PRIVATE,DIRECT,no-resolve` — **всегда**, при обеих политиках;
4. `MATCH,<хвостовая группа>`.

| Политика | Группа наборов | Хвост `MATCH` |
|---|---|---|
| `only` | `BYPASS` | `DIRECT` |
| `except` | `DIRECT` | `BYPASS` |

Группа своего правила от политики **не зависит** — только от действия:

| Действие | Группа |
|---|---|
| `tunnel` | `BYPASS` |
| `direct` | `DIRECT` |

Своим правилам нечего скачивать, поэтому применение без единого набора
заканчивается сразу после перезапуска движка — ожидания провайдеров нет.

**Строка `GEOIP,PRIVATE` не имеет выключателя намеренно.** Правила mihomo
читаются до первого совпадения, и `MATCH` забирает всё. При политике `except`
хвост — `MATCH,BYPASS`, то есть «всё остальное в туннель»; без
`GEOIP,PRIVATE,DIRECT,no-resolve` под «остальное» попала бы локальная сеть
(`192.168.0.0/16`, `10.0.0.0/8`), и роутер вместе с панелью перестал бы быть
доступен с домашних машин. При политике `only` строка не меняет ничего.
Стережёт `TestRenderKeepsPrivateBeforeMatch`.

**Наш `MATCH` закрывает правила профиля.** Они не удалены и не изменены, но
пока политика панели активна, очередь до них не доходит. Это цена решения,
названная в [ADR-0039](../adr/0039-geosite-rulesets-mixin-file.md), — и
причина, по которой свои `DOMAIN-SUFFIX`/`DOMAIN`/`IP-CIDR` строки из
`main.yml` переезжают во вкладку как свои правила
([ADR-0040](../adr/0040-custom-rules-in-mixin.md)). Правила по портам и
протоколам (`DST-PORT`, `NETWORK`) вкладка не выражает: они остаются в
профиле и при активной политике не работают.

**Правила в одинарных кавычках.** В именах репозитория встречаются `@` и `!`
(`netflix@ads`, `category-ai-!cn`), а сами правила содержат запятые — так
безопаснее для `yq`.

## Имена провайдеров, адреса и `download`

| | |
|---|---|
| Провайдер доменов | `nm-geosite-<имя>`, `behavior: domain` |
| Провайдер подсетей | `nm-geoip-<имя>`, `behavior: ipcidr` — только у 13 имён, которые есть в обоих деревьях |
| Адрес | `https://raw.githubusercontent.com/MetaCubeX/meta-rules-dat/meta/geo/{geosite\|geoip}/<имя>.mrs` |
| Путь на диске | `./rules/<имя провайдера>.mrs` — относительно `/etc/nikki/run` |
| Интервал | `86400` (сутки), обновляет сам mihomo, без участия панели |

**Своя приставка `nm-`, а не голое имя набора:** в `run/config.yaml` наши
провайдеры лежат рядом с провайдерами профиля владельца, и совпадение имён
затёрло бы чужое. По приставке же видно из ssh, что провайдер наш.

**Имя в адресе не экранируется намеренно.** `@` и `!` допустимы в пути URL как
есть — именно в таком виде их отдаёт GitHub и в таком виде их ждёт mihomo;
экранирование превратило бы рабочий адрес в `404`.

`download=tunnel` добавляет каждому провайдеру строку `proxy: PROXY`: единственный
путь там, где `raw.githubusercontent.com` закрыт у провайдера. Цена — мёртвый
туннель означает и невыполненное обновление наборов, поэтому умолчание
`direct`.

## `PUT /api/nikki/rulesets`: порядок проверок

**Все проверки стоят до первой записи.** Это не аккуратность, а единственный
доступный вид отката: откатов в проекте нет
([ADR-0006](../adr/0006-no-rollback.md)), после `uci commit` отказаться уже
нечем, а перезаписанный `mixin.yaml` не вернуть.

| № | Проверка | Отказ |
|---|---|---|
| 1 | тело разбирается как JSON; пустой `download` заменяется на `direct` | `400 bad_request` |
| 1а | свои правила: вид и действие из набора значений, значение годное, без дублей, не больше 64, не при `profile` — **до каталога**, потому что от него не зависят | `400 bad_rule`, в тексте номер строки |
| 2 | файл на диске: чужой | `409 foreign_mixin` |
| 2а | файл не прочитался | `500 read_failed` |
| 3 | `If-Match` прислан и совпал с нынешним `fingerprint` | `409 stale_rulesets` (оба случая — один код, тексты разные) |
| 4 | среди имён есть новые (не в каталоге и не среди применённых) → каталог грузится синхронно | `503 catalog_unavailable` |
| 5 | форма выбора: политика и `download` из набора значений, `profile` без наборов, без дублей | `400 bad_request` |
| 5а | имена существуют в каталоге | `400 unknown_set`, имена перечислены |
| 6 | `uci changes nikki` пуст | `409 foreign_staged_changes`; `503 uci_unavailable`, если uci не ответил |
| 7 | движок отвечает и группа `BYPASS` в профиле есть (при `profile` не проверяется; молчащий движок — пропуск) | `503 group_missing` |
| 8 | джоб свободен | `409 job_busy`, иначе `202 {job}` |

Порядок именно такой: от «запись бессмысленна» к «запись невозможна».
Испорченный файл записи **не мешает** и отпечатка у него не спрашивают —
сверять было бы не с чем, а `PUT` переписывает файл целиком, то есть чинит ту
самую поломку, о которой `GET` докладывает `500`.

Каталог спрашивается **только когда он действительно нужен**: уже применённое
имя валидно и без него, иначе повторное применение без интернета — скажем,
одна лишь смена «откуда качать» — отбивалось бы на именах, которые сам же
демон и записал.

Все коды с текстами и подробностями — [`errors.md`](errors.md); схемы тел —
`docs/api/openapi.yaml`, примеры — `docs/api/examples/nikki-rulesets-*.json`.

## Джоб `rulesets`: что он делает и что проверяет

`kind: "rulesets"`, `arg: ""`, `eta_sec: 15`. Шаги идут от того, что переживает
перезагрузку, к тому, что живёт до неё:

1. **Файл** — атомарная запись. Отказ → `failed`, «ничего не изменено».
2. **Флаг** `nikki.mixin.mixin_file_content` — только если отличается. Отказ →
   `uci revert nikki.mixin` и `failed` с указанием, действует ли уже файл.
3. **Режим не `nikki`** → `done`: записано, вступит при включении Nikki.
   Перезапускать выключенный намеренно движок нельзя.
4. **`netmode-apply nikki`** — стоп nikki и b4, перезапуск firewall, старт
   nikki. На старте `nikki.init` склеивает `main.yml` ⊕ `mixin.yaml` ⊕ UCI в
   `run/config.yaml`; mihomo поднимается и качает `.mrs`. Отказ → `failed` тем
   же текстом, что у смены режима; файл и флаг остаются, повтор возможен.
5. **`profile` или ноль наборов** → `done`: сверять нечего, правил мы не
   писали.
6. **Ожидание докачки** — `GET /providers/rules` раз в секунду, до 20 секунд,
   пока не загрузятся все запрошенные наборы. Не ответил ни разу → `failed`
   «загрузились ли наборы, неизвестно» (тексты разные у «спросить некому»,
   «ожидание прервано» и «Clash API не ответил»).
7. **Вердикт по последнему снимку.** Ни одного набора → `failed` с первыми
   тремя именами и подсказкой про `raw.githubusercontent.com` и
   `/var/log/nikki/core.log`. Часть → `done`, недогруженные видны в `GET`
   как `loaded: false` (mihomo докачает их сам по суточному циклу). Все →
   `done`.

Провал оседает в `job.error` и **не** пишется в `status.last_fail`: своей
таксономии причин у наборов нет, как и у подписки.

**Набор загружен, когда загружены ВСЕ его провайдеры** — у каждого ненулевое
`updatedAt` в ответе Clash API. У набора с подсетями скачавшиеся домены без
подсетей — это половина набора. `ruleCount` критерием не является: три набора
в репозитории пусты и загружаются с нулём правил.

## `loaded`: три значения, и сливать их нельзя

В `GET /api/nikki/rulesets` поля `loaded`, `rules` и `updated_at` трёхзначны:

| Значение | Что это | Когда |
|---|---|---|
| `true` | набор скачан движком | Clash API ответил, все провайдеры набора с ненулевым `updatedAt` |
| `false` | набор **не** скачан | Clash API ответил, хотя бы одного провайдера нет или у него нулевое время |
| `null` | **неизвестно** | движок молчит: в теле `live: false`, все три поля `null` |

`null` — это ответ, а не отказ: выбор владельца лежит в нашем файле и читается
без mihomo. Отдавать здесь `503` значило бы, что при упавшем движке панель не
показывает даже того, что сама записала, — и владелец решил бы, что потерял
настройку. Подменять `null` на `false` — соврать ровно там, где владелец ищет
причину неработающего обхода.

## Что видно и что делается по ssh

```sh
cat /etc/nikki/mixin.yaml                       # весь выбор человекочитаемо
uci get nikki.mixin.mixin_file_content          # склеивается ли он вообще
grep -n nm-geosite /etc/nikki/run/config.yaml   # что реально получил mihomo
ls -la /etc/nikki/run/rules/                    # что скачалось
```

Возврат к профилю без панели — выключить склейку и перезапустить движок:

```sh
uci set nikki.mixin.mixin_file_content=0 && uci commit nikki && netmode-apply nikki
```

Файл при этом остаётся на диске, но не читается. Тот же результат из панели
даёт кнопка «Вернуть профилю»: `PUT` с `policy: profile` — файл из одной шапки,
флаг `0`, перезапуск.
