# Контракт: модель ошибок

Одна форма тела на все ошибки, один машинный код на каждую причину. Панель
принимает решение по машинному коду и показывает пользователю свой перевод, а
не текст демона.

## Форма тела

**Демон отдаёт вот это** (`apiError` в `internal/httpapi/server.go`, единственный
отправитель — `writeErr`):

```json
{
  "code": "ambiguous_selection",
  "error": "В конфигурации включено несколько станционных сетей. Демон не выбирает за владельца: оставьте одну через LuCI или ssh."
}
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `code` | `string` | да | `snake_case`, стабилен, часть контракта. Переименование = смена версии API |
| `error` | `string` | да | по-русски, для человека. Может меняться свободно — на него не программируют |

> ### Расхождение, известное и не закрытое
>
> Этот документ раньше описывал другую форму — `{"error": <машинный код>,
> "message": <текст>, "details": {…}}` — и описывал её как действующую.
> Такого ответа демон не отдавал никогда:
>
> - машинный код лежит в `code`, а не в `error`;
> - человеческий текст лежит в `error`, а не в `message`;
> - **`details` не существует.** Поля нет в структуре, ни один путь его не
>   заполняет. Все ссылки на `details` ниже описывают намерение, а не ответ.
>
> Панель живёт по фактической форме: `web/app.js` разбирает `e.code`, таблица
> `ERR_KEY`. Так что клиент и демон согласованы между собой, а этот документ
> расходился с обоими.
>
> Сводить их — решение владельца, и оно правится кодом, а не текстом: либо
> демон переименовывает поля и заводит `details`, либо контракт признаёт
> `{code, error}` окончательной формой. До тех пор здесь описано то, что
> приходит по проводу, а обещанные `details` помечены на месте.

Ниже, в таблицах кодов, колонка `details` сохранена: она говорит, **какие
подробности нужны** каждому коду, если поле появится. Сейчас эти подробности
не отдаются нигде.

Правила, общие для всех ответов:

1. **Ни один ответ не содержит `key`, токена и любых секретов** — включая текст
   ([ADR-0012](../adr/0012-write-only-credentials.md)).

   **Исключение ровно одно, и оно названо:** `GET /api/nikki/panel` отдаёт
   `{"url": …}`, где в query лежит `nikki.mixin.api_secret` — иначе дашборд
   открывает экран ввода пароля вместо панели
   ([ADR-0023](../adr/0023-nikki-panel-secret-on-demand.md)). Условия
   исключения — часть контракта, а не оговорка:

   - ответ **не кэшируется** (`Cache-Control: no-store`);
   - **не логируется ни при одном исходе** — ни адрес, ни секрет, ни текст
     ошибки клиента;
   - **не имеет фикстуры** в `docs/api/examples/`: пример с настоящим секретом
     был бы утечкой, а с затёртым — не примером;
   - выдаётся **по клику по видимой ссылке**, а не опросом; `/api/status`
     секрета не содержит и содержать не будет — `links.nikki` там это адрес
     без параметров. Ссылка видна, только когда `nikki.available: true`
     ([ADR-0024](../adr/0024-panel-links-only-when-service-answers.md)),
     поэтому обращений «на всякий случай» этот путь не получает.

   Токена API исключение не касается: `/api/status` не отражает его по-прежнему.
2. `Content-Type: application/json; charset=utf-8` у ошибок тоже.
3. Тело есть всегда, включая `409` и `503`. Пустое тело неотличимо от
   неисправного сервера. **Исключение — `405`:** его отдаёт `http.ServeMux`
   своим текстом мимо `writeErr`, то есть не в этой форме вовсе (см. ниже).
4. Панель не должна разбирать текст — для каждой ветки поведения есть
   отдельный `code`.

## Полный список кодов

### 400 — запрос неверен

| `error` | Когда |
|---|---|
| `bad_request` | тело не разбирается, нет обязательного поля, значение вне допустимого набора, отсутствует `If-Match` на записи (кроме `PUT /api/nikki/rulesets` — там это `409 stale_rulesets`), в теле больше одного JSON-значения |
| `unsupported_field` | в теле `POST /api/wifi/networks` поле, которого нет в схеме `NetworkWrite`; в теле `POST /api/upstream` поле помимо `id` |
| `unknown_set` | в теле `PUT /api/nikki/rulesets` есть имена наборов, которых нет ни в каталоге geosite, ни среди уже применённых. Текст перечисляет именно эти имена |
| `bad_rule` | в теле `PUT /api/nikki/rulesets` своё правило не принято: неизвестный вид или действие, негодное значение (не имя хоста, адрес под видом домена, подсеть без маски или не каноническая), значение дважды, больше 64 правил, правила при `policy: profile`. Текст называет **номер строки** (с единицы), вид, значение и причину; отбивается первое негодное правило |
| `bad_ip` | в теле `POST /api/watch` адрес не разобрался, не IPv4 либо не из подсети LAN. Отдельный код, а не `bad_request`: панель подсвечивает поле адреса и предлагает список устройств из `GET /api/watch/hosts` |

`bad_request` — про значения, `unsupported_field` — про форму. Разделены не
ради дробности: незнакомое поле означает, что клиент и демон разошлись в
понимании контракта (чаще всего панель новее демона), и лечится это не
исправлением ввода, а сборкой. Молча проглотить такое поле нельзя — клиент
получил бы `200` на просьбу, которую никто не выполнял. Так было с `network`
в `POST /api/wifi/networks`: поле принималось и выбрасывалось, а секция
создавалась на `wwan`. Принять его тоже нельзя: активную сеть выбирает
`POST /api/upstream` переключением `disabled`, а не переносом секции в другую
L3-сеть ([ADR-0026](../adr/0026-switch-from-ambiguous.md)).

`bad_rule` — по той же логике, что и `unknown_set`: отдельный код, потому что
панель подсвечивает конкретную строку своих правил по номеру из текста, а
«неверный запрос» не сказал бы, какую из шестидесяти четырёх. Проверяется
**до** похода за каталогом: опечатка в домене от каталога не зависит, и
`503 catalog_unavailable` вместо неё отправил бы владельца чинить не то.

`unknown_set` — `400`, а не `409`: состояние системы тут ни при чём, чинится
правкой запроса (владелец ошибся в имени или каталог опередил панель), а не
перечитыванием. Отдельный код от `bad_request` потому, что панель подсвечивает
именно названные чипы: «неверный запрос» не сказало бы, какое из тридцати имён
написано с опечаткой.

### 401 / 403 — доступ

| Код | `code` | Когда |
|---|---|---|
| 401 | `unauthorized` | токен не пришёл ни заголовком `Authorization: Bearer`, ни параметром `?token=`, ни кукой `netmode_token` — либо не совпал ([ADR-0014](../adr/0014-lan-bind-and-token.md)) |
| 403 | `forbidden_origin` | **ЗАРЕЗЕРВИРОВАН, не отдаётся.** Замысел: отбивать запрос с чужим `Origin`. Проверки в коде нет вовсе (`grep Origin internal/` пуст), хотя ADR-0014 описывает её как один из двух механизмов защиты от CSRF. Фактически защита одна — `SameSite=Strict` у куки |

### 404 / 405

| Код | `code` | Когда |
|---|---|---|
| 404 | `not_found` | нет секции с таким `id`; нет сета b4 с таким `id`; нет узла Nikki с таким именем |
| 405 | `method_not_allowed` | **ЗАРЕЗЕРВИРОВАН, не отдаётся в этой форме.** `http.ServeMux` сам отвечает `405` с заголовком `Allow` и текстом `Method Not Allowed` в `text/plain`, не проходя через `writeErr`. Клиент, ждущий JSON, получит не его |

Неизвестный путь под `GET` попадает в `http.FileServer` панели и получает его
собственный `404` — тоже не в этой форме. `POST /api/confirm` из SPEC §7
попадает под `405` по той же причине: маршрут `GET /` совпадает по пути, но не
по методу ([ADR-0006](../adr/0006-no-rollback.md) — эндпоинта нет,
подтверждать нечего).

### 409 — состояние системы не позволяет

Самая содержательная группа. Все случаи означают одно: запрос корректен, но
выполнить его сейчас нельзя, и **исправляет это пользователь, а не повтор
запроса**. Колонка `details` — какие подробности нужны; сейчас поле не
отдаётся (см. выше).

| `code` | Когда | `details` (не реализовано) | Что делать пользователю |
|---|---|---|---|
| `job_busy` | уже выполняется джоб; пришёл второй ([ADR-0013](../adr/0013-fast-vs-slow.md)) | `{"job": {…текущий джоб…}}` | дождаться завершения; очереди нет сознательно |
| `foreign_staged_changes` | `uci changes` пакета непусто до нашей записи: `wireless` на записи сетей, `nikki` на `PUT /api/nikki/rulesets` ([ADR-0011](../adr/0011-optimistic-concurrency.md)) | `{"pkg": "wireless", "changes": ["wireless.wifinet2.ssid='NEW'"]}` | завершить или отменить правку в LuCI |
| `fingerprint_required` | на записи нет заголовка `If-Match` | `{}` | прочитать `GET /api/wifi/networks` и повторить с его `fingerprint` |
| `fingerprint_mismatch` | `If-Match` не совпал с текущим отпечатком | `{"expected": "sha256:…", "got": "sha256:…"}` | обновить список и повторить |
| `ambiguous_selection` | `Selection == Ambiguous`, запрошено **создание, правка или удаление** сети ([ADR-0026](../adr/0026-switch-from-ambiguous.md)) | `{"sections": ["wifinet0","wifinet2"], "reason": "multiple_enabled" \| "unparsable_disabled"}` | переключиться на нужную сеть кнопкой в панели — это снимет неоднозначность; либо оставить одну включённую секцию в LuCI |
| `enabled_network_readonly` | правка или удаление включённой секции ([ADR-0026](../adr/0026-switch-from-ambiguous.md)) | `{"id": "wifinet0", "ssid": "John24"}` | переключиться на другую сеть, затем править |
| `already_selected` | `POST /api/upstream` по секции, которая **уже единственная включённая** ([ADR-0025](../adr/0025-upstream-narrow-verb.md)) | `{"id": "wifinet0", "ssid": "John24"}` | перечитать `GET /api/wifi/networks` — список устарел |
| `network_incomplete` | `POST /api/upstream` по секции, которая заведомо не поднимется: нет `ssid`; либо `encryption` не `none`, а пароля нет; либо `network` ведёт не во внешний канал ([ADR-0025](../adr/0025-upstream-narrow-verb.md)) | `{"id": "wifinet2", "missing": "key"}` | дописать сеть через «изменить», затем переключаться |
| `group_not_selectable` | группа mihomo не принимает ручной выбор | `{"group": "PROXY"}` | поправить профиль mihomo |
| `member_not_selectable` | выбран не узел: заголовок раздела, «Авто» или запись, которую конвертер не смог перевести ([ADR-0031](../adr/0031-subscription-in-daemon.md)) | `{"name": "⬇️ Обходы белых списков ⬇️", "kind": "separator"}` | выбрать узел; строки других видов панель и так не даёт нажать |
| `subscription_not_configured` | `POST /api/subscription/update` при пустом `netmode.main.subscription_url` | `{}` | задать адрес подписки: `uci set netmode.main.subscription_url='…' && uci commit netmode` |
| `stale_autopool` | `If-Match` на `PUT /api/nikki/autopool` не совпал с нынешним `fingerprint` либо не прислан вовсе — тексты разные, код один. Отпечаток у пула СВОЙ, отдельный от наборов: секции независимы, и правка одной не должна отбивать чужую запись другой | `{"expected": "sha256:…", "got": "sha256:…"}` | перечитать `GET /api/nikki/autopool` и повторить с новым отпечатком |
| `bad_autopool` | форма выбора не принята: неизвестный режим, дубликат имени, потолок в 128 узлов, пустой список у `allow` | `{"reason": "в авто-пуле не осталось ни одного узла"}` | снять лишнее или сменить режим |
| `unknown_node` | отмечено имя, которого в подписке нет: вкладка устарела либо запрос ручной | `{"names": ["🇿🇼Нет такого"]}` | перечитать `GET /api/nikki/autopool` |
| `empty_pool` | после такого выбора в авто-пуле не остаётся ни одного узла. `empty-fallback: REJECT` в профиле спасёт движок, но владелец увидел бы мёртвое «Авто» и не понял, чем он его опустошил | `{"mode": "deny", "available": 3}` | снять часть отметок |
| `no_provider_pool` | запрошен режим `provider`, а балансировщика у провайдера в подписке нет — состав брать неоткуда | `{}` | выбрать узлы вручную |
| `stale_rulesets` | `If-Match` на `PUT /api/nikki/rulesets` не совпал с нынешним `fingerprint` (пока владелец выбирал, выбор изменила вторая вкладка или ssh) либо не прислан вовсе — тексты у этих двух случаев разные, код один | `{"expected": "sha256:…", "got": "sha256:…"}` | перечитать `GET /api/nikki/rulesets` и повторить с новым отпечатком |
| `foreign_mixin` | `/etc/nikki/mixin.yaml` есть, но написан не нами (первая строка не начинается с `# netmoded:`) | `{"path": "/etc/nikki/mixin.yaml"}` | убрать или переименовать файл на роутере — перезаписать его демон не станет |
| `engine_off` | `POST /api/watch` при режиме обхода не `nikki`. Наблюдатель читает решения движка — какое правило сработало и куда ушёл трафик; движок остановлен, решений нет вовсе. `409`, а не `503`: движок не сломан, владелец сам его выключил, и чинится это сменой режима на главной | `{"mode": "off"}` | включить Nikki |

`stale_rulesets` — свой код, а не `fingerprint_mismatch`, и это не дробность:
сверяются разные источники правды (`/etc/nikki/mixin.yaml` против
`/etc/config/wireless`), и панель на них реагирует в разных экранах. Отдельного
`fingerprint_required` у наборов нет: отсутствующий `If-Match` с нынешним
отпечатком не совпадает и приходит тем же `stale_rulesets` — лечится он тем же
самым, перечитыванием `GET`.

`foreign_mixin` — единственный отказ, который повтором не чинится вовсе: пока
чужой файл лежит на месте, любая запись наборов молча уничтожила бы чужую
работу. Выход отсюда только руками, по ssh.

`fingerprint_required` — именно `409`, а не `400`: заголовка нет не потому, что
запрос кривой, а потому, что клиент не доказал знание текущего состояния. Это
конфликт представлений, и лечится он перечитыванием списка.
[ADR-0011](../adr/0011-optimistic-concurrency.md) называет здесь `400` —
побеждает код.

`b4_partial` **удалён** ([ADR-0033](../adr/0033-b4-sets-not-exclusive.md)).
Он описывал состояние «прочие сеты погашены, целевой не включён», а оно
существовало только между двумя вызовами эксклюзивного переключения. Сеты
больше не эксклюзивны, `POST /api/b4/set` делает один вызов, и середины,
которую этот код называл, не существует. Не «мы перестали её показывать» —
её неоткуда взять.

#### `already_selected` — почему `409`, а не `200`

Просьба выполнена ещё до её поступления, и соблазн ответить «уже так» велик.
Но `200` здесь был бы неправдой о клиенте. Панель не считает включённость
сама — она читает `switchable`, который вычислил сервер, и у уже выбранной
сети такой кнопки не рисует вовсе. Значит запрос по такой секции означает
ровно одно: **список у клиента устарел**. Это конфликт представлений, тот же
самый, что `fingerprint_mismatch`, и лечится он тем же — перечитать список.
Сверх того, `200` потребовал бы отдельной формы ответа: на этом маршруте
успех — это `202` с джобом, а джоба здесь не будет, потому что применять
нечего. Формы «`200` без джоба» в этом API нет больше нигде, и заводить её
ради состояния «делать ничего не надо» дороже, чем сказать правду кодом.

#### `network_incomplete` — отказ до первой записи

Секция без `ssid`, или с шифрованием без пароля, или привязанная не к
внешнему каналу — это сеть, которая **не поднимется**. Записать намерение,
закоммитить и применить его значило бы оставить роутер без upstream по
причине, известной заранее. Отката нет ([ADR-0006](../adr/0006-no-rollback.md)),
а после `uci commit` отказаться уже нечем: отменить коммит нельзя, и
применение станет неизбежным при ближайшем чужом `network reload`. Поэтому
проверка стоит перед первой записью — там, где мы ещё ничего не сломали
([ADR-0025](../adr/0025-upstream-narrow-verb.md)).

#### `ambiguous_selection` на `POST /api/upstream` не отдаётся — и это решение

**Никогда, ни при каком состоянии конфигурации.** Это не забытая проверка и
не дырка в реализации: переключение и есть выход из неоднозначности
([ADR-0026](../adr/0026-switch-from-ambiguous.md)). Демон здесь ничего не
выбирает — секцию называет человек по имени, результат детерминирован
(включена ровно одна названная секция), значит запрет
[ADR-0010](../adr/0010-never-auto-repair.md) на автопочинку не нарушен: он
запрещает демону решать, какая из включённых сетей лишняя, а не запись при
неоднозначности как таковую.

Обратное — запрет — означало бы, что единственное действие, снимающее
неоднозначность, запрещено именно из-за неоднозначности, и владелец с
баннером «включено две сети» идёт в ssh мимо готовой кнопки.

**На создании, правке и удалении код отдаётся как прежде** и по прежней
причине: при двух включённых секциях неизвестно, какую поднимет netifd, и
безвредность **любой** правки — даже правки выключенной секции — недоказуема.
Переключение этим свойством не обладает: оно не полагается на текущий выбор,
а заменяет его целиком.

Отсюда же два поля в схеме `Network` вместо одного: `editable` при
`ambiguous` — `false`, `switchable` — `true`.

| `code` | Статус |
|---|---|
| `ambiguous_set_name` | **ЗАРЕЗЕРВИРОВАН, не отдаётся.** Задумывался для случая «в `GET /api/sets` два сета с запрошенным именем». Сет адресуется по `id` (`POST /api/b4/set` принимает `{"id": …, "enabled": …}`), имя ключом не является — угадывать нечего. [ADR-0008](../adr/0008-b4-exclusive-sets.md) описывает обратное; побеждает код. [ADR-0033](../adr/0033-b4-sets-not-exclusive.md) отменил 0008 целиком, но адресацию по `id` сохранил — вывод тот же |

### 501 — не отдаётся ни одним маршрутом

| `code` | Статус |
|---|---|
| `not_implemented` | **ЗАРЕЗЕРВИРОВАН, не отдаётся.** Отдавался ровно одним маршрутом — `POST /api/upstream`, — и тот с фазы 2 работает: оба блокера [ADR-0016](../adr/0016-upstream-deferred.md) (RQ-03, RQ-04) закрыты замером, третье условие исполнено [ADR-0025](../adr/0025-upstream-narrow-verb.md). Маршрутов, отвечающих `501`, в демоне не осталось. Имя оставлено в наборе, чтобы не было занято под другой смысл |

`POST /api/nikki/test` под это правило не подпадал и раньше: пока он не был
реализован, его маршрут просто не был зарегистрирован, и запрос получал `405`
от `http.ServeMux`, а не `501`. Теперь маршрут есть (RQ-06 закрыт), и этот
абзац остаётся только затем, чтобы `405` в старых заметках не приняли за
исчезнувшую ветку кода.

Отдельно про его исход: «не ответил ни один узел» — это `200`, а не ошибка.
Движок отработал, узлы опрошены, и «все мертвы» — такой же результат замера,
как «все живы»; он едет полем `test`, а не кодом.

Смысл кода, если он когда-нибудь вернётся, остаётся прежним: `501`, а не
`503`, — «не в этой версии», а не «попробуйте позже»; повторять запрос
бессмысленно.

### 503 — внешняя зависимость недоступна

Демон жив, но нужный ему компонент — нет. Повтор запроса имеет смысл.

| `code` | Когда | `details` (не реализовано) |
|---|---|---|
| `b4_unavailable` | b4 (порт 7000) не ответил, ответил не `200`, либо клиент не настроен | `{"probe": "GET /api/version", "err": "connection refused"}` |
| `nikki_unavailable` | Clash API не ответил либо клиент не настроен. **RQ-01 закрыт** — это условное состояние, а не постоянное | `{"probe": "GET /proxies"}` |
| `group_missing` | Clash API ответил, но нужной группы в профиле нет: `PROXY` на выборе узла и замере, `BYPASS` на `PUT /api/nikki/rulesets` (правила `RULE-SET,…,BYPASS` без неё не применятся, и mihomo не поднимется вовсе — отбить лучше до записи файла). Чинится правкой профиля, а не ожиданием | `{"group": "PROXY"}` |
| `ubus_unavailable` | `ubus call network.wireless status` не ответил на пути скана | `{"object": "network.wireless"}` |
| `uci_unavailable` | `uci changes` или `uci show wireless` не отработали на пути записи — включая путь `POST /api/upstream` | `{"pkg": "wireless"}` |
| `scan_failed` | `ubus call iwinfo scan` вернул ошибку | `{"ifname": "phy0.0-sta0"}` |
| `radio_unknown` | не выяснено, какое радио работает станцией: интерфейса с `mode=sta` нет ни в `network.wireless status`, ни в `/etc/config/wireless` ([ADR-0019](../adr/0019-radio-role-derived.md)) | `{}` — угадывать нечем |
| `ifname_unknown` | станционное радио выяснено, но имя его интерфейса не выводится из `network.wireless status`: радио выключено, объект не ответил | `{"radio": "radio1"}` |
| `unavailable` | планировщик подписки не настроен. В штатной сборке недостижимо: `NewServer` заводит его всегда | `{}` |
| `host_unknown` | адрес роутера не выводится из заголовка `Host`: панель открыта через ssh-туннель или по петле. Только `GET /api/nikki/panel` | `{}` — угадывать нечем |
| `nikki_unconfigured` | не задан `nikki.mixin.api_listen` (не выводится порт) либо пуст `nikki.mixin.api_secret`. Только `GET /api/nikki/panel` | `{}` — значения секрета в подробностях быть не может |
| `catalog_unavailable` | список имён наборов geosite не загружен и загрузить его не удалось (нет аплинка, исчерпан лимит GitHub в 60 запросов в час, дерево пришло обрезанным). Отдаётся `GET /api/nikki/rulesets/catalog` всегда, а `PUT /api/nikki/rulesets` — только когда среди присланных имён есть новые: уже применённые проверяются по файлу и каталога не спрашивают | `{}` — причина в тексте |
| `panel_missing` | Clash API настроен, но по `/ui/` нет статики дашборда: не скачана (`nikki.mixin.ui_url` тянет её с GitHub при первом запуске) либо движок не поднят. Только `GET /api/nikki/panel` | `{}` |
| `lan_unknown` | подсеть локальной сети не вывелась из `network.lan` на пути `POST /api/watch`: ни `ipaddr` с маской внутри, ни пара `ipaddr` + `netmask` не разобрались. Демон не сочиняет чужую конфигурацию ([ADR-0019](../adr/0019-radio-role-derived.md)), а пустить в наблюдение любой адрес значило бы наблюдать за чем угодно | `{}` — угадывать нечем |

Три кода `/api/nikki/panel` разделены не ради дробности: они чинятся в трёх
разных местах — в браузере, в `/etc/config/nikki` и на диске роутера, — и один
общий код отправил бы владельца перебирать их наугад
([ADR-0023](../adr/0023-nikki-panel-secret-on-demand.md)).

`panel_missing` — не `nikki_unavailable`: Clash API может отвечать прекрасно, а
дашборд быть не скачан. `503`, а не `500`: повтор осмыслен ровно после того, как
владелец докачал панель или поднял движок.

`host_unknown` — тоже `503`, а не `400`: заголовок `Host` корректен, просто по
нему не выводится адрес, пригодный для браузера владельца. Мешает обстановка, а
не запрос.

| `code` | Статус |
|---|---|
| `b4_auth_required` | **ЗАРЕЗЕРВИРОВАН, не отдаётся.** На этом роутере `auth_check` вернул `auth_required: false`, и клиент этот маршрут не зовёт вовсе. Включённая аутентификация деградирует в `b4_unavailable`: пароль не угадываем ([ADR-0007](../adr/0007-b4-api-only.md) описывает отдельный код — побеждает код) |

### 502 — внешний сервис ответил, но не так

Отличается от `503` тем, что ждать бесполезно: сервис жив, непонятен его ответ.

| `code` | Когда |
|---|---|
| `b4_error` | b4 ответил неразобранным телом, отклонил запрос (`b4.ErrRejected`) либо вернул код вне контракта |
| `nikki_error` | то же для Clash API (`nikki.StatusError` с непредвиденным кодом) |

`radio_unknown` и `ifname_unknown` — два разных незнания, и сливать их нельзя:
первое означает «неизвестно, ЧТО трогать», второе — «известно что, но не
поднято». Первое запрещает и запись тоже (демон не знает, какие секции наши);
второе мешает только обращению к живому радио.

Ни то, ни другое не лечится догадкой. «Возьмём радио с меньшим индексом» — это
тот же хардкод, который [ADR-0019](../adr/0019-radio-role-derived.md) убрал:
индекс радио задаётся порядком регистрации драйверов, а не диапазоном.

`radio_unknown` возвращают `GET /api/wifi/scan`, `GET`/`POST /api/wifi/networks`,
`DELETE /api/wifi/networks/{id}` и `POST /api/upstream`. На последнем незнание
особенно дорого: неизвестно не только, чьи секции наши, но и какому устройству
адресовать `reconf` ([ADR-0025](../adr/0025-upstream-narrow-verb.md)).
`ifname_unknown` — `GET /api/wifi/scan` и
всё, что требует обращения к живому радио. `/api/status` при этом **отдаёт 200** — там недоступность
выражается полями (`associated_ssid: null`, `b4.available: false`), а не
кодом ответа ([ADR-0017](../adr/0017-polling-no-push.md)).

### 500 — наша ошибка

| `code` | Когда |
|---|---|
| `internal` | всё, что мы не предусмотрели: не завёлся джоб, не сгенерировалось имя секции, панель не встроена в бинарь |
| `parse_failed` | вывод `uci show` или `network.wireless status` не разобрался. Это наша ошибка, а не внешняя: команда ответила |
| `write_failed` | `uci set`, `uci add` или `uci delete` не отработали. Для опции `key` текст без значения (ADR-0012) |
| `commit_failed` | `uci commit wireless` не отработал. Отдельный код от `write_failed`: стейджинг остался, и это видно в LuCI |
| `read_failed` | журнал `/etc/nikki/updates.log` не прочитался; либо не прочитался вовсе файл наборов `/etc/nikki/mixin.yaml` — права, каталог, ФС только для чтения. О содержимом в этом случае неизвестно ничего, поэтому код не `mixin_corrupt`: «примените заново» тут не поможет |
| `mixin_corrupt` | `/etc/nikki/mixin.yaml` наш (шапка на месте), но его содержимому верить нельзя: число правил в теле не сходится с записанным состоянием, то есть файл правили руками или запись оборвалась. Только `GET /api/nikki/rulesets`: `PUT` этим не отбивается — он переписывает файл целиком, то есть чинит ровно эту поломку |

Текст у всех — общий, без внутренних путей и без значений опций.

Не используется для «состояние системы такое» — для этого есть `409`.

## Правило выбора кода

| Вопрос | Ответ | Код |
|---|---|---|
| Запрос синтаксически неверен? | да | `400` |
| Не тот, кто пришёл? | да | `401` / `403` |
| Объекта нет? | да | `404` |
| Метод не поддержан на этом пути? | да | `405` |
| Мешает текущее состояние системы, исправляет человек? | да | `409` |
| Не реализовано и в этой версии не появится? | да | `501` — **сейчас таких маршрутов нет** |
| Внешний компонент молчит, повтор осмыслен? | да | `503` |
| Внешний компонент ответил, но непонятно чем? | да | `502` |
| Всё прочее | | `500` |

## Как ведёт себя `/api/status`

`/api/status` **никогда не отвечает `409`, `501` и `503`**. Он всегда `200`
(или `401`), а любая недоступность выражена полями:

| Ситуация | В теле `/api/status` |
|---|---|
| b4 лежит | `"b4": {"available": false, "version": null, "set": "", "enabled_count": 0}` |
| Nikki недоступна | `"nikki": {"available": false, "version": null, "set": "", "enabled_count": 0}` |
| ассоциации нет | `"associated_ssid": null` |
| конфликт выбора | `"selection_state": "ambiguous"`, `"configured_ssid": null`, `"conflict": ["wifinet0","wifinet2"]` |
| радио не выяснено | поля гаснут (`ap.band: ""`, `associated_ssid: null`), но ответ остаётся `200`: `503 radio_unknown` — удел путей, которые собираются что-то **трогать** ([ADR-0019](../adr/0019-radio-role-derived.md)) |
| джоб упал | `job.state: "failed"`, `job.error` — текст (виден **5 с** после завершения, `job.keepFinished`) |
| переключение upstream не состоялось | `last_fail: {ssid, reason, at}` — один из восьми машинных кодов `reason`. В отличие от `job`, поле не гаснет через 5 секунд: браузер, потерявший связь вместе с upstream, вернётся позже, чем джоб пропадёт из показа. Перезапуск демона его обнуляет — на диск оно не пишется ([ADR-0025](../adr/0025-upstream-narrow-verb.md)) |
| адрес морды не собрался | `links.b4` / `links.nikki` / `links.luci` — `null`, и панель прячет кнопку, а не подставляет свой адрес наугад. Причина у всех трёх общая: хост из `Host` не вывелся. Для `links.luci` это причина **единственная** — своего эндпоинта, который мог бы отказать по-другому, у него нет |
| движок не отвечает | поле `links.<движок>` остаётся прежним адресом, а кнопку панель **не рисует**: у b4 и Nikki морда и API — один слушатель, и ссылка упёрлась бы в connection refused ([ADR-0024](../adr/0024-panel-links-only-when-service-answers.md)). Причину отказа для nikki при живом Clash API называет только `GET /api/nikki/panel` ([ADR-0023](../adr/0023-nikki-panel-secret-on-demand.md)) |
| роутер отвечает, а движки нет | `links.luci` **и его кнопка** на месте: правило показа заведено на морды движков, которыми управляет `netmode-apply`, а uhttpd мы не гасим. Живость LuCI не проверяется — исправный LuCI на неаутентифицированный запрос отвечает `403`, и проба не отличила бы «жив» от «сломан» |

Причина: статус опрашивается 1 Гц и служит источником картины целиком. Если
он начнёт падать из-за лежащего b4, панель ослепнет вся.

## Проверяется тестами

Механического сторожа у формы тела **нет**: ни один тест не сверяет ответ с
образцом, `scripts/check-routes.sh` видит только пути. Проверяются машинные
коды на конкретных сценариях — этого достаточно, чтобы поймать подмену кода, и
недостаточно, чтобы поймать переименование поля.

| Сценарий | Ожидание |
|---|---|
| `409 job_busy` | второй `POST /api/mode` во время первого |
| `409 ambiguous_selection` | фикстура с двумя включёнными секциями |
| `409 fingerprint_mismatch` | подмена фикстуры между `GET` и `POST` |
| `409 enabled_network_readonly` | `POST` по `id` включённой секции |
| `409 foreign_staged_changes` | непустой `uci changes` |
| `409 already_selected` | `POST /api/upstream` по секции, которая уже единственная включённая; файл не изменён |
| `409 network_incomplete` | `POST /api/upstream` по секции без `ssid`; по секции с `encryption != none` и без `key`; по секции с чужим `network`. Во всех трёх — `uci changes` пуст после ответа |
| `POST /api/upstream` при `ambiguous` | **`202`, а не `409`**: джоб заведён, после применения включена ровно одна секция ([ADR-0026](../adr/0026-switch-from-ambiguous.md)) |
| `not_implemented` не отдаётся | греп по телам всех ответов в тестах: кода нет ни на одном пути |
| `503 b4_unavailable` | клиент b4 с отказом соединения |
| `503 radio_unknown` | фикстура без `mode=sta` и в ubus, и в UCI |
| Радио переставлены местами | код идёт за `mode=sta`, а не за индексом |
| `/api/status` при лежащем b4 | **200**, `b4.available: false` |
| Ни в одном ответе нет `key` | грепом по всем телам в тестах |
| `503 host_unknown` / `nikki_unconfigured` / `panel_missing` | `TestNikkiPanelRefusals` — три подтеста, каждый сверяет `code`, а не текст |
| Секрета Clash API нет в `/api/status` | `TestStatusNeverLeaksSecret` — греп по телу; падает и в случае, когда у тестового сервера секрет пуст и проверять нечего |
| Секрет и путь панели не попадают в журнал | `TestNikkiPanelNeverLogsSecret` — на всех четырёх исходах эндпоинта |
| Ответ с секретом не кэшируется | `TestNikkiPanelIsNotCacheable` |
