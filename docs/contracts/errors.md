# Контракт: модель ошибок

Одна форма тела на все ошибки, один машинный код на каждую причину. Панель
принимает решение по машинному коду и показывает пользователю свой перевод, а
не текст демона.

## Форма тела

**Демон отдаёт вот это** (`apiError` в `internal/httpapi/server.go`, единственный
отправитель — `writeErr`):

```json
{
  "code": "ambiguous_selection",
  "error": "В конфигурации включено несколько станционных сетей. Демон не выбирает за владельца: оставьте одну через LuCI или ssh."
}
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `code` | `string` | да | `snake_case`, стабилен, часть контракта. Переименование = смена версии API |
| `error` | `string` | да | по-русски, для человека. Может меняться свободно — на него не программируют |

> ### Расхождение, известное и не закрытое
>
> Этот документ раньше описывал другую форму — `{"error": <машинный код>,
> "message": <текст>, "details": {…}}` — и описывал её как действующую.
> Такого ответа демон не отдавал никогда:
>
> - машинный код лежит в `code`, а не в `error`;
> - человеческий текст лежит в `error`, а не в `message`;
> - **`details` не существует.** Поля нет в структуре, ни один путь его не
>   заполняет. Все ссылки на `details` ниже описывают намерение, а не ответ.
>
> Панель живёт по фактической форме: `web/app.js` разбирает `e.code`, таблица
> `ERR_KEY`. Так что клиент и демон согласованы между собой, а этот документ
> расходился с обоими.
>
> Сводить их — решение владельца, и оно правится кодом, а не текстом: либо
> демон переименовывает поля и заводит `details`, либо контракт признаёт
> `{code, error}` окончательной формой. До тех пор здесь описано то, что
> приходит по проводу, а обещанные `details` помечены на месте.

Ниже, в таблицах кодов, колонка `details` сохранена: она говорит, **какие
подробности нужны** каждому коду, если поле появится. Сейчас эти подробности
не отдаются нигде.

Правила, общие для всех ответов:

1. **Ни один ответ не содержит `key`, токена и любых секретов** — включая текст
   ([ADR-0012](../adr/0012-write-only-credentials.md)).
2. `Content-Type: application/json; charset=utf-8` у ошибок тоже.
3. Тело есть всегда, даже у `501` и `503`. Пустое тело неотличимо от
   неисправного сервера. **Исключение — `405`:** его отдаёт `http.ServeMux`
   своим текстом мимо `writeErr`, то есть не в этой форме вовсе (см. ниже).
4. Панель не должна разбирать текст — для каждой ветки поведения есть
   отдельный `code`.

## Полный список кодов

### 400 — запрос неверен

| `error` | Когда |
|---|---|
| `bad_request` | тело не разбирается, нет обязательного поля, значение вне допустимого набора, отсутствует `If-Match` на записи, в теле больше одного JSON-значения |
| `unsupported_field` | в теле `POST /api/wifi/networks` поле, которого нет в схеме `NetworkWrite` |

`bad_request` — про значения, `unsupported_field` — про форму. Разделены не
ради дробности: незнакомое поле означает, что клиент и демон разошлись в
понимании контракта (чаще всего панель новее демона), и лечится это не
исправлением ввода, а сборкой. Молча проглотить такое поле нельзя — клиент
получил бы `200` на просьбу, которую никто не выполнял. Так было с `network`
в `POST /api/wifi/networks`: поле принималось и выбрасывалось, а секция
создавалась на `wwan`. Принять его тоже нельзя — выбор L3-сети станционной
секции и есть смена upstream, отложенная [ADR-0016](../adr/0016-upstream-deferred.md).

### 401 / 403 — доступ

| Код | `code` | Когда |
|---|---|---|
| 401 | `unauthorized` | токен не пришёл ни заголовком `Authorization: Bearer`, ни параметром `?token=`, ни кукой `netmode_token` — либо не совпал ([ADR-0014](../adr/0014-lan-bind-and-token.md)) |
| 403 | `forbidden_origin` | **ЗАРЕЗЕРВИРОВАН, не отдаётся.** Замысел: отбивать запрос с чужим `Origin`. Проверки в коде нет вовсе (`grep Origin internal/` пуст), хотя ADR-0014 описывает её как один из двух механизмов защиты от CSRF. Фактически защита одна — `SameSite=Strict` у куки |

### 404 / 405

| Код | `code` | Когда |
|---|---|---|
| 404 | `not_found` | нет секции с таким `id`; нет сета b4 с таким `id`; нет узла Nikki с таким именем |
| 405 | `method_not_allowed` | **ЗАРЕЗЕРВИРОВАН, не отдаётся в этой форме.** `http.ServeMux` сам отвечает `405` с заголовком `Allow` и текстом `Method Not Allowed` в `text/plain`, не проходя через `writeErr`. Клиент, ждущий JSON, получит не его |

Неизвестный путь под `GET` попадает в `http.FileServer` панели и получает его
собственный `404` — тоже не в этой форме. `POST /api/confirm` из SPEC §7
попадает под `405` по той же причине: маршрут `GET /` совпадает по пути, но не
по методу ([ADR-0006](../adr/0006-no-rollback.md) — эндпоинта нет,
подтверждать нечего).

### 409 — состояние системы не позволяет

Самая содержательная группа. Все случаи означают одно: запрос корректен, но
выполнить его сейчас нельзя, и **исправляет это пользователь, а не повтор
запроса**. Колонка `details` — какие подробности нужны; сейчас поле не
отдаётся (см. выше).

| `code` | Когда | `details` (не реализовано) | Что делать пользователю |
|---|---|---|---|
| `job_busy` | уже выполняется джоб; пришёл второй ([ADR-0013](../adr/0013-fast-vs-slow.md)) | `{"job": {…текущий джоб…}}` | дождаться завершения; очереди нет сознательно |
| `foreign_staged_changes` | `uci changes wireless` непусто до нашей записи ([ADR-0011](../adr/0011-optimistic-concurrency.md)) | `{"changes": ["wireless.wifinet2.ssid='NEW'"]}` | завершить или отменить правку в LuCI |
| `fingerprint_required` | на записи нет заголовка `If-Match` | `{}` | прочитать `GET /api/wifi/networks` и повторить с его `fingerprint` |
| `fingerprint_mismatch` | `If-Match` не совпал с текущим отпечатком | `{"expected": "sha256:…", "got": "sha256:…"}` | обновить список и повторить |
| `ambiguous_selection` | `Selection == Ambiguous`, запрошена любая запись в `wireless` ([ADR-0010](../adr/0010-never-auto-repair.md)) | `{"sections": ["wifinet0","wifinet2"], "reason": "multiple_enabled" \| "unparsable_disabled"}` | оставить одну включённую секцию в LuCI |
| `enabled_network_readonly` | правка или удаление включённой секции ([ADR-0009](../adr/0009-phase1-write-invariant.md)) | `{"id": "wifinet0", "ssid": "John24"}` | выключить сеть в LuCI, затем править; либо ждать фазы 2 |
| `b4_partial` | прочие сеты погашены, целевой включить не удалось: обход выключен целиком | `{"set": "general"}` | повторить нажатие — b4 отвечает, помогает повтор, а не ожидание |
| `group_not_selectable` | группа mihomo не принимает ручной выбор | `{"group": "PROXY"}` | поправить профиль mihomo |

`fingerprint_required` — именно `409`, а не `400`: заголовка нет не потому, что
запрос кривой, а потому, что клиент не доказал знание текущего состояния. Это
конфликт представлений, и лечится он перечитыванием списка.
[ADR-0011](../adr/0011-optimistic-concurrency.md) называет здесь `400` —
побеждает код.

`b4_partial` — тоже `409`, а не `503`: b4 **отвечает**, состояние изменено, но
не то, о котором просили. Отката нет намеренно (ADR-0006, ADR-0010): сервис, не
ответивший на включение, с той же вероятностью не ответит и на компенсацию.

| `code` | Статус |
|---|---|
| `ambiguous_set_name` | **ЗАРЕЗЕРВИРОВАН, не отдаётся.** Задумывался для случая «в `GET /api/sets` два сета с запрошенным именем». Сет адресуется по `id` (`POST /api/b4/set` принимает `{"id": …}`), имя ключом не является — угадывать нечего. [ADR-0008](../adr/0008-b4-exclusive-sets.md) описывает обратное; побеждает код |

### 501 — не реализовано в этой поставке

| `code` | Где | Тело |
|---|---|---|
| `not_implemented` | **только** `POST /api/upstream` | обязано называть причину и блокеры |

```json
{
  "code": "not_implemented",
  "error": "Переключение внешней сети появится во второй фазе: сначала надо выяснить, можно ли применить изменение только к станционному радио, не уронив домашнюю сеть — оба радио делят одну phy0 (RQ-03)."
}
```

`POST /api/nikki/test` под это правило **не подпадает**, хотя и не реализован:
его маршрут не зарегистрирован вовсе, поэтому запрос получает `405` от
`http.ServeMux`, а не `501` с объяснением. Блокер — RQ-06.

Именно `501`, а не `503`: «не в этой версии», а не «попробуйте позже».
Повторять запрос бессмысленно ([ADR-0016](../adr/0016-upstream-deferred.md)).

### 503 — внешняя зависимость недоступна

Демон жив, но нужный ему компонент — нет. Повтор запроса имеет смысл.

| `code` | Когда | `details` (не реализовано) |
|---|---|---|
| `b4_unavailable` | b4 (порт 7000) не ответил, ответил не `200`, либо клиент не настроен | `{"probe": "GET /api/version", "err": "connection refused"}` |
| `nikki_unavailable` | Clash API не ответил либо клиент не настроен. **RQ-01 закрыт** — это условное состояние, а не постоянное | `{"probe": "GET /proxies"}` |
| `group_missing` | Clash API ответил, но группы `PROXY` в профиле нет. Чинится правкой профиля, а не ожиданием | `{"group": "PROXY"}` |
| `ubus_unavailable` | `ubus call network.wireless status` не ответил на пути скана | `{"object": "network.wireless"}` |
| `uci_unavailable` | `uci changes` или `uci show wireless` не отработали на пути записи | `{"pkg": "wireless"}` |
| `scan_failed` | `ubus call iwinfo scan` вернул ошибку | `{"ifname": "phy0.0-sta0"}` |
| `radio_unknown` | не выяснено, какое радио работает станцией: интерфейса с `mode=sta` нет ни в `network.wireless status`, ни в `/etc/config/wireless` ([ADR-0019](../adr/0019-radio-role-derived.md)) | `{}` — угадывать нечем |
| `ifname_unknown` | станционное радио выяснено, но имя его интерфейса не выводится из `network.wireless status`: радио выключено, объект не ответил | `{"radio": "radio1"}` |
| `unavailable` | планировщик подписки не настроен. В штатной сборке недостижимо: `NewServer` заводит его всегда | `{}` |

| `code` | Статус |
|---|---|
| `b4_auth_required` | **ЗАРЕЗЕРВИРОВАН, не отдаётся.** На этом роутере `auth_check` вернул `auth_required: false`, и клиент этот маршрут не зовёт вовсе. Включённая аутентификация деградирует в `b4_unavailable`: пароль не угадываем ([ADR-0007](../adr/0007-b4-api-only.md) описывает отдельный код — побеждает код) |

### 502 — внешний сервис ответил, но не так

Отличается от `503` тем, что ждать бесполезно: сервис жив, непонятен его ответ.

| `code` | Когда |
|---|---|
| `b4_error` | b4 ответил неразобранным телом, отклонил запрос (`b4.ErrRejected`) либо вернул код вне контракта |
| `nikki_error` | то же для Clash API (`nikki.StatusError` с непредвиденным кодом) |

`radio_unknown` и `ifname_unknown` — два разных незнания, и сливать их нельзя:
первое означает «неизвестно, ЧТО трогать», второе — «известно что, но не
поднято». Первое запрещает и запись тоже (демон не знает, какие секции наши);
второе мешает только обращению к живому радио.

Ни то, ни другое не лечится догадкой. «Возьмём радио с меньшим индексом» — это
тот же хардкод, который [ADR-0019](../adr/0019-radio-role-derived.md) убрал:
индекс радио задаётся порядком регистрации драйверов, а не диапазоном.

`radio_unknown` возвращают `GET /api/wifi/scan`, `GET`/`POST /api/wifi/networks`
и `DELETE /api/wifi/networks/{id}`. `ifname_unknown` — `GET /api/wifi/scan` и
всё, что требует обращения к живому радио. `/api/status` при этом **отдаёт 200** — там недоступность
выражается полями (`associated_ssid: null`, `b4.available: false`), а не
кодом ответа ([ADR-0017](../adr/0017-polling-no-push.md)).

### 500 — наша ошибка

| `code` | Когда |
|---|---|
| `internal` | всё, что мы не предусмотрели: не завёлся джоб, не сгенерировалось имя секции, панель не встроена в бинарь |
| `parse_failed` | вывод `uci show` или `network.wireless status` не разобрался. Это наша ошибка, а не внешняя: команда ответила |
| `write_failed` | `uci set`, `uci add` или `uci delete` не отработали. Для опции `key` текст без значения (ADR-0012) |
| `commit_failed` | `uci commit wireless` не отработал. Отдельный код от `write_failed`: стейджинг остался, и это видно в LuCI |
| `read_failed` | журнал `/etc/nikki/updates.log` не прочитался |

Текст у всех — общий, без внутренних путей и без значений опций.

Не используется для «состояние системы такое» — для этого есть `409`.

## Правило выбора кода

| Вопрос | Ответ | Код |
|---|---|---|
| Запрос синтаксически неверен? | да | `400` |
| Не тот, кто пришёл? | да | `401` / `403` |
| Объекта нет? | да | `404` |
| Метод не поддержан на этом пути? | да | `405` |
| Мешает текущее состояние системы, исправляет человек? | да | `409` |
| Не реализовано и в этой версии не появится? | да | `501` |
| Внешний компонент молчит, повтор осмыслен? | да | `503` |
| Внешний компонент ответил, но непонятно чем? | да | `502` |
| Всё прочее | | `500` |

## Как ведёт себя `/api/status`

`/api/status` **никогда не отвечает `409`, `501` и `503`**. Он всегда `200`
(или `401`), а любая недоступность выражена полями:

| Ситуация | В теле `/api/status` |
|---|---|
| b4 лежит | `"b4": {"available": false, "version": null, "set": "", "enabled_count": 0}` |
| Nikki недоступна | `"nikki": {"available": false, "version": null, "set": "", "enabled_count": 0}` |
| ассоциации нет | `"associated_ssid": null` |
| конфликт выбора | `"selection_state": "ambiguous"`, `"configured_ssid": null`, `"conflict": ["wifinet0","wifinet2"]` |
| радио не выяснено | поля гаснут (`ap.band: ""`, `associated_ssid: null`), но ответ остаётся `200`: `503 radio_unknown` — удел путей, которые собираются что-то **трогать** ([ADR-0019](../adr/0019-radio-role-derived.md)) |
| джоб упал | `job.state: "failed"`, `job.error` — текст (виден **5 с** после завершения, `job.keepFinished`) |

Причина: статус опрашивается 1 Гц и служит источником картины целиком. Если
он начнёт падать из-за лежащего b4, панель ослепнет вся.

## Проверяется тестами

Механического сторожа у формы тела **нет**: ни один тест не сверяет ответ с
образцом, `scripts/check-routes.sh` видит только пути. Проверяются машинные
коды на конкретных сценариях — этого достаточно, чтобы поймать подмену кода, и
недостаточно, чтобы поймать переименование поля.

| Сценарий | Ожидание |
|---|---|
| `409 job_busy` | второй `POST /api/mode` во время первого |
| `409 ambiguous_selection` | фикстура с двумя включёнными секциями |
| `409 fingerprint_mismatch` | подмена фикстуры между `GET` и `POST` |
| `409 enabled_network_readonly` | `POST` по `id` включённой секции |
| `409 foreign_staged_changes` | непустой `uci changes` |
| `501` на `POST /api/upstream` | тело содержит `blocked_by` |
| `503 b4_unavailable` | клиент b4 с отказом соединения |
| `503 radio_unknown` | фикстура без `mode=sta` и в ubus, и в UCI |
| Радио переставлены местами | код идёт за `mode=sta`, а не за индексом |
| `/api/status` при лежащем b4 | **200**, `b4.available: false` |
| Ни в одном ответе нет `key` | грепом по всем телам в тестах |
