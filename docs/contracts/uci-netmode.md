# Контракт: `/etc/config/netmode`

Собственный конфиг демона. Содержит **одну** секцию и четыре опции.

Это единственное состояние, которым демон действительно владеет. Всё
остальное — сохранённые сети, выбор upstream, сеты b4, узлы Nikki — живёт в
чужих источниках и читается заново ([ADR-0002](../adr/0002-source-of-truth.md)).

## Файл целиком

```
config main 'main'
	option mode 'off'
	option listen '192.168.9.1'
	option port '8088'
	option token_file '/etc/netmoded/token'
```

Права: **0600**, владелец `root:root`. Отступ — табуляция (формат UCI).

Значения выше — сид под этот роутер: `listen` равен `network.lan.ipaddr`
без маски (`192.168.9.1/24`, `raw/11-uci-show-network.txt`).

> **Секция обязана быть именованной** — `'main'` вторым токеном, в
> кавычках. `config main` без имени создаёт **анонимную** секцию
> (`@main[0]`), а весь код обращается к ней как `netmode.main.*`.
>
> Пойман на живом роутере: сид первой поставки был написан без имени.
> `uci get netmode.main.mode` падал с `Entry not found`, `uci set
> netmode.main.mode=...` — с `Invalid argument`. Чтение в Go тихо
> проглатывало ошибку и подставляло дефолт, который случайно совпал с
> значениями сида, поэтому баг не проявлялся на `/api/status` — но
> `POST /api/mode` немедленно проваливал джоб при попытке записи.
>
> Фикстуры `Executor` в Go-тестах хранят значения в обычной map по
> строке `"netmode.main.mode"` и не различают именованные и анонимные
> секции UCI, поэтому 193 теста проходили, пока дефект был жив.
> Проверяется `scripts/check-netmode-seed.sh` — он читает сид как текст,
> а не через фейк, специально ради этого класса ошибок.

## Опции

| Опция | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `mode` | `nikki` \| `b4` \| `off` | `off` | целевой режим обработки трафика |
| `listen` | IPv4-адрес | `network.lan.ipaddr` без маски | адрес, на котором слушает HTTP-сервер |
| `port` | 1–65535 | `8088` | порт HTTP-сервера |
| `token_file` | абсолютный путь | `/etc/netmoded/token` | путь к файлу с токеном API |

### `mode`

**Единственное подлинно собственное состояние демона.** Из живой системы его
вывести нельзя: «nikki запущен» — это следствие режима, а не режим. После
падения nikki по своей причине мы обязаны знать, что владелец хотел `nikki`,
а не решить, что он хотел `off`.

- Записывается только обработчиком `POST /api/mode`, до вызова
  `netmode-apply`. Порядок именно такой: UCI — источник намерения, скрипт
  приводит систему к намерению. Если скрипт упал, намерение сохранено, джоб
  в состоянии `failed`, и повтор возможен.
- Значение вне набора не исправляется: `/api/status` отдаёт `mode: "unknown"`,
  файл остаётся как есть ([ADR-0010](../adr/0010-never-auto-repair.md)).
- Тот же файл читает `netmode-apply` при загрузке системы — так режим
  переживает перезагрузку без участия демона.

### `listen`

Демон слушает **только** этот адрес. `0.0.0.0` запрещён: проверяется при
старте, при попытке — отказ запуска с сообщением
([ADR-0014](../adr/0014-lan-bind-and-token.md)).

Если опции нет — адрес выводится из `uci get network.lan.ipaddr` (отбрасывая
`/24`). Если и это не удалось — **демон не стартует**. Отката на «слушать
везде» нет ни при каких условиях.

### `port`

**8080 занят.** Разведка (`raw/25-netstat.txt`) показала на нём `mihomo`;
за ним же 9090 (Clash API), 7890–7892, 1080, 1053, 40253. Плюс 80 и 443
у `uhttpd`, 22 у `dropbear`, 53 у `dnsmasq`.

Демон получает **8088** — свободен в снимке и вне диапазонов соседей.

Проверять `netstat -lntp` перед первым запуском всё равно стоит: снимок
мог устареть. При занятом порте демон обязан упасть с внятным сообщением,
а не выбирать другой самостоятельно — молчаливая смена порта означает,
что панель окажется не там, где её ищут.

### `token_file`

Хранится **путь**, а не сам токен.

- Файл: 32 случайных байта (`crypto/rand`) в base64url, права `0600`,
  каталог `/etc/netmoded` — `0700`.
- Создаётся при первом старте, если отсутствует. Существующий не
  перезаписывается никогда.
- Ротация: `rm /etc/netmoded/token && /etc/init.d/netmoded restart`.

Почему не в UCI: `/etc/config/wireless` имеет права `644`
(`raw/40-etc-config-perms.txt`) — в этом каталоге мировидимость зависит от
пакета, а не от политики. Плюс UCI-файлы попадают в бэкап sysupgrade и в
редактор конфигурации LuCI, а ротация секрета не должна быть правкой
конфигурации.

## Чего в файле нет

| Отсутствует | Почему |
|---|---|
| `config network 'home'` и любые секции сохранённых сетей | сети — обычные `wifi-iface` в `/etc/config/wireless` ([ADR-0003](../adr/0003-saved-networks-in-wireless.md)) |
| `option upstream` | выбор выводится из `disabled`, не хранится ([ADR-0004](../adr/0004-selection-derived.md)) |
| `option token` | секрет — в сайдкаре 0600 ([ADR-0014](../adr/0014-lan-bind-and-token.md)) |
| адрес и порт b4 | `127.0.0.1:7000` — факт разведки, зафиксирован в `evidence.json`; конфигурируемость дала бы способ увести вызовы на чужой хост |
| адрес Clash API | **не наш**: читается из `nikki.mixin.api_listen`, секрет — из `nikki.mixin.api_secret`, при старте демона. Дублировать его у себя значило бы завести второй источник правды ([ADR-0002](../adr/0002-source-of-truth.md)) и разъехаться с mihomo при первой же ротации секрета. RQ-01 закрыт |
| расписание обновления подписки | пока константа в коде. Появится опцией, когда понадобится менять её без пересборки (SPEC §9) |
| `option poll_interval`, таймауты, размер кэша | не настраивается: значения выведены из SPEC §7 (1 Гц, кэш 500 мс) и менять их без изменения контракта нельзя |

Файл сознательно держится минимальным: каждая опция — это ветка поведения,
которую надо покрыть тестом и объяснить в UI.

## Поведение при отсутствии файла

| Опция | Если файла или опции нет |
|---|---|
| `mode` | `off`; файл **не создаётся** — записывается при первом `POST /api/mode` |
| `listen` | из `network.lan.ipaddr`; если недоступно — отказ запуска |
| `port` | `8088` |
| `token_file` | `/etc/netmoded/token` |

Отсутствие файла — валидное состояние свежей установки, а не ошибка. Оно
согласовано с `Selection == Empty`
([`state-machine.md`](state-machine.md)): свежий роутер выглядит пустым во
всех измерениях сразу.

## Чтение и запись

| Операция | Как |
|---|---|
| Чтение `mode` | `UCIGet("netmode", "main", "mode")`; `ErrNotFound` → `off` |
| Чтение `listen`/`port`/`token_file` | то же, один раз при старте |
| Запись `mode` | `UCISet` + `UCICommit("netmode")` в обработчике `POST /api/mode` |
| Чтение файла | UCI, а не `os.ReadFile` — формат разбирает `uci`, не мы |

Запись в `netmode` не требует ни отпечатка, ни проверки чужого стейджинга:
файл наш, других писателей у него нет. Это единственный пакет UCI, где мы
коммитим без проверки `uci changes`.

## Пример: тот же файл после `POST /api/mode {"mode":"b4"}`

```
config main 'main'
	option mode 'b4'
	option listen '192.168.9.1'
	option port '8088'
	option token_file '/etc/netmoded/token'
```

Изменилась одна опция. Порядок и форматирование сохраняет `uci`, а не мы.
